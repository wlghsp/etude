# 빈틈 보강 작업의 결정과 시행착오 (2026-11-19~20)

세션이 바뀌어도 이어갈 수 있도록 코드와 점검 기록에 드러나지 않는 **결정의 이유**와 **반복된 함정**을 모은다. 문제 내용은 `scripts/content-gen/new_sets/setNNN.py`, 점검 지적은 `reviews/` 가 기준이다.

## 1. 결정과 이유

## 2. 반복된 시행착오 (생성기·검증)

- **하네스는 `sh -c`(dash)로 실행한다.** `**`, `<<<`, `[[ ]]` 같은 bash 문법이 깨진다 (예: 2의 거듭제곱은 `<<`).
- **`pkill -f 패턴` 은 setup 쉘 자신이 매칭된다**(종료 코드 143). `pkill -x 이름` 을 쓴다. 맨몸 `wait` 은 백그라운드 서버까지 기다려 멈춘다.
- **heredoc 안에 같은 종결어를 넣으면 바깥이 끊긴다.** 파일은 Write 도구나 파이썬 삼중따옴표로 만든다.
- **mawk 의 `%d` 는 int32 로 잘린다**(IP 정수 변환). `%.0f` 를 쓴다.
- **문제마다 setup 이 새로 실행된다.** 앞 문제의 결과를 전제하는 문제(예: 579:4 복구 후 파일 꺼내기)는 그 문제 setup 에 앞 단계를 넣어야 한다.
- **`grep` 이 명령 줄(`$ ...`)까지 잡는다.** 샘플 로그에 프롬프트 줄이 있으면 정답 추출이 오염된다 (583:5).
- **`e2fsck -fy` 는 `-b` 없이도 백업 슈퍼블록을 자동으로 시도한다.** 체크가 `-b` 를 강제하면 유효한 풀이를 막는다.
- **ext4 축소는 점검 없이도 진행된다**(새로 만든 이미지). "도구가 점검을 요구한다"고 쓰면 사실과 다르다 (578:6).
- **`mke2fs` 를 `-n` 없이 실행하면 이미지가 지워진다.** 문제 설명에 경고를 넣는다.

## 3. 반복된 점검 지적 유형

세부 목록과 기준은 `reviews/README.md` 의 "반복해서 나온 지적 유형"에 있다. 이번 묶음(557~586)에서 특히 많았던 것만 적는다.

- 객관식 정답 길이비 1.5 초과, 순서 문제의 정답이 하나로 고정되지 않음(설명·힌트가 순서를 나열하거나 반대로 모호함), 힌트가 정답·명령을 그대로 알려 줌.
- 명령 적기 문제의 정규식이 유효한 변형(`sudo`, `ip r`, `-c` 연결 옵션, 옵션 순서)을 막음.
- 샘플 출력이 실제 도구 형식·내부 수치와 어긋남(lvs 합계와 pvs 할당량, mdadm `faulty` 와 `removed` 동시 표기, qemu 쓰기 잠금과 모순되는 ps 샘플).

## awk 숫자 체크는 빈 파일을 통과시킨다 (2026-11-20, 615~617)

`awk '{exit !($1+0==N)}' 파일` 은 파일에 레코드가 없으면 규칙이 실행되지 않아 종료 코드 0 으로 끝나, 아무 값도 안 쓴 빈 파일이 정답 처리된다(무행동은 파일이 없어 실패하므로 verify 로는 안 걸린다). 숫자 비교는 `awk 'NR==1{v=$1+0} END{exit !(NR==1 && v==N)}'` 로 쓰거나 `tr -d` 로 공백을 지운 문자열 `=` 비교를 쓴다.

전수 점검(2026-11-20): `exit !(` 패턴을 쓰는 세트를 모두 확인했다. 빈 파일이 통과하던 것은 568(평균 12.35), 582(iowait 42.5), 610(steal 38) 세 곳이라 모두 `NR==1 && v==N` 형태로 고치고 재생성·재검증(18/18)했다. 나머지(522·537·123·350)는 `END` 에서 변수로 판정하거나 앞의 한 줄 확인 체크로 막혀 있어 안전하다.
