## 권고

### 546:3 — 설명에 정답이 그대로 적혀 있음 (힌트 누설)
설명에 규칙 첫머리 `*.info;mail.none;authpriv.none;cron.none` 와 "메일·인증·크론 로그는 각각 자기 파일로 따로 가기 때문입니다" 가 있어, 답(`mail`·`authpriv`·`cron`)을 읽기만 하면 나온다. 문제가 "찾기"가 아니라 "옮겨 적기"가 된다.
수정안: 규칙 본문과 마지막 문장을 빼고 "`/var/log/messages` 에 쓰는 규칙을 찾아, `종류.none` 으로 제외된 종류를 모으세요"로 바꾼다. `종류.none = 그 종류 제외` 설명은 유지한다. 해설에서 "메일·인증·크론은 각자 파일로 간다"를 풀어 준다.

### 546:5 — 예시가 정답의 첫 줄과 같음
"(예: 첫 줄 `weekly`, 둘째 줄 숫자만)" 인데 Rocky 9 `/etc/logrotate.conf` 의 실제 값은 `weekly` / `rotate 4` 다. 첫 줄 정답이 예시로 노출된다.
수정안: 예시를 `monthly` 로 바꾸거나 "첫 줄은 주기 단어, 둘째 줄은 숫자만"으로 쓴다.

### 546:10 — 해설의 "systemd 가 부팅돼 있지 않아" 는 사실과 다름
`linux-systemd` 는 systemd 가 PID 1 로 돌고 있다(547 은 `systemctl` 로 실습한다). 직접 확인: `systemctl is-enabled logrotate.timer` = enabled, `is-active` = inactive. 정확한 표현은 "systemd 는 돌지만 이 타이머는 활성 상태가 아니다"이다.
수정안: 해설 마지막 문장을 "이 샌드박스에서는 `logrotate.timer` 가 비활성이라 자동 회전은 일어나지 않지만 구성은 같습니다"로 바꾼다. 같은 문제의 힌트("이름에 `timer` 가 들어간 유닛")는 정답 보기를 그대로 지목하므로 "패키지 파일 목록에서 `/usr/lib/systemd/system/` 아래 유닛 파일을 찾아 보세요" 정도로 낮춘다.

### 546:11 — 힌트가 정답 설명을 그대로 함 / 해설이 안 본 것을 인용함
힌트 "회전한 뒤 프로그램이 로그 파일을 다시 열게 하거나, 파일을 옮기지 않고 내용만 복사해 비우는 방법"은 정답 보기의 풀이와 같다. 해설의 "(예: rsyslog 설정에서 본 `HUP`)" 도 학습자가 본 적이 없다. 이 세트의 rsyslog.conf 읽기 문제에는 HUP 가 없고, `/etc/logrotate.d/rsyslog` 의 postrotate 에만 있다.
수정안: 힌트는 "프로그램은 파일 이름이 아니라 이미 열어 둔 파일에 씁니다. 이름이 바뀐 뒤에도 같은 파일에 쓰는 이유를 생각해 보세요"까지만. 해설은 "예: `cat /etc/logrotate.d/rsyslog` 의 postrotate 줄"로 고친다.

### 546:12 — 설명 괄호가 순서 전체를 나열함
"설정을 만든 뒤, 실제 파일을 바꾸기 전에 먼저 안전하게 점검하고, 그다음 강제 회전으로 한 번 시험하며, 마지막에 결과를 확인" 이 정답 순서의 전체다. 기준 3·5 상 순서를 설명으로 고정하는 것은 필요하지만, 이대로면 카드 맞추기가 독해 문제가 된다.
수정안: "설정 파일이 있어야 시작할 수 있고, 파일을 바꾸는 단계는 안전 점검 뒤에 둡니다. 마지막 단계는 결과 확인입니다"처럼 제약만 적는다.

### 546:4 — check 가 주석으로 통과됨
`grep -q "local5\.\*"`, `grep -q "/var/log/myapp.log"` 는 `# local5.* ...` 같은 주석 줄이나 틀린 규칙(예: `local5.* action(type="omfile" file="/var/log/other.log")` 와 별도 주석 줄)로도 통과한다. 직접 확인: 주석 한 줄만 있는 파일에서 `rsyslogd -N1` 은 rc=0 이다. 문법이 틀린 파일은 rc=1 로 잘 잡힌다. 무행동(파일 없음)은 실패하므로 "무행동 실패" 기준은 만족한다.
수정안: `grep -qE '^[[:space:]]*local5\.\*[[:space:]]+action\(.*file="/var/log/myapp\.log"' /etc/rsyslog.d/myapp.conf` 로 한 줄에서 종류·출력 파일을 함께 확인한다. 레거시 형식(`local5.*  /var/log/myapp.log`)도 허용하려면 `^[[:space:]]*local5\.\*[[:space:]].*/var/log/myapp\.log`.

### 547:3 — 힌트가 정답을 그대로 알려 줌
"`yesterday` 는 어제 0시, `today` 는 오늘 0시… 시작과 끝을 둘 다 정해야 한다"는 정답 보기(`--since yesterday --until today`)를 그대로 설명한다. 나머지 보기는 각각 한쪽만 있거나 `-b -1` 이라 힌트만으로 소거된다.
수정안: 힌트를 "하루치는 시작 시각과 끝 시각이 모두 있어야 합니다. `--since`·`--until` 에 줄 수 있는 `yesterday`·`today` 가 각각 몇 시를 뜻하는지 `man journalctl` 의 TIME 구문에서 찾아 보세요"로 바꾼다.

## 참고

- 547:1 힌트 "범위는 덜 심각한 쪽 이름부터 적습니다" 는 사실과 다르다. 직접 확인: `-p warning..err` 와 `-p err..warning` 둘 다 같은 결과(err·warning 만)다. 정답에는 영향이 없다. 정확히는 "순서는 어느 쪽이든 되지만 두 수준을 포함한 사이만 남습니다"로 고치면 된다.
- 547:2 시각 이전·이후 줄 사이가 2~3초라 `date` 기록·`--since` 초 단위 해석에서 안전하다(직접 확인: new-event 만 나옴). 문제 없음. 다만 설명에 "신고 시각은 서버 현재 시간대 기준"을 한 줄 넣으면 좋다(해설 코멘트에만 있음).
- 547:5 힌트 "하위 명령 이름에는 reset 이 들어갑니다" 는 사실상 명령 이름을 알려 준다. 새 개념(`reset-failed`)이라 방향 제시로 수용 가능. 힌트에서 "failed 상태를 초기화"까지만 두는 안도 있다.
- 547:11 "cron 의 `at` 처럼" 은 부정확하다. `at` 은 cron 이 아니라 별도 명령(atd)이다. "`at` 명령처럼"으로 고친다.
- 547:12 힌트 "reverse(뒤집기)의 첫 글자를 딴 짧은 옵션" 은 답(`-r`)을 지목한다. 보기에 `-f`·`-n 20`·`-k` 가 함께 있으니 "보기 옵션 중 순서를 뒤집는 것"으로 낮출 수 있다.
- 545 선택형 distractor 가 약하다(2·3·7·9번의 오답 3개 중 2개 이상이 "일부러 틀린 문장"). 예: 7번 "hostnamectl 로 다시 저장한다", "서버를 재설치해야 한다". 정답 위치는 빌더가 분산해 주므로 문제는 없으나, 7번은 "`nmcli device reapply eth0` 만 하면 된다" 같은 그럴듯한 부분 정답/오답을 섞으면 변별력이 올라간다(단, 복수 정답이 되지 않게 `up` 이 이 문제의 정답이 되도록 설명 필요).
- 546:7 check 3("옛 로그가 아직 없고 50줄 그대로")은 학습자가 `logrotate -f` 를 눌러 보면 실패한다. 문제 설명에 "점검만 하고 실제 회전은 하지 마세요"가 없다. 설명에 한 줄 추가를 권장한다. 또 `missingok`·`notifempty` 는 check 로 확인하지 않는다(설명의 필수 옵션이므로 `grep -qw` 로 추가 가능).

## 문제 없음 (확인한 것)

### 545
- 1 hostnamectl 샘플: 라벨 오른쪽 정렬(19칸)·Static/Transient 구분이 실제 `hostnamectl` 출력 형식과 같다. `awk '/Static hostname/ {print $NF}'` 는 한 줄에만 걸린다.
- 2 `hostnamectl set-hostname` = `/etc/hostname` 영구, `hostname`·`/proc/sys/kernel/hostname`·`export HOSTNAME` 은 비영구. 정답 하나.
- 3 `ip addr add` 임시 설명 정확. 정답 하나.
- 4 nmcli 샘플(`NAME UUID TYPE DEVICE`, 비활성 `--`, lo `loopback`) 형식이 실제와 같다. `awk '$4=="eth0"'` 정답 하나(연결 이름에 공백이 있는 `System eth0` 같은 경우는 샘플에 없어 안전).
- 5 `.nmconnection` 샘플: `[ipv4]` 의 `address1=주소/접두사,게이트웨이`, `dns=...;`, `method=manual` 순서와 형식이 실제 NetworkManager(Rocky 9) 파일과 같다(`[ipv6] addr-gen-mode=eui64` 포함). 정답 2개 check 모두 무행동 시 실패.
- 6 `nmcli connection modify` 정답 하나. `up`·`show`·`delete` 는 오답.
- 7 `modify` 는 프로필만 저장, `up`(또는 `device reapply`)으로 적용 — 사실 정확. 원격 세션 끊김 경고도 타당.
- 8 `ip route` 샘플(`default via .. dev eth0 proto dhcp src .. metric 100`)이 실제 출력과 같다. `$3` 은 `via` 다음 칸. 프로필(.1) vs 실제(.254, dhcp)로 "적용 안 됨" 서사가 7번과 맞물린다.
- 9 "IP 는 되고 이름은 안 됨 → DNS" 정답 하나. `ping` 오류 문구 `Name or service not known` 정확.
- 10 order 정답 `[3,1,4,0,2]` = modify → up → ip -br a → ip route → getent hosts. 카드 순서와 정답이 다르고, 설명으로 순서가 고정된다. `getent hosts` 는 9번 해설에서 처음 나오므로 문맥 밖 지식 수준은 경미(허용).
- 현장 정보: `example.com`, `192.0.2.x`, `198.51.100.x`, `203.0.113.x` 만 사용. 문제 없음.
- 실습 4개(1·4·5·8)는 모두 출력 파일 읽기형이고 결과 파일이 없으면 실패한다(무행동 실패 충족).

### 546
- 1 직접 확인: 이미지의 `/etc/rsyslog.conf` 는 `action(type="omfile" file="/var/log/…")` 형식이고, 켜진 `/var/log` 파일이 정확히 6개(messages·secure·maillog·cron·spooler·boot.log)다. `include(file="/etc/rsyslog.d/*.conf"…)` 는 `file="/var/log` 패턴에 걸리지 않는다. check 의 `sort` 기반 비교와 일치.
- 2 `/var/log/secure`(authpriv) 정답 하나. dnf.log·maillog·messages 는 오답.
- 3 정답 `authpriv cron mail`(직접 확인: 줄은 `*.info;mail.none;authpriv.none;cron.none`). awk `$1` 로 첫 칸만 뽑는 풀이가 형식과 일치. (누설은 권고 참조)
- 5 logrotate.conf 직접 확인: `weekly` / `rotate 4`(+`create`, `dateext`, `include /etc/logrotate.d`). check 는 파일에서 다시 계산한 값과 비교해 이미지 변경에 안전.
- 6 `-d` 정답 하나. `-d` 는 변경 없음, `-f` 는 강제 회전, `-v` 는 상세 출력(주기가 되면 실제 회전), `-s` 는 상태 파일.
- 7 직접 확인: `logrotate -d` 출력이 `rotating pattern: /var/log/myapp/app.log  after 1 days (7 rotations)` 형식으로 나온다. check 1~3 의 의도(설정이 읽힘·압축·점검만 함)가 맞고 무행동(설정 없음)이면 실패.
- 8 직접 확인: 설정 파일만 지정해 `-f` 하면 `dateext` 가 적용되지 않아 `app.log.1.gz` 가 생기고, 새 빈 `app.log`(create)가 만들어진다. 설명에 "`/etc/logrotate.d/myapp` 설정으로"가 명시돼 정답 하나. `notifempty` 덕에 `-f` 를 두 번 눌러도 결과가 유지된다(직접 확인).
- 9 직접 확인: `rotate 3` → `2` 로 바꾸고 `-f` 하면 `app.log.3.gz` 가 삭제되고 `app.log.1.gz`(MARK-line 50줄)·`app.log.2.gz`(old1)만 남는다. `rm` 으로 지우는 풀이는 check 3 에서 걸러진다. 무행동이면 설정이 3 이라 check 1 이 실패.
- 12 order 정답 `[2,3,0,1]` = 설정 만들기 → `-d` → `-f` → `ls -l`. 보기 순서와 정답이 다르다. (설명 누설은 권고 참조)
- 설정(setup): dnf 로 logrotate·rsyslog 를 설치하고(약 8초), rsyslogd 는 띄우지 않고 `-N1` 검증만 쓴다 — 직접 확인: `rsyslogd -N1` 은 문법 오류 시 rc=1, 정상 시 rc=0.
- 현장 정보 없음(`myapp`, `/var/log/myapp` 등 일반 이름).
