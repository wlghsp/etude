# 점검 기록 — 세트 615~617 (iperf3, VXLAN·WireGuard, 연결 장애 상황집)

- 점검자: 독립 서브에이전트(읽기 전용). 판정: CHANGES_REQUIRED (차단 1묶음, 권고 8, 참고 5). 변형 풀이 약 100건 시험.

## 반영 결과

- 차단: `awk '{exit !($1+0==N)}' 파일` 체크는 빈 파일(레코드 없음)이 종료 코드 0 으로 통과했다. `NR==1{v=$1+0} END{exit !(NR==1 && v==N)}` 로 바꿔 빈 파일·여러 줄 파일을 거부(615:1·2, 617:5). 이후 숫자 비교 체크는 이 형태를 쓴다(lessons 에 추가).
- 616:1 설명 오류 수정: 50바이트는 내부 이더넷 14 + VXLAN 8 + UDP 8 + 외부 IP 20 이다(외부 이더넷은 언더레이 MTU 에 포함되지 않음).
- 616:5 NAT 시나리오 정정: NAT 뒤 호스트가 공인 피어(Endpoint)를 향해 keepalive 를 넣는 것이 표준.
- 615:8 회선 속도 명시(100Mbit/s 링크에 1000Mbit/s), 617:4 샘플을 기본 임시 포트 수(약 28000) 이하로 정정(timewait 27940, TCP 합계 28610 과 표의 TCP 650 관계 유지), 617:10 순서 설명에 IP 와 이름 풀이의 선후 전제를 명시.
- 힌트 일반화(617:2·4·5·9, 615:1·2·6·9), 주석 처리된 줄이 통과하던 것(615:3·4·5, 616:3) 앵커로 차단, 616:6 키 생성 체크를 파이프 순서 검사로 바꾸고 `| sudo tee` 관용구 허용.
- 재검증: 실습 16개 통과, `check-content.sh` 통과, 빈 파일 체크 거부 확인, 정답 길이 비율 ≤ 1.5.
- 미검증·추정: `arping` 출력의 MAC 대소문자(실제는 대문자일 수 있음), `-b` 를 바이트 단위로 준 풀이(615:4)는 거부된다.
