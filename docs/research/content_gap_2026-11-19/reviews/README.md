## 단원 안 순서 (재배치, 2026-11-19)

새 세트(502~541)는 처음에 단원 맨 끝(display_order 723~762)에 붙었고, 화면 확인에서 개념 세트가 손연습보다 뒤에 놓이는 문제가 드러나 `scripts/content-gen/reorder_gap_sets.py` 로 재배치했다.

- 단원 안 순서는 스크립트의 `UNIT_ORDER`(옛 세트의 상대 순서는 그대로, 새 세트만 선행 관계에 맞게 끼움)가 정한다. 예: SQL 2 = 141 → 331 → **510 → 522** → 372 → **523** → 374, SQL 4 = … 371 → **525 → 526** → 369 …, MariaDB 운영 = 158 → 332 → **502 → 503 → 507 → 524** → 402 …
- 선행 개념이 다른 단원에 있던 상황집 4개는 단원을 옮겼다(`UNIT_MOVE`): 515·516·518 → 단원 58(systemd·df/du·패키지 세트 뒤), 517 → 단원 59(sudo·ACL·방화벽 뒤).
- 분야(category)별 `display_order` 를 단원 순서 → 단원 안 순서대로 다시 매겼다(분야의 최솟값은 그대로라 분야 순서는 불변). 세트 id 는 그대로라 완료 기록에는 영향이 없다.
- 반영: 마이그레이션 `2026-11-19_zz_gap_reorder.sql`(이름이 가장 뒤라 `unit_set_order` 뒤에 실행됨), 시드 `05_display_order.sql`·`06_units.sql`, 로컬 DB. 새 세트를 더 만들면 `UNIT_ORDER` 에 추가해 스크립트를 다시 실행하면 된다(같은 결과가 나온다).

## 점검 기준 (매번 이것부터)

1. **정답 정확성**: 사실(버전별 동작 포함)이 맞는가. MariaDB 10.6, Ubuntu 22.04(apt 2.4), Rocky 9(systemd 252), Docker 최신.
2. **복수 정답 없음**: 객관식·빈칸에서 정답이 정확히 하나인가.
3. **순서 문제**: 정답 순서가 하나로 고정되는가(설명으로 고정), 보기 순서가 정답과 다른가.
4. **무행동 실패**: 실습은 아무것도 하지 않으면 반드시 실패하는가.
5. **힌트 누설 금지**: 힌트는 방향만. 정답 값·명령·순서 전체를 말하지 않는다. 순서 문제 힌트는 순서를 나열하지 않는다.
6. **문맥 밖 지식**: 앞 문제·선행 세트에서 가르치지 않은 개념을 전제하지 않는다 (필요하면 해설에서 소개).
7. **설명(description)**: DB 이름·경로·두 번째 세션 명령이 명시돼 있고, 손으로 칠 때 시간 안에 끝낼 수 있는가(SLEEP 길이).
8. **현장 정보 금지**: IP·도메인·센터·내부 이름 없음 (`example.com`, `192.0.2.x`, 일반 이름만).

## 반복해서 나온 지적 유형 (생성 때 미리 피할 것)

- 힌트가 정답 값·순서를 그대로 알려 줌 (가장 많음). 힌트에는 "찾는 방법"만 적는다.
- 순서 문제에 같은 결과를 내는 다른 순서가 있음 → description 으로 순서를 하나로 고정.
- 이전에 가르치지 않은 명령·변수가 정답 보기로 등장.
- 두 번째 세션을 `SLEEP` 으로 겹치게 하는 문제에서 시간이 짧아 손으로 따라 칠 수 없음.
- k8s 학습자는 `edit`(자기 네임스페이스) 권한뿐이라 PV·RBAC 객체·`--as` 는 실습 불가 → 퀴즈·PVC 상태 실습으로 대체.
- Docker 세트는 Hub 429 로 검증이 가짜로 실패할 수 있음 → 아래 로컬 미러 사용.

## 알려진 한계·남은 사항

- 채점 한계(참고로만 기록): 502:3~5 는 SAVEPOINT 없이 같은 최종 값을 만들어도 통과, 503:5 는 한도를 올리는 해결도 통과.
- 515:8 check 강화, 520:7 check 는 선택 사항(미결).
- 512 는 학습자가 PV 를 만들 수 없어 reclaimPolicy 실습이 없다 (k8s-isolated 샌드박스 지원 필요).
- 511(RBAC)은 k8s 샌드박스 권한 제약으로 손연습을 퀴즈로 대체했다(2026-11-20 결정).
- 리눅스 스토리지·방화벽·SELinux 세트(534~541)는 비특권 샌드박스 한계로 `mount`·LVM·`firewalld`·SELinux 를 실제로 실행하지 못하고, 샘플 출력 파일을 읽는 실습과 읽기형 문제로 대체했다. 특권 샌드박스(또는 별도 환경)가 생기면 실제 실행 실습으로 교체할 후보다.
- 542(sudo)는 `Dockerfile.linux` 에 sudo 를 넣어 해결(이미지 재빌드·배포 필요, setup 의 apt 설치는 있으면 건너뜀). 546(logrotate·rsyslog)은 Rocky 이미지가 공식 이미지 그대로라 setup 이 dnf 로 설치하며 외부 접속이 없으면 실패한다(미결: 별도 Rocky 이미지 필요).
- 545·548·550 은 nmcli·iostat/sar·modprobe 가 샌드박스에 없어 샘플 출력 읽기 위주다. 544:11 의 추가 검사는 03 SQL 에만 있고 verify JSON 은 정답만 담는다.
- 새 세트는 화면(UI)에서 확인하지 않았다. 단원 안 순서는 끝에 붙였으므로 커리큘럼 재배치 때 조정이 필요할 수 있다.

## 다시 검증하려면

```bash
cd backend
npm run verify:quests -- --set 502,503,504,505,506,507,508,509,510,512,513,514,515,516,517,518
# 도커 세트는 Hub 한도(429)를 피하려고 로컬 미러를 쓴다
DOCKER_REGISTRY_MIRROR=http://host.docker.internal:5055 npm run verify:quests -- --set 519,520,521
bash ../scripts/check-content.sh
```

로컬 미러(`etude-mirror-local`, 포트 5055)가 없으면 `registry:2` 를 풀스루 모드로 띄운 뒤
`MIRROR_ADDR=127.0.0.1:5055 bash scripts/mirror-warm.sh` 로 이미지를 미리 받는다 (설계: `docs/specs/spec_registry_mirror.md`).
