# review_E — 세트 515~518 문제 텍스트 점검 (읽기 전용, 파일 미수정)

형식: `세트:번호 — 문제 / 수정안(필드와 새 값)`
정답·checks 는 전 문항 이상 없음(정답 정확, 복수 정답 없음). "아무것도 안 하면 통과" 검사 없음(전 실습: 초기 상태에서 grade 가 거짓 — 515 는 서비스 실패 상태, 516·517·518 은 산출 파일이 setup 의 `rm -f /tmp/*.txt` 로 지워져 있거나 조건이 거짓).
적용한 사실 점검: 515 systemd 252(Rocky 9), 516~518 Ubuntu 22.04(apt 2.4, netcat-openbsd, dpkg 1.21).

## 차단

- 515:5 — 설명 모순. description 의 "로그가 말하는 **없는 파일**" 은 사실과 다름(hint 가 맞게 말하듯 `Failed to load environment files: No such file or directory` 에는 파일 이름이 없음). 또 "상태에는 이번에는 `203/EXEC`…" 은 어색한 한국어.
  - description 새 값: "`envfail5` 서비스는 `EnvironmentFile=` 로 설정 파일을 읽도록 되어 있는데 시작되지 않습니다. 이번에는 상태에 `203/EXEC` 같은 종료 코드가 없고 `Result: resources` 가 보입니다.\n\n유닛이 읽으려는 **없는 파일**을 만들고, 그 안에 **`APP_PORT=9090`** 한 줄을 적어 서비스가 **active** 가 되게 하세요. (서비스는 `APP_PORT` 값을 `/tmp/port5.out` 에 기록합니다.)"

- 515:6 — hint 사실 오류. "포트 번호는 유닛의 `ExecStart=` 줄 끝에 있습니다" 는 틀림(줄 끝은 `--bind 127.0.0.1`, 포트는 중간).
  - hint 새 값: "`journalctl -xeu web6` 에서 `Address already in use` 를 확인하세요. 포트 번호는 유닛의 `ExecStart=` 줄 안에 있습니다. 고친 뒤 systemd 에 알리고 다시 시작합니다."

- 516:6 — PID 정답이 둘로 보일 수 있음. 서비스 셸이 `exec 3>>` 로 연 fd 3 을 자식 `sleep 1` 이 그대로 상속하므로 `find /proc/*/fd -lname '*(deleted)'` 에 서비스 셸 PID 와 잠깐 떠 있는 `sleep` PID 가 함께 나옴(grade 는 셸 PID 만 인정). 힌트로 구분 기준 제공.
  - hint 새 값: "`ls -l /proc/*/fd` 의 출력에서 `(deleted)` 가 붙은 줄을 걸러 보세요. 어느 PID 의 폴더 안인지 같이 나오게 하려면 `find /proc/*/fd` 에 링크 대상 이름으로 찾는 옵션을 써도 됩니다. 같은 파일을 연 프로세스가 둘 보이면, 잠깐 떴다 사라지는 `sleep` 이 아니라 계속 도는 쪽(그 부모)이 서비스입니다."

- 516:11 — `noauto` 도 "디스크가 없어도 부팅은 멈추지 않음" 을 만족해 복수 정답 소지(explanation 이 noauto 를 배제하는 근거는 "자동 마운트 안 함" 인데 description 이 그 조건을 말하지 않음). 조건을 description 에 명시. hint 는 "없어도 실패로 보지 않는다" 가 옵션 이름(nofail)을 거의 그대로 풀이해 주므로 완화.
  - description 새 값: "`/backup` 은 가끔 분리해 두는 외장 디스크입니다. 연결돼 있으면 부팅 때 평소처럼 자동으로 마운트되고, **연결돼 있지 않아도 부팅이 멈추지 않고 계속 진행**되도록 fstab 의 옵션 열에 넣을 값을 채우세요."
  - hint 새 값: "장치가 없거나 마운트에 실패했을 때 그것을 부팅 실패로 볼지 정하는 옵션입니다."

- 516:12 — 순서 고정 안 됨(점검 요청 항목). `df -h` ↔ `df -i` 는 앞뒤가 바뀌어도 타당하고, `du`(0)도 `df -i` 앞에 올 수 있음. 카드는 못 고치므로 description 으로 순서를 고정.
  - description 새 값: "`No space left on device` 장애를 처리하는 올바른 순서로 카드를 놓으세요. (원인을 가르는 단계가 먼저, 정리는 범인을 확인한 뒤입니다. 원인을 가를 때는 용량 확인을 inode 확인보다 먼저 하고, 큰 폴더를 따라 내려가는 단계는 둘을 모두 확인한 뒤에 합니다.)"

- 517:12 — 순서 고정 안 됨. 카드 0(`curl 127.0.0.1`)은 `ss -ltn`(카드 4) 앞에서 증상 재현용으로도 쓸 수 있어 [1,0,4,3,2] 도 타당. 진단/조치/확인 구분을 description 으로 고정.
  - description 새 값: "서비스에 접속하는데 `Connection refused` 가 납니다. 알맞은 점검·복구 순서로 카드를 놓으세요. (먼저 메시지를 해석하고 서버에서 포트를 듣는지 진단한 뒤, 고치고, 고친 결과는 서버 안에서 서버 바깥 쪽으로 차례로 확인합니다.)"

## 참고 (수정 불필요)

- 515:1~3, 515:7, 515:9, 515:10 — 문제 없음. 515 systemd 사실(203/EXEC·217/USER·`Result: resources`, EnvironmentFile 로그에 파일명 없음, `Failed to locate executable`, `status=1/FAILURE`) 이상 없음.
- 515:2·516:1·516:9·517:9·517:10·518:9·518:12 — 선택형에서 정답 보기가 가장 길다(길이 단서). choices 수정 불가라 그대로 두되, 유사 길이로 다듬을 수 있으면 좋음.
- 516:4 — `rm -rf 폴더; mkdir 폴더` 로도 grade 통과(폴더 유지 검사만 있음). 문제 문구상 허용 범위.
- 516 setup — 이전 문제의 백그라운드 `while` 프로세스(516:5·6·7)를 죽이지 않고 `rm -rf /tmp/lab` 만 해서, 같은 컨테이너를 재사용하면 이전 프로세스가 `(deleted)` 파일을 계속 쥠. 516:6 은 description 에 `/tmp/lab/old/app.log` 경로가 있어 구분되지만, 517 처럼 setup 에 `kill $(cat /tmp/lab/.pid) 2>/dev/null` 추가를 권장(setup_cmd 는 이번 점검 필드 밖).
- 517:5 — description/hint 가 구조(`&`, `curl -s`, `>`)를 거의 알려 주나 학습용 안내 수준으로 허용.
- 517:11 — 보기 `u`(UDP)도 문법상 유효한 명령이지만 description("포트가 열렸는지만", 데이터를 보내지 않음)으로 `z` 만 정답. 이상 없음.
- 518:1 — 보여 준 `E: Failed to fetch file:/tmp/rep/./Packages` 오류 문구는 [trusted=yes] 로 Release 없이 쓰는 flat 저장소 기준이라 샌드박스 재현과 일치한다고 보이나, 실제 출력 일치는 미검증(추정).
- 518:5 — description 에 오류 문구(`dpkg --configure -a`)가 그대로 있어 정답 명령이 노출되지만, "오류 문장을 읽는 훈련" 취지로 허용.
- 518:7 — `apt-get upgrade` 가 hold 패키지를 "kept back" 목록에 보여 주는지는 정적으로 미검증(추정; 보여 주지 않으면 설명 문구만 `0 upgraded ... 1 not upgraded.` 로 줄이면 됨).
- 518:8 — 보여 준 `Depends: libdep2-lab (>= 2.0) but it is not going to be installed` 는 실제로는 `but 1.0 is to be installed` 로 나올 수 있음(미검증). 학습에 지장 없음. hint 가 description 의 절차를 되풀이(안내형 문항이므로 허용).
- 518:10 — 518:9 의 정답 보기에 `signed-by` 가 이미 노출돼 10번 정답을 회상으로 풀 수 있음(세트 내 강화로 허용).
- 518:11 — 카드 "저장소 설정을 고치고 `apt-get update`…" 가 저장소 문제에 한정된 표현이나 explanation 이 "여기서는 저장소 설정" 으로 밝혀 순서는 하나로 고정됨.
- 현장 정보: 515~518 전체에서 실제 IP·도메인·내부 이름 없음(example.com·192.0.2.x 문서용 대역만 사용).
