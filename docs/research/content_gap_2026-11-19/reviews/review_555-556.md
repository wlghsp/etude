## 권고

### 555

1. **555:7 힌트가 정답 문장을 그대로 말한다.** 힌트 "2375 는 인증도 암호화도 없는 포트입니다" 가 정답 보기의 앞 절("인증·암호화가 없어서 …")과 같다.
   - 수정안: "서버의 도커 데몬 API 는 컨테이너를 만들고 지울 수 있는 관리자 창구입니다. 이 포트에 닿을 수 있는 사람이 도커에게 무엇을 시킬 수 있는지 생각해 보세요." (인증·암호화 여부는 해설에서 소개)
2. **555:6 설정이 길게 유지되지 않는다.** setup 의 `webapp` 이 `sleep 600`(10분) 이라, 학습자가 오래 걸리거나 `docker ps` 가 ssh 타임아웃으로 멈춘 시간까지 더하면 컨테이너가 끝나 check 1(`grep -qx webapp`)이 실패할 수 있다.
   - 수정안: `sleep 3600` 으로 늘린다.
3. **555:3 해설·힌트가 "원격에 도커 CLI 도 필요" 를 빠뜨렸다.** `ssh://` context 는 원격에서 `docker system dial-stdio` 를 실행하므로 원격 계정 PATH 에 `docker` 바이너리가 있어야 한다. 힌트는 "데몬만 있으면 되는지" 라고 물어 오해를 유도한다(정답 보기 자체는 틀리지 않음).
   - 수정안: 힌트를 "원격에서는 어떤 프로그램이 실행되어야 하는지, 별도 포트가 필요한지 생각해 보세요." 로, 해설에 "원격에도 docker CLI 가 설치되어 있어야 한다(내부적으로 `docker system dial-stdio` 실행)" 한 문장 추가.

### 556

1. **556:5 힌트가 정답 키워드를 지목한다.** "오류 메시지 속 단어 `swarm` 에 주목" 이고, 정답 보기만 Swarm 을 언급한다. 오류 문구를 읽을 수 있으면 개념 없이 맞힌다.
   - 수정안: 힌트를 "overlay 가 풀려는 문제가 서버 한 대 안의 연결인지, 서버 여러 대 사이의 연결인지 생각해 보세요." 로 바꾼다. 선택 사항으로, 오답 보기에도 "Swarm" 단어를 한두 개 넣어(예: "overlay 는 Swarm 서비스 이름 해석 때문에 …") 변별력을 높인다.
2. **556:6 설명과 힌트가 이중으로 정답을 말한다.** 설명 "Swarm 서비스가 아니라 평범한 `docker run` 컨테이너도 붙일 수 있는" 에 힌트 "'붙일 수 있는' 이라는 뜻의 영어 단어" 까지 붙으면 `--attachable` 이 거의 번역 문제가 된다.
   - 수정안: 힌트를 "`docker network create --help` 에서 overlay 와 관련된 옵션 설명을 읽어 보세요. 붙이기·내부 전용·ingress 중 이 목적에 맞는 것은 무엇인가요?" 같은 방향 제시로 바꾼다.
3. **556:9 힌트가 정답의 정의를 준다.** "부모 인터페이스의 MAC 을 같이 쓰는가" 는 ipvlan 의 정의 그 자체다. 다만 ipvlan 은 앞 문제에서 한 번도 소개되지 않아 힌트 없이는 풀 수 없다.
   - 수정안: 개념 소개를 앞 문제로 옮기거나(예: 556:8 해설 끝에 "ipvlan 은 macvlan 과 비슷하지만 MAC 을 공유한다" 한 줄), 힌트를 "MAC 주소를 컨테이너마다 새로 만드는 쪽과 그렇지 않은 쪽이 무엇인지 해설의 macvlan 설명을 떠올려 보세요" 정도로 낮춘다.

## 참고

### 555

- 555:9 힌트가 순서를 거의 풀어서 말한다("길이가 열려 있는지 → 만들어져 있는지 → 되돌리기는 사용이 끝난 뒤"). description 이 이미 첫 단계·마지막 단계를 고정하므로 큰 문제는 아니나, 힌트를 "각 단계가 앞 단계의 무엇을 필요로 하는지 생각해 보세요" 정도로 낮추면 좋다.
- 555:5 는 `DOCKER_CONTEXT` 환경변수를 다루지 않는다. 사용자 지정 우선순위는 `--context` > `DOCKER_HOST` > `DOCKER_CONTEXT` > `docker context use` 저장값인데, 해설은 앞의 두 단계만 말한다. 해설에 한 줄 추가하면 정확하다. 해설의 "(또는 `-H`)" 는 맞다(`-H` 와 `--context` 를 같이 주면 충돌 오류가 난다).
- 555:6 은 `--context default` 외에도 `-H unix:///var/run/docker.sock`, `DOCKER_HOST=... docker ps` 로 통과한다. 모두 올바른 해법이라 문제는 아니다. 채점은 파일 내용과 최종 선택만 보므로 `docker context use default; ...; docker context use broken` 로 우회해도 통과하는 한계가 있다(README 한계 항목에 준하는 수준).
- 555:1 은 "무엇이 정하나요" 에 context 만 답으로 하고, DOCKER_HOST 가 이를 덮어쓴다는 사실은 555:5 에서 처음 나온다. 모순은 아니다.

### 556

- 556:2·4 의 CLEAN 에는 `alpine` 이미지 확인·pull 이 없다(555 의 PRE 에는 있다). 이미지가 없으면 `docker run` 이 직접 받는다. Hub 429 시 가짜 실패 가능성은 README 의 미러 안내를 따른다.
- 556:2·4 는 파일에 출력만 있으면 통과하는 구조라 `echo` 로 흉내 내도 통과한다. 컨테이너 상태 check 가 함께 있어 허용 수준.
- 556:4 check 는 `docker0` 에 의존한다. 샌드박스 데몬이 `docker0` 를 만들지 않는 설정이면 정답도 실패한다. 실행 검증(`verify:quests`)에서 확인할 것(미검증).
- 서로 다른 보기 길이: 556 의 선택형 대부분에서 정답 보기가 가장 길다(556:3·5·10·12 등). 세트 전체에서 위치는 섞이지만(생성기 `pos` 분산) "긴 것이 정답" 이라는 단서가 남는다. 오답 보기를 비슷한 길이로 다듬으면 좋다.
- 556 은 9번부터 12번까지 선택형 네 개가 연속이다. 끝에 한 문제는 터미널·빈칸으로 바꾸면 리듬이 낫다(필수 아님).

## 문제 없음 (점검했고 이상 없음)

사실 정확성
- 555:1 context = 이름 + endpoint 저장, 기본 `default` 는 로컬 소켓. 맞음.
- 555:2 `docker context create --description --docker "host=ssh://..."`, `inspect -f '{{.Endpoints.docker.Host}}'`, 설명 문자열 grep 형식(`"Description": "staging server"`). 만들기만 하므로 연결 없음. 맞음.
- 555:3 `ssh://` 는 SSH 를 통해 원격 도커에 연결(별도 API 포트 불필요), 키 로그인·docker 그룹 필요. 맞음(위 권고 3 의 CLI 요건만 보완).
- 555:4 `context create/use/show`, `default` 로 복구. 맞음.
- 555:5 정답 "DOCKER_HOST 가 이긴다" 는 도커 CLI 의 해석 순서(`--context` > `-H`/`DOCKER_HOST` > `DOCKER_CONTEXT` > 현재 context)와 일치. 맞음.
- 555:7 2375 = 평문·무인증, TLS 는 보통 2376, 공개 2375 가 채굴 악성코드 표적. 맞음.
- 555:8 스킴은 `ssh://`. `tcp://` 는 유효한 스킴이지만 문제 의도(SSH)와 다르고 `http://`·`ssh@` 는 부적합. 복수 정답 아님.
- 556:1 기본 네트워크 `bridge`·`host`·`none`, `none` 의 DRIVER 는 `null`. 맞음.
- 556:3 host 모드: 별도 IP·NAT 없음, 호스트 포트 충돌 가능, `-p` 무시. 맞음.
- 556:5 오류 문구 `This node is not a swarm manager...` 실제 문구와 일치. overlay 는 Swarm 필요. 맞음.
- 556:6 `--attachable` 맞음. `--internal`·`--ingress` 설명도 맞음.
- 556:7 `swarm init` → `create -d overlay --attachable` → `ls` 로 SCOPE 확인 → `run --network`. 순서 하나로 고정됨(description 이 SCOPE 확인 위치를 지정, 네트워크가 있어야 확인·사용 가능).
- 556:8 macvlan 생성(`-d macvlan --subnet --gateway -o parent=eth0`). check 세 개가 드라이버·서브넷/게이트웨이·parent 를 모두 확인. 맞음.
- 556:9 macvlan = 컨테이너별 고유 MAC, ipvlan = 부모 MAC 공유. 맞음. 오답 보기들은 명백히 틀림.
- 556:10 사용자 정의 bridge 가 유일한 정답(기본 bridge 는 이름 해석 없음, host 는 `-p` 무의미·노출, none 은 통신 불가). 복수 정답 없음.
- 556:11 `hostNetwork: true` ≈ `--network host`. 맞음.
- 556:12 CNI ≈ overlay 와 같은 문제(노드 사이 Pod 통신). Flannel 은 VXLAN overlay, Calico 는 BGP·IPIP·VXLAN 선택이므로 "많다" 표현이 정확. `cni plugin not initialized` 의미도 맞음.

형식·안전성
- 무행동 실패: 555:2·4·6, 556:2·4·8 모두 아무것도 하지 않으면 실패한다(파일·context·컨테이너·네트워크 부재). 555 PRE·556 CLEAN 이 이전 상태를 지워 무행동 통과가 없다.
- 순서 문제 555:9, 556:7 은 보기 배열 순서가 정답과 다르고(`[1,2,0,3,4]`, `[3,0,1,2]`) 정답이 하나로 고정된다.
- 현장 정보: 모두 문서용 주소 `192.0.2.x`·일반 이름(`deploy`, `ops`, `staging server`, `prod`)뿐. IP·도메인·내부 이름 없음.
- 형식 다양성: 555 는 선택 4·터미널 3·빈칸 1·순서 1, 556 은 선택 7·터미널 3·빈칸 1·순서 1. 3종 이상 충족(556 은 선택 편중 약간, 참고 참조).
- 문맥 밖 지식: 555 는 Docker 기본 개념과 앞 문제로 충분. 556 의 Swarm·VXLAN·ipvlan 은 해설에서 소개되지만 ipvlan 은 위 권고 3 참조.
