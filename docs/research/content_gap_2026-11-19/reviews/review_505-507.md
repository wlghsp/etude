# 세트 505·506·507 점검 (읽기 전용, MariaDB 10.6 기준)

결론: 정답이 틀리거나 복수 정답인 문제는 없다. 순서 문제 1건이 고정되지 않고, 나머지는 힌트 누설과 문구 정확성 문제다. 지적하지 않은 문제는 모두 이상 없음이다.

## 차단

- 506:12 — 순서 문제의 순서가 고정되지 않는다. 카드 "같은 쿼리를 다시 ANALYZE 로 재서 전후를 비교한다"와 "결과가 이전과 같은지 확인한다"는 앞뒤가 바뀌어도 타당하다. 수정 가능한 필드는 description 뿐이고 choices·answer_spec 은 고칠 수 없다. 수정안(description): "느린 쿼리를 하나 개선하는 올바른 순서로 카드를 놓으세요. (개선 효과를 숫자로 비교하는 것까지 끝낸 뒤, 마지막에 결과가 달라지지 않았는지 검증합니다.)". 이 수정이 마음에 들지 않으면 drop.

## 권고

### 힌트·본문 누설

- 506:7 — 힌트가 정답 쿼리(`FROM orders o JOIN (SELECT customer_id, AVG(amount) av FROM orders GROUP BY customer_id) a ON ... WHERE o.amount > a.av`)를 거의 그대로 알려 준다. 수정안(hint): "고객별 평균을 `GROUP BY customer_id` 로 한 번만 구해 서브쿼리(파생 테이블)로 만들고, 그것을 `orders` 와 `customer_id` 로 JOIN 해서 각 주문 금액과 비교하세요. 파일 내용에 맞게 `COUNT(*)` 로 세고, `mariadb -N shop < 파일` 로 실행합니다."
- 506:8 — 힌트가 `WHERE id > 마지막id ORDER BY id LIMIT 20` 으로 정답 쿼리 전체를 알려 준다. 수정안(hint): "마지막으로 본 행의 id 를 기준으로 그 뒤부터 읽으면 건너뛸 행을 읽지 않습니다. `OFFSET` 은 쓰지 않습니다. 실행은 `mariadb -N shop < /tmp/next.sql > /tmp/page.txt` 입니다."
- 506:5 — description 의 "(같다(`=`) 조건 열을 앞에, 범위(`>=`) 조건 열을 뒤에 두는 순서를 떠올려 보세요.)"가 정답 열 순서를 알려 준다. 또 "앞 세트에서 배운 대로"라고 했지만 505 는 범위 조건의 열 순서를 가르치지 않았다(505:8 은 같음 조건과 정렬 컬럼). 수정안(description): 첫 문단 끝의 "열 순서는 앞 세트에서 배운 대로 고르세요."를 "열 순서는 직접 판단해 고르세요."로 바꾸고, 두 번째 문단(괄호 문장)은 삭제.
- 507:5 — 힌트가 정답 명령을 계정 이름까지 그대로 적었다(`REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'report'@'localhost';`). 수정안(hint): "넓게 준 권한은 `REVOKE` 로 먼저 모두 회수한 뒤, 필요한 범위·종류만 `GRANT` 로 다시 줍니다. 결과는 `SHOW GRANTS FOR ...` 로 확인하세요."
- 505:2 — 힌트가 정답 범위("3월 1일 이상, 4월 1일 미만")를 그대로 알려 준다. 수정안(hint): "컬럼은 그대로 두고 `>=` 와 `<` (또는 `BETWEEN`)로 날짜 범위를 만드세요. `created_at` 은 DATETIME 이라 3월 31일 하루 전체가 빠지지 않게 끝 경계를 주의하세요. 파일은 `cat > /tmp/q2.sql <<'SQL' ... SQL` 로 다시 써도 됩니다."
- 505:4 — 힌트의 "양쪽에서 1 을 빼 보세요"가 정답 변형을 그대로 알려 준다(description 에도 "값 쪽으로 옮깁니다"가 이미 있다). 수정안(hint): "컬럼이 등호의 한쪽에 혼자 남도록 계산을 반대쪽으로 옮기세요. 컬럼이 혼자 있는 쪽이 인덱스를 탑니다."

### 사실·설명 정확성

- 507:12 — explanation 이 REVOKE 를 DROP USER 의 필수 선행 단계처럼 쓴다. 507:6 의 해설("DROP USER 는 계정과 그 권한을 함께 지운다")과 어긋난다. 카드가 모두 쓰이는 순서 문제라 순서 자체는 하나로 고정된다. 수정안(explanation): "지울 계정이 맞는지 SHOW GRANTS 로 먼저 확인하고, 권한부터 REVOKE 로 회수해 접근을 단계적으로 끊은 뒤 DROP USER 로 삭제합니다(DROP USER 만으로도 권한은 함께 지워지지만, 이 문제는 단계별 정리 절차를 묻습니다). 마지막에 그 계정으로 접속해 거부되는지 확인하면 정리가 끝난 것입니다."
- 506:11 — explanation 의 "`<>` 는 정렬 방향과 무관하게 모든 행을 가져옵니다"는 부정확하다. `<>` 는 150020 하나만 빼고 앞쪽 행까지 포함한다. 수정안(explanation): "`>` 는 150020 보다 큰 것만 가져와 다음 행부터 시작합니다. `>=` 는 마지막으로 본 150020 이 다음 페이지에 또 나오고, `<` 는 이전 방향이며, `<>` 는 150020 하나만 빼고 앞쪽 행까지 모두 가져와 '다음 20건'이 되지 못합니다."
