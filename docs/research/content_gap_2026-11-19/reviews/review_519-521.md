# review_F: 세트 519·520·521 (Docker 상황집) 점검

범위: 36문제. 정적 점검(코드상 확인됨)이며 실제 실행으로 검증하지는 않았다.
아무것도 안 하면 통과하는(do-nothing) 검사는 실습 문제 모두 없었다. 첫 상태가 FAIL 이 되도록 setup 이 만들어져 있다.
Docker 사실 점검: bad address / Connection refused / Pool overlaps / Read-only file system / exec format error / no such file or directory(shebang) / manifest unknown / apt-get 127 / -p 문법 / 바인드 마운트와 볼륨 동작은 모두 맞다.

## 차단

520:6 — 볼륨 이름이 정답을 말해 준다
- 설명은 "이름이 크기를 말해 주지는 않으니" 라고 하지만 볼륨 이름이 `bigvol`/`midvol`/`smallvol` 이라 이름만 보고 `bigvol` 을 적으면 통과한다. 도커 출력을 볼 필요가 없고, 설명과도 모순된다.
- 수정안은 fix 가능 필드(title/description/hint/explanation/template)만으로는 안 되고 setup_cmd·grade_cmd·checks·solution 을 같이 바꿔야 한다. 이게 어려우면 drop.
  - setup_cmd: 기존 `for p in big:30 mid:8 small:1 ...` 를 `for p in a:8 b:30 c:1; do n=${p%%:*}; m=${p##*:}; docker run --rm -v vol-${n}:/d alpine sh -c "dd if=/dev/urandom of=/d/f bs=1M count=$m 2>/dev/null"; done; true` 로 바꾼다. 앞부분 정리 명령은 그대로 둔다.
  - description: "볼륨 세 개(`vol-a`, `vol-b`, `vol-c`)가 있습니다. 이름이 크기를 말해 주지 않으니, 도커가 보고하는 **항목별 사용량**을 보고 **가장 큰 볼륨의 이름**만 `/tmp/big.txt` 에 저장하세요."
  - grade_cmd 와 checks: `[ "$(cat /tmp/big.txt)" = vol-b ]`
  - solution: `docker system df -v | grep -E '^vol-'` 후 `echo vol-b > /tmp/big.txt`

520:9 — 보기 3 도 /app/index.txt 가 보일 수 있다 (복수 정답 가능)
- 보기 3 은 "옛 버전의 파일이 이미 들어 있는 볼륨" 이다. 옛 버전에도 `index.txt` 가 있었다면 `/app/index.txt` 는 보인다. 해설도 "옛 파일이 보입니다" 라고 해서 질문("보이는 경우")과 어긋난다.
- choices 는 못 고치므로 description 을 고친다.
- description 새 값: "이미지의 `/app` 안에 `index.txt` 가 들어 있습니다. 다음 중 컨테이너를 실행했을 때 **이미지가 담고 있는 `/app/index.txt` 가 그대로 보이는** 경우는 어느 것일까요? (옛 볼륨에는 이 파일이 들어 있지 않다고 봅니다.)"
- explanation 새 값: "처음 쓰는 빈 이름 있는 볼륨은 컨테이너가 시작될 때 이미지의 해당 경로 내용이 복사되어 채워집니다. 호스트 폴더(바인드 마운트)는 비어 있어도 이미지 내용을 가리고, 없는 경로는 도커가 빈 폴더를 만들어 붙이므로 마찬가지입니다. 이미 내용이 있는 볼륨은 이미지가 바뀌어도 다시 채워지지 않아 이미지의 파일이 나타나지 않고, 볼륨에 있던 옛 내용만 보입니다."

519:12 — 순서가 하나로 고정되지 않는다
- 카드 `docker ps`(실행 중인지)와 `docker inspect`(같은 네트워크인지)는 서로 바꿔도 타당하다.
- hint 새 값: "아래 층부터 한 겹씩 올라갑니다. 컨테이너가 떠 있는지 → 네트워크 배치 → 이름 해석 → 포트 접속 순으로, 앞 단계가 확인되어야 뒤 단계 결과를 믿을 수 있습니다."
- explanation 첫 문장 새 값: "컨테이너가 살아 있어야 네트워크 정보(`docker inspect`)가 의미가 있으므로 `docker ps` 를 먼저 보고, 같은 네트워크인지 확인합니다."
- 힌트가 순서를 알려 주는 것이 싫으면 drop.

521:12 — 앞 두 카드가 서로 바뀔 수 있다
- "실패한 단계를 찾는다"와 "오류 메시지를 읽고 원인을 짐작한다"는 어느 쪽을 먼저 해도 타당하다.
- hint 새 값: "먼저 **어디서**(어느 단계·줄) 실패했는지 찾고, 그다음 **왜**인지 메시지를 읽습니다. 고친 것이 맞는지는 맨 끝에서 봅니다."

## 권고

519:7 — title 이 원인을 누설한다
- title 이 "바깥으로 못 나간다: --internal 네트워크" 라서 원인이 그대로 나온다.
- title 새 값: "바깥으로 못 나간다: 기본 경로가 없다"
- hint 새 값: "`docker network inspect isolated` 의 출력에서 이 네트워크가 가진 **특별한 속성**을 찾아 보세요. 그 속성은 만든 뒤 바꿀 수 없습니다. 바깥으로 나갈 길을 어떻게 만들지 `docker network --help` 에서 생각해 보세요."

520:7 — title 과 hint 가 명령을 알려 준다
- title("system prune 의 범위")과 hint 가 `docker system prune` 을 직접 말한다. `container prune`+`image prune` 조합도 정답이다.
- title 새 값: "안전하게 정리하기: 무엇이 지워질까"
- hint 새 값: "도커에는 안 쓰는 것을 지우는 `prune` 계열 명령이 있습니다. 각각 무엇을 지우고 무엇을 남기는지 `--help` 로 확인하세요. 볼륨을 지우는 옵션은 따로 있고, 한 번 지우면 되돌릴 수 없습니다. 정리 전에 `docker ps -a`, `docker images`, `docker volume ls` 로 현재 상태를 기록해 두면 좋습니다."
- 검사 보강(선택): `-a` 로 과하게 지운 경우를 막으려고 grade_cmd 와 checks 에 `docker image inspect tool:1 >/dev/null 2>&1` ("쓰던 태그 이미지는 그대로다")를 추가한다.

520:8 — hint 가 풀이를 거의 그대로 알려 준다
- hint 새 값: "볼륨 안의 소유권은 호스트에서가 아니라 컨테이너를 통해서도 바꿀 수 있습니다. 권한을 바꿀 수 있는 사용자로 도는 일회용 컨테이너에 이 볼륨을 붙이는 방법을 생각해 보세요."

520:3 — `docker logs` 를 `> file` 로만 저장하면 실패한다
- 오류는 표준 오류(stderr)로 재생되어 `> /tmp/err.txt` 로는 빈 파일이 되고 검사가 실패한다. 문제에 이 주의가 없어서 학생이 막힌다.
- hint 새 값: "`docker logs` 는 컨테이너의 표준 출력과 표준 오류를 각각 그대로 다시 내보냅니다. 오류까지 파일에 담으려면 리다이렉션을 확인하세요. `--read-only` 를 빼는 것은 답이 아닙니다. 읽기 전용 루트 파일시스템에서 일부 경로만 쓰기 가능하게 하는 옵션을 `docker run --help` 에서 찾아보세요."

520:1 — 검사 우회 가능
- `docker exec app sh -c 'echo hello > /data/hello.txt'` 로도 통과한다(오타 난 경로 `/tmp/note` 를 그대로 두고).
- grade_cmd 와 checks 에 `[ "$(docker inspect -f '{{range .Mounts}}{{.Source}}{{end}}' app)" = /tmp/notes ]` ("`/tmp/notes` 를 붙였다")를 추가한다.

519:8 — 검사가 너무 엄격하다
- `grep -qx "DB_HOST=db"` 는 `DB_HOST=db:80` 같은 정당한 풀이를 막는다.
- grade_cmd·checks 의 첫 조건을 `! grep -q "localhost" /tmp/app.env` 로 바꾸고 `out.txt` 검사는 유지한다.

519:5 — 오류 메시지에 id 가 빠져 있다
- 실제 메시지는 `network appnet id <긴 해시> has active endpoints` 이다.
- description 의 해당 부분을 `Error response from daemon: error while removing network: network appnet id ... has active endpoints` 로 고친다.

519:9, 519:10 — 해설 문장이 어색하고 정답 보기가 가장 길다
- 519:9 explanation 끝의 "다른 쪽은 이 메시지와 관련이 없습니다" 는 모호하다. "나머지 보기는 이 메시지와 관련이 없습니다." 로 바꾼다.
- 정답 보기가 가장 길어서 길이로 찍을 수 있다. choices 는 못 고치므로 참고만 한다.

520:5 — 검사 우회 가능
- `docker exec app sh -c 'echo v2 > /conf/ver'` 로도 통과한다. 이미지가 v2 인지는 검사하지 않는다.
- v2 이미지를 쓰는지 보려면 `docker run --rm app:1 cat /conf/ver` = v2 를 추가로 확인하거나 현 수준으로 수용한다.

521:1~7 — 검사 우회 가능 (공통)
- grade 가 `/tmp/qN.txt` 내용만 확인해서 `echo base-ok > /tmp/q1.txt` 로도 통과한다.
- 각 문제에 `docker image inspect tN >/dev/null 2>&1` ("이미지 tN 이 있다") 검사를 grade_cmd 와 checks 에 추가한다. N 은 문제 번호(t1~t7)다.

521:8 — 검사 우회 가능
- `docker run -d --name q8 alpine sleep 600` 으로도 통과한다.
- grade_cmd 와 checks 에 `[ "$(docker inspect -f '{{.Config.Image}}' q8 2>/dev/null)" = t8 ]` ("q8 이 이미지 t8 로 실행 중이다")를 추가한다.

521:11 — 해설 마지막 문장이 어색하다
- explanation 의 "그 줄 앞에서 내용이 바뀌도록 Dockerfile 을 고칩니다" 를 "특정 줄부터만 다시 하고 싶다면 그 줄(또는 그 앞)의 내용을 바꿔 캐시를 무효화합니다." 로 고친다.

521:9 — 오류 메시지 원문이 다르다
- 원문은 끝에 `manifest unknown` 이 한 번 더 붙는다 (`...not found: manifest unknown: manifest unknown`). 신규 Docker(containerd 이미지 저장소)는 `failed to resolve reference ... not found` 로 나오기도 한다.
- description 코드 블록에 이를 반영하거나, 둘 다 나올 수 있다는 한 줄을 추가한다.

520:10, 520:12 — 설명이 부정확하다
- Docker 23 이상에서는 `system prune --volumes` 만으로는 익명 볼륨만 지워지고, 이름 있는 볼륨까지 지우려면 `-a` 도 필요하다.
- 520:12 의 정답(`-a --volumes -f`)은 여전히 맞다. 520:10 explanation 과 520:7 의 주석에 있는 "볼륨은 `--volumes` 를 줘야만 지워진다"는 정확하지만, 이름 있는 볼륨은 `-a` 도 필요하다는 점을 한 줄 덧붙일 수 있다.
