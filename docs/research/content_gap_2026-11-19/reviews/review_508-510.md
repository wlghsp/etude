## 권고 (사실 오류·모호함)

508:12 — description 사실 오류. "GTID 이벤트의 end_log_pos 는 1725" 라고 썼으나 GTID 이벤트는 수십 바이트라 1725 에서 끝나지 않는다. 1725 는 DELETE 트랜잭션 전체가 끝나는 위치다. 정답(1599)은 영향 없음.
  수정안(description): "DELETE 트랜잭션은 위치 1599 에서 **시작**(GTID 이벤트)하고, 이 트랜잭션의 마지막 이벤트는 1725 에서 끝납니다. 풀 백업 복원 후 binlog 를 재생해 **DELETE 가 반영되지 않게** 하려면 `--stop-position` 에 무엇을 쓰나요?"

508:9 — description 모호. "`--stop-datetime` 는 그 시각 이후에 일어난 이벤트를 재생하지 않습니다" 로 쓰면 DELETE 시각과 같은 이벤트(DELETE 자신)는 재생되는 것처럼 읽힌다. 실제로는 그 시각과 같거나 늦은 이벤트부터 읽지 않는다. 같은 문제에서 DELETE 시각을 그대로 쓰라고 안내하므로 모순.
  수정안(description 의 해당 문장): "`--stop-datetime=\"YYYY-MM-DD HH:MM:SS\"` 는 그 시각과 **같거나 늦은** 이벤트부터는 재생하지 않습니다. 이번에는 kiwi 추가와 실수 DELETE 사이에 시간 간격이 있습니다."

508:10 — hint 가 순서를 사실상 그대로 알려 줌("안전하게 지킨 뒤 복원하고, 마지막에 결과를 확인").
  수정안(hint): "복원은 현재 데이터를 덮어쓰는 작업입니다. 복원하기 전에 무엇을 막고 무엇을 지켜야 할지, 결과 확인은 언제 할지 생각해 보세요."

509:5 — explanation 사실 오류. "인자 모양이 맞지 않아 오류가 납니다" 는 REPLACE 에 해당하지 않는다. `REPLACE(name,1,1)` 은 인자 3개라 오류 없이 실행된다(이름이 그대로 나옴). LENGTH·ROUND 만 인자 개수 때문에 오류. 정답은 SUBSTRING 하나로 유지됨.
  수정안(explanation): "`SUBSTRING(문자열, 시작, 길이)` 는 시작 위치부터 길이만큼 잘라 냅니다. REPLACE 는 글자를 바꾸는 함수라 첫 글자를 꺼내지 못하고, LENGTH 와 ROUND 는 이 모양의 인자(3개)를 받지 않아 오류가 납니다."

509:8 — hint 가 정답 쿼리를 한 글자도 다르지 않게 그대로 줌(`SELECT ROUND(AVG(score), 1) FROM members`).
  수정안(hint): "함수 안에 함수를 넣을 수 있습니다. 안쪽에서 평균을 구하고, 바깥에서 소수점 아래 자리수를 맞춥니다."

509:9 — hint 가 형식 문자열 `'%Y-%m'` 을 그대로 줌.
  수정안(hint): "형식은 따옴표로 감쌉니다. 연도, 구분자 `-`, 월 순서로 이어 쓰세요. 사이의 `-` 는 그대로 출력되는 글자입니다."

509:11 — hint 가 두 WHEN 의 순서를 직접 알려 줌(설명 속 "높은 기준을 먼저").
  수정안(hint): "CASE 로 시작해 END 로 끝납니다. 위에서부터 처음 맞는 조건을 고르니, 두 WHEN 의 순서가 바뀌면 95점의 등급이 어떻게 되는지 생각해 보세요."

510:2 — hint 가 핵심(`WHERE e.id IS NULL`)과 JOIN 구문을 사실상 전부 알려 줌.
  수정안(hint): "`emp` 를 왼쪽, `dept` 를 오른쪽에 두고 `RIGHT JOIN` 하면 짝 없는 부서의 직원 칸은 `NULL` 이 됩니다. 그 행만 `WHERE` 로 거르세요. `mariadb -N hr -e \"...\"` 의 출력을 `>` 로 저장합니다."
