# 세트 542·543·544 점검 (읽기 전용, 정적)

대상: 542 sudo 위임(10문제) / 543 ACL·특수권한(12문제) / 544 계정 정책(12문제).
근거: DB 문제 텍스트, `scripts/content-gen/new_sets/set542~544.py`(정답·setup·checks), `backend/verify/set542~544.json`. 점검 기준은 `README.md` 의 8항목. 실행은 하지 않았고(`verify:quests` 는 별도), 사실 정확성은 sudo 1.9(Ubuntu 22.04)·acl·shadow-utils 4.8 동작을 기준으로 코드·설명과 대조했다.

판정: **차단 없음.** 권고 7건(대부분 힌트 누설), 참고 8건.

## 차단

## 권고

### 힌트가 정답을 거의 그대로 말함 (README 가 가장 많이 나온다고 한 유형)

1. **542:5** (허용한 명령이 전권이 되는 경우) — 힌트 "편집기에는 외부 명령을 실행하는 기능이 있습니다"가 정답 보기(셸 탈출)를 그대로 가리킨다.
   수정안: "`vim` 이 root 로 떠 있는 동안 그 프로그램 **안에서** 할 수 있는 일이 무엇인지, 인자 제한이 그것까지 막아 주는지 생각해 보세요."
2. **542:6** (`sudo {0} -U carol`) — 힌트 "영어 단어 list 의 첫 글자"가 정답 `-l` 을 직접 알려 준다. 설명의 "이 옵션은 목록 조회와만 함께 쓸 수 있습니다"도 같은 효과.
   수정안: 힌트를 "`sudo -h` 에서 '허용된 명령을 보여 주는' 옵션을 찾아보세요. 암호 캐시를 다루는 옵션은 목록을 보여 주지 않습니다."로, 설명의 "목록 조회와만" 구절은 삭제.
3. **544:4** (`passwd -{0}` / `usermod -{1}`) — 힌트가 "lock 의 앞글자(소문자) / unlock 의 앞글자(대문자)"라 정답 `l`, `U` 가 그대로 나온다.
   수정안: "`passwd` 와 `usermod` 는 같은 동작에 쓰는 옵션 글자의 대소문자가 서로 다릅니다. 각 명령의 `--help` 에서 lock·unlock 설명을 찾아보세요."
4. **544:3·5** 와 **544:10** — 힌트에 `passwd --help` 가 같은 문장 안에서 두 번 나오고(3번 "…찾아 보세요. `passwd --help` 에 설명이 있습니다."), 10번은 "`usermod` 의 같은 옵션"까지 명령·옵션을 말한다. 3번은 중복 문장만 지우고, 10번은 "계정을 만들 때 셸을 정한 옵션을 기억하나요? 이미 있는 계정을 고치는 명령에도 같은 이름의 옵션이 있습니다."로 방향만 남기면 된다.
5. **544:12** (last·lastlog·lastb) — 힌트의 "시간순 기록 전체 / 계정마다 한 줄 / 실패 기록"이 정답 보기 내용과 거의 같다. 수정안: "세 명령은 읽는 파일이 서로 다릅니다. 각각 어떤 파일(wtmp·lastlog·btmp)에서 무엇을 읽는지 이름에서 떠올려 보세요."

### 선택지 모호

6. **543:8** (대문자 S) — 오답 보기 4 "소문자와 대문자는 표시 방식만 다르고 상태는 같다"는 일부 참이다(둘 다 setgid 가 켜진 상태이고, 다른 것은 그룹 x 유무). 정답 보기와 구분이 흐려 진지하게 읽은 학생이 맞는 말로 오해할 수 있다.
   수정안: "소문자 `s` 와 대문자 `S` 는 서로 다른 특수 비트를 가리킨다"로 바꾸거나, "대문자 S 는 오류 표시일 뿐 setgid 는 꺼져 있다" 쪽으로 명백한 오답으로 만든다(2번 보기가 이미 비슷하니 4번을 "`S` 는 sticky 와 setuid 가 함께 켜졌다는 뜻이다" 정도로).

### 채점이 느슨함

7. **544:11** — 검사는 "ops01·ops02 있음 / root 없음 / 공백 없음"뿐이라, 범위 옵션 없이 `lastlog | awk '/Never/{print $1}'` 로 `daemon`·`bin` 같은 다른 시스템 계정까지 넣어도 통과한다(설명은 "일반 계정만"). 수정안: 검사 하나 추가 `! grep -qxE "daemon|bin|sys|nobody" /tmp/q11.txt` (샌드박스 계정 목록은 확인 필요).

## 참고

1. **544:6** 설명 — "nologin 셸로 완전히 막는다"는 과장이다. nologin 은 셸만 막고 `ssh -N -L` 같은 포트 포워딩은 키 인증으로 통과할 수 있다. 계정 만료(`chage -E 0`/`usermod -e 1`)가 핵심 해결이고, 모두 sshd `UsePAM yes`(Ubuntu·Rocky 기본) 전제다. 정답 보기 문구는 "…계정 만료나 nologin 셸을 함께 쓴다"라 틀리지는 않으니 해설에 "포트 포워딩은 `AllowTcpForwarding no`·`authorized_keys` 의 `restrict` 로 따로 막는다" 정도만 덧붙이면 된다.
2. **543:9** — 시나리오(`-rw-r--r--` = umask 022)는 Ubuntu 기본이다. 이 세트의 샌드박스(Rocky 9)에서 일반 계정은 사용자별 사설 그룹(UPG) 때문에 umask 가 002 라 새 파일이 664 로 나온다. 퀴즈 자체는 맞지만 학생이 실제 샌드박스에서 재현하면 664 가 나올 수 있으니, 지문을 "umask 가 022 인 환경에서"로 한정하면 혼란이 줄어든다. umask 개념도 이 세트에서 처음 설명 없이 쓰인다(선행 세트에서 다뤘는지 확인).
3. **543:3** — 설명에서 `-x` 가 "지정한 항목 제거"라고 옵션 4개를 모두 풀어 줘서, 사실상 읽기만 하면 풀린다(정답 자체가 설명에 있다). 의도된 도입 문제면 두고, 변별력을 원하면 설명에서 `-x` 줄만 빼고 해설로 옮긴다.
4. **543:11** — 설명이 "그룹 준비(만들기 → 멤버) → 폴더 → 그룹 지정 → 모드 → 확인"으로 순서를 거의 전부 말해 순서 고정에는 성공했지만 풀이가 된다(README 의 "설명으로 고정" 방식이니 허용). 다만 `chgrp` 와 `chmod 2770` 의 순서는 실제로는 어느 쪽이든 같은 결과(디렉터리는 chgrp 가 setgid 를 지우지 않음)라 설명의 "지정한 다음에 setgid" 문장이 순서를 고정하는 유일한 근거다.
5. **543:12** — 검사 2 가 이름 있는 `default:group:dev:rw` 를 요구한다. 무이름 그룹(`setfacl -d -m g::rwx`)으로 같은 결과를 내도 검사 3 은 통과하지만 검사 2 에서 실패한다. 설명이 "default ACL 로 해결"이라 의도는 맞고 힌트도 `g:` 를 짚으니 허용 범위.
6. **544:9** — 만료일 검사가 `date -u` 일수와 shadow 8번째 칸을 비교한다. `chage -E` 는 로컬 시간대로 환산하므로 샌드박스가 UTC 가 아니면 하루 어긋난다. UTC 라면 문제 없으니 컨테이너 시간대만 확인.
7. **542 전체** — sudo 설치(`apt-get update && install`)가 각 실습 setup 에 들어 있어 첫 실행은 네트워크 의존·지연이 있다(주석에 명시됨, 구조상 현재 선택지). 오프라인 샌드박스에서는 실습 2~4·7·8 이 모두 막힌다.
8. **정답 위치** — 생성기가 `pos = (n*7+seed)%4` 로 정답 위치를 분산하므로 "항상 1번" 문제는 없다. 544:4 의 칸 두 개는 같은 칩 목록을 쓰므로(`l`·`u`·`U`·`S`·`e`) 학생이 같은 칩을 두 칸에 쓰지 못하게 하는 규칙이 있는지는 화면에서 확인 필요.

## 문제 없음 (점검 통과)
