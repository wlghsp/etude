# 점검: 세트 551·552 (읽기 전용, 정적 점검)

대상: 551 볼륨 백업·복원과 권한(12문제), 552 Compose 구성 실습(12문제).
방법: DB 의 문제 텍스트 + `new_sets/set551.py`·`set552.py` 의 정답·setup·checks 대조. 실행은 하지 않았다 (`verify:quests` 담당). 판정: **CHANGES_REQUIRED** (차단 1, 권고 7).

표기: `코드상 확인됨` = 정적 확인, `미검증·추정` = 실행·문서 확인 필요.

## 차단

### 552:2 (compose 네트워크 이름) — 전제가 모순이라 정답이 하나로 정해지지 않음 (코드상 확인됨)
- 문제: 최상위에 `backend` 만 정의하고 "서비스들이 별도 `networks` 설정 없이 `backend` 를 쓴다고 가정". 그러나 `networks` 를 적지 않은 서비스는 `backend` 가 아니라 `default` 네트워크에 붙는다. 이 가정대로면 `docker network ls` 에는 `shop_default` 가 보이고(보기 4), 아무도 쓰지 않는 `backend` 는 Compose v2 에서 만들어지지 않는 것이 보통이다 (미검증·추정). 즉 보기 1(`shop_backend`)과 보기 4(`shop_default`)가 모두 근거를 갖는다.
- 수정안: 설명을 "서비스 `api`, `db` 가 모두 `networks: [backend]` 로 이 네트워크에 속한다(그래서 기본 네트워크는 쓰지 않는다)"로 바꾼다. 해설의 `shop_default` 문장은 유지.

## 권고

1. **552:6 (순서) 카드가 정답 순서로 저장됨 + 사실 표현 부정확.**
   - DB `choices` 가 정답 순서 그대로이고 `answer_spec` 이 `[0,1,2,3]`. 화면에서 카드를 섞어 보여 주지 않으면 풀이가 필요 없다 (미검증·추정: UI 확인). 다른 순서형(551:12 는 `[2,0,4,3,1]`)처럼 카드 순서를 바꾸고 spec 을 맞춘다.
   - 4번 카드 "`app` 컨테이너가 만들어지고 시작된다", 힌트 "`app` 은 `db` 의 상태가 정해지기 전에는 만들어지지 않습니다"는 부정확하다. Compose v2 는 `service_healthy` 일 때 의존 서비스의 **생성**까지 막지 않고 **시작**을 healthy 뒤로 미루는 출력이 일반적이다 (`Created` 가 먼저 나오고 `Waiting`→`Healthy`→`app Started`; 미검증·추정). 카드를 "`app` 컨테이너가 시작된다", 힌트를 "`app` 은 `db` 의 상태가 정해지기 전에는 시작되지 않습니다"로 바꾼다. 0번 카드의 "만들어지고 시작된다"는 그대로 가능.
2. **552:8 이 552:7 설명에 누설됨.** 7번 설명의 "(파일을 고치기만 하고 `docker compose up -d` 를 해도 컨테이너 안은 `v1` 입니다.)"가 8번 정답(그대로 옛 소스)을 먼저 알려 준다. 7번에서 해당 괄호를 지우거나 8번을 7번 앞으로 옮긴다.
3. **552:3 선행 지식 없음.** `condition: service_healthy` 를 이 문제 전에는 가르치지 않고 힌트는 "Compose 문서를 보라"고만 한다 (샌드박스에서 문서 접근이 안 될 수 있음). 6번에서야 이름이 나온다. 3번 설명에 "`depends_on` 의 `condition` 에 `service_healthy` 라는 값이 있다"를 한 줄 소개하거나 해설에 풀이를 둔다. 힌트의 `["CMD", ...]`·`condition:` 구조 안내는 줄여도 된다.
4. **제목·힌트 누설.** 551:8(제목 `--user`, 설명도 옵션 이름 명시), 551:9(제목 `cp -a`, 힌트 "아카이브 모드"), 552:11(제목 `compose.override.yaml` 이 곧 정답 파일명), 552:12(힌트가 `mem_limit`·`cpus`·`m`/`g` 단위까지 전부 제시, `deploy.resources.limits` 도 언급), 551:6(힌트가 "root 권한으로 풀면 기록된 값을 따릅니다"). 제목은 증상·목적으로 ("백업 파일의 주인 정하기", "볼륨을 소유자 그대로 옮기기", "덧씌우기 파일이 적용되지 않는다", "메모리·CPU 제한 걸기"), 힌트는 찾는 방법만.
5. **551:7 과 551:10·12 의 메시지 충돌.** 7번은 `db` 를 멈추지 않고 백업하라고 하는데 10·12번은 쓰는 중 백업이 위험하니 멈추라고 가르친다. 7번 설명에 "여기서는 `--volumes-from` 동작을 익히는 연습이고, 실제 DB 라면 10번처럼 멈추거나 덤프를 쓴다"를 한 줄 덧붙인다.
6. **551:12 설명이 순서를 전부 말함.** 설명이 "백업→확인→복원→확인"과 "멈춤 먼저, 아카이브 확인은 복원 전"을 모두 적는다. 순서 고정 목적은 충족하지만 카드 풀이가 사실상 필요 없다. 괄호 안 설명만 남기고 앞의 화살표 나열은 지우는 것을 권한다 (차단 아님).
7. **552:4 정답 예시가 "가장 최근" 이 아님.** 정답 `(index .State.Health.Log 0).Output` 은 **가장 오래된** 점검이다 (Log 는 시간순 최대 5개). 모든 점검이 같은 메시지라 채점에는 영향이 없지만 "가장 최근" 설명과 어긋나므로 설명을 "점검 출력 메시지"로 하거나 정답을 `len` 기반 마지막 항목으로 바꾼다.

## 참고 (조치 선택)

- 551:1 힌트 "볼륨의 내용을 읽을 수 있는 곳은 그 볼륨을 마운트한 컨테이너 안입니다"는 과장 (root 는 호스트의 `/var/lib/docker/volumes` 로도 읽을 수 있음). "가장 안전한 곳"이 정확.
- 551:10 정답 보기만 길고 단서("잠시 멈추거나")가 많아 눈에 띔. 다른 보기도 길이를 맞추면 좋다.
- 551:8·9 는 호스트에서 `chown`, `cp -rp`, `tar | tar` 같은 다른 경로로도 check 를 통과한다 (옵션 학습이 목적이라 허용 가능). 551:9 는 권한(mode) 보존을 검사하지 않고 uid 만 본다.
- 552:4 는 `docker compose exec web cat /tmp/ok 2>&1` 로도 같은 메시지를 얻어 통과한다 (inspect 를 안 써도 됨). 허용 가능.
- 552:11 은 compose.yaml 을 고쳐 debug 로 만들고 빈 override 파일을 두어도 통과한다 (check 3 개 모두 만족). 허용 가능.
- 552:3 은 `interval: 1s` 여부를 검사하지 않는다 (설명은 1초라 함).
- 552:10 해설의 `!override` 는 Compose **2.24 이상**이라고 적혀 있다. `!reset`·`!override` 태그 도입은 2.24.0 쪽으로 기억하나, 이번 점검에서 공식 문서로 확정하지 못했다 (미검증·추정). 샌드박스 Compose 버전(로컬은 5.7.0)에서 동작하는 것은 문제없고, 숫자는 릴리스 노트로 확인 후 유지/수정.
- 551:3 설명이 `tar czf 파일 -C 폴더 .` 형태를 사실상 알려 주고 힌트가 `-C` 와 아카이브 이름 자리까지 설명한다. 처음 접하는 tar 이므로 허용 가능한 수준.

## 문제 없음 (항목별 점검 통과)

- 사실 정확성: `docker save`/`commit`/`cp` 설명(551:1), `tar xzf … -C /data`(551:5, `czf`는 빈 아카이브 거부, `tzf`는 목록, `rzf`는 압축본에 추가 불가), root 의 tar 가 uid 복원(551:6), `--volumes-from` 동일 경로 마운트(551:7), `--user` 로 새 파일 주인 결정(551:8), `cp -a` 소유자·권한 보존(551:9), 600 root 파일을 uid 1000 이 읽지 못해 Permission denied, root 헬퍼로 해결(551:11), 552:1 네트워크 분리, 552:5 `--wait`, 552:7·8 `up` 은 이미지가 있으면 재빌드 안 함, 552:9 맵 병합(키 단위 덮어쓰기), 552:10 ports 목록은 이어 붙여짐, 552:11 `compose.override.yaml` 자동 적용, 552:12 `mem_limit: 64m`=67108864·`cpus: 0.5`=500000000 과 `deploy.resources.limits` 동등.
- 복수 정답: 객관식 551:1·10, 552:8·10 은 정답 1개(552:2 만 위 차단). 551:5 빈칸은 `xzf` 하나.
- 무행동 실패: 실습 전부 결과 파일·볼륨·컨테이너 상태가 setup 에서 없거나 기대값이 아니어서 무행동이면 실패 (551:2~4·6~9·11, 552:1·3·4·7·9·11·12). 551:7 의 "db 실행 중" check 만 단독으로는 통과지만 `db.tgz` check 로 실패.
- 순서 고정: 551:12 는 설명으로 고정, 카드도 섞여 있음.
- 현장 정보: IP·도메인·센터·내부 이름 없음 (`alpine`, `nginx:alpine`, `shop`, `example` 류 일반 이름만).
- 문맥 밖 지식: 551 은 520·228 선행으로 `-v`, uid, 권한 개념 소개 충분 (551:11 의 600 권한은 520 선행). 552 는 위 권고 3 외 문제 없음.
- setup 정리(CLEAN/PRE)와 check 의 `cd` 경로, `WAITH` 대기(15초)는 일관됨.
