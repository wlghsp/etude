## 565 TCP 연결의 일생 — PASS
**권고**
- 문제 4: TIME-WAIT 은 약 60초 지워지지 않아 연결을 두 번 만들면 `= 1` 채점을 통과할 수 없음 → 개수 검사를 `-ge 1`.
- 문제 11: description·힌트가 순서 나열 → "세 번의 메시지 교환 뒤에 데이터" / "누가 먼저 말을 걸고, 누구의 확인으로 끝나는지".
- 문제 3·5·6: 힌트에 ss 필터·`grep -o 'pid=...'`·`kill PID` 등 해법 골격 → 방향만.
- 문제 1: description 의 "예: `0.0.0.0:9000`" 이 정답 그대로 → "`주소:포트` 형태".
**참고**: 7·8·9 길이비 1.17·1.05·1.07 로 기준 이내. 사실(OpenBSD nc -N/-zv, ss state 필터·-p, TIME-WAIT/CLOSE-WAIT) 맞음.

## 566 TLS 와 인증서 읽기 — PASS
**권고**
- 문제 11: TLS 1.3 에서는 키 합의가 hello 안에서 먼저 일어나고 인증서(암호화됨)·검증은 그 뒤인데 "검증이 통과해야 키를 합의" 로 서술 → 4번 항목 "핸드셰이크를 마치고 암호화된 데이터를 주고받는다", 해설 수정, description·힌트의 순서 나열 제거.
- 문제 7: 힌트가 명령 전체 → 옵션 조합 방향만(`openssl req -help`).
- 문제 5: 힌트가 `grep "Verify return code"` 까지 거의 완성 → "검증 결과를 알려 주는 줄만 고르세요".
- 문제 8: 해설의 "CPU·문자셋·케이블과는 무관" 이 실제 오답과 불일치 → "CPU 사용률·파일 용량·포트 번호".
**참고**: 문제 4 는 CA 없이도 같은 오류로 통과(읽기형 한계). 2·3 은 추측 통과 가능. 사실(-ext subjectAltName, -checkend, 코드 21/0/62, -verify_hostname, openssl ca -startdate/-enddate) 3.0.2 에서 맞음.

## 567 서브넷 계산 손연습 — PASS
**권고**

- 문제 11: 힌트가 순서 전체 나열 → 교체. 문제 1: 힌트가 계산식 그대로 → 낮춤. 문제 4·5·6: 힌트가 루프 골격 → 방향만.

## 568 ping·traceroute·mtr 읽기 — PASS
**권고**

- 문제 7: 길이비 2.21 → 정답 "응답이 약 7개 홉을 지나 왔다", 오답 부연, 힌트 낮춤. 문제 8: 길이비 1.75 → 정답 줄임, 힌트 낮춤.

- 문제 10: 힌트가 순서 전체 나열, IP 와 이름의 선후가 description 에 없음 → "경로(IP)가 되는지 확인한 뒤에야 이름 해석을 의심" 추가, 힌트 교체.
**참고**: 1(TTL 64)·2(1008)는 환경 기본값 의존. 5 의 "뛴 홉" 은 5 로 하나로 정해짐. 샘플은 문서용·사설 주소만 사용.
