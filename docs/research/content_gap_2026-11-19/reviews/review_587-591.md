# 점검 결과: 세트 587~591 (독립 에이전트, 읽기 전용 정적 점검, 2026-11-20)

점검 기준은 README 의 '점검 기준'과 lessons.md. 코드를 실행하지 않은 점검(코드상 확인)이며 객관식 길이비는 스크립트로 계산했다(전부 1.5 이하).

## 전체 요약
- 차단 1건: 590:10 (`ping -6` 빈칸의 복수 정답: 주소가 IPv6 리터럴이면 `-n`·`-q` 도 IPv6 로 보낸다).
- 권고: 명령 적기 정규식이 유효한 변형을 막음(587:6, 588:3·5·6, 589:6), 체크 허점(589:1 암호 비움 미검사, 588:5 reload 순서), 순서 문제 모호(589:10), 힌트가 구문 틀을 줌(589:3·6·9, 588:4·6, 590:2·9, 591:2).
- 환경 의존: 590:1·2(Docker 기본 브리지의 IPv6 가능 여부), 589(ssh 클라이언트가 git 의 Recommends 로만 설치), 587:5(netcat-openbsd 의 프로세스 이름 `nc`).

## 반영 요약
- 587: 주소 추가 명령 정규식 완화(`address`·인자 순서·label), 해설의 자동 복구 예시를 접속과 분리된 예약으로, 순서 힌트 낮춤.
- 588: 열린 포트 비교를 정렬 후로, `--permanent` 위치 자유·reload 가 뒤에 있는지 검사, nft 규칙 정규식 완화·힌트 낮춤, 사용률 힌트 낮춤.
- 589: 키 암호 비움 검사 추가, setup 의 키 파일 정리, `-R` 바인드 주소 허용, 터널 샘플에 0.0.0.0 미끼 행 추가(127.0.0.1 만 인정), 순서 항목에 시점 문구, 힌트 낮춤.
- 590: 10번을 `ip -{0} addr show lo`(6·4·s·c)로 교체해 복수 정답 제거, 힌트 낮춤.
- 591: 힌트 낮춤, 순서 마지막 항목 중복 제거.

## 반영 결과
- 지적을 `new_sets/set587~591.py` 에 반영하고 `emit_new_sets.py --rewrite` 로 다시 만들었다. 재검증 통과, `check-content.sh` 통과.
- 반영하지 않은 것: 587:5 의 `nc` 프로세스 이름 가정과 589 의 ssh 클라이언트 설치 의존은 이미지 구성 사항이라 그대로 둔다(아래 남은 확인). 590 샘플의 `proto ra` 생략 등 단순화, 588:4 의 반올림 구분(65500 변경)은 선택 사항.
- 남은 확인(배포 호스트): `docker run --rm etude-linux sh -c 'ip -6 addr show lo; ping -6 -c1 ::1'` 로 IPv6 루프백과 ping 동작을 확인한다. 이 로컬 Docker(Colima)에서는 동작을 확인했다.
