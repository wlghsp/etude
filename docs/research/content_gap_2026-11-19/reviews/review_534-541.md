## 권고

### 정답 정확성·샘플 형식

- 537:10 — description 은 `df -T` 출력이라 하고 샘플은 `118G`·`2.0G` 같은 사람이 읽는 단위(`-h`)다. 실제 `df -T` 는 1K 블록 숫자이므로 문서와 샘플이 다르다.
  수정안: description 의 `df -T`(파일시스템 종류 포함)를 `df -hT`(종류 포함, 사람이 읽는 단위)로 바꾼다. setup 샘플은 그대로 둔다.
- 534:2 — 샘플이 실제 `lsblk` 기본 출력이 아니다. 실제 기본 출력은 `├─sda1` 같은 트리 문자와 `MAJ:MIN`, `RM`, `RO` 열이 있다. 샘플은 `lsblk -l -o NAME,SIZE,TYPE,MOUNTPOINTS` 에 해당한다. 실습 뒤 실제 출력을 만났을 때 어긋난다.
  수정안: description 첫 문단 끝에 "(출력은 `lsblk -l -o NAME,SIZE,TYPE,MOUNTPOINTS` 로 뽑은 목록형입니다. 기본 `lsblk` 는 트리 모양으로 나옵니다)"를 추가한다.
- 539:3 — 샘플의 아키텍처 열이 `arm64` 다. 같은 세트의 대상은 Ubuntu 22.04 로, 보통 `amd64` 로 본다.
  수정안: description 코드블록의 두 줄 `arm64` 를 `amd64` 로 바꾼다.
- 536:9 — 채점의 `SWAPSPACE2` 위치(`skip=4086`)는 페이지 크기 4096 을 가정한다. 64K 페이지 호스트(예: arm64 일부)에서는 위치가 달라져 정답이 실패한다. (`미검증·추정`)
  수정안: grade_cmd 와 checks 의 `dd ... skip=4086 count=10 ...= SWAPSPACE2` 를 `grep -aq SWAPSPACE2 /tmp/lab/swapfile` 로 바꾼다(`head -c 70000 /tmp/lab/swapfile | grep -aq SWAPSPACE2` 도 가능). 파일 전체에서 서명 문자열 존재만 본다.
- 541:10 — 채점이 `journalctl -k` 출력에 `kernel:` 줄이 있다는 것에 의존한다. 이는 샌드박스 호스트의 커널 링버퍼와 journald 의 `/dev/kmsg` 읽기 권한에 달려 있다. 호스트나 프로필이 바뀌어 커널 메시지가 비면 `-- No entries --` 가 되어 정답도 실패한다. `linux-systemd` 가 privileged 프로필이라 지금은 통과하지만 환경 의존이다. (`미검증·추정`)
  수정안: grade_cmd 와 checks 의 `grep -q "kernel:"` 를 "서비스 줄이 없고, 머리글(`-- `)이 아닌 모든 줄이 ` kernel: ` 를 포함한다"로 바꾼다.
  - 예: `[ -s /tmp/q10.txt ] && ! grep -q bootdemo /tmp/q10.txt && ! grep -v -e '^-- ' -e ' kernel: ' /tmp/q10.txt | grep -q .`
  - 이러면 커널 메시지가 없을 때도 안전하게 통과하고, 무행동(파일 없음)은 여전히 실패한다.
- 541:9 — `logger -p user.err` 가 journald 로 들어가는 것에 의존한다. journald 가 안 떠 있으면 정답도 실패한다(setup 의 `sleep 1` 만 있음). spec 상 7/7 통과 확인은 있다. (`미검증·추정`)
  수정안: setup_cmd 끝에 `journalctl -b -p err --no-pager | grep -q bootdemo || sleep 2` 를 추가해 기록 지연을 흡수한다.
- 538:7 — 채점이 `langpacks-en` 이 `dejavu-sans-fonts` 의 의존 패키지라는 것에 의존한다. 베이스 이미지(`rockylinux:9-ubi-init`)가 갱신돼 의존이 바뀌면 정답이 실패한다. (`미검증·추정`)
  수정안: grade_cmd 와 checks 의 `grep -q "langpacks-en"` 를 지우고 `Removing dependent packages` 확인만 남긴다. 의존 패키지가 없는 이미지에서 이 줄이 없을 수 있으면 `grep -Eq "Removing( dependent)? packages|Remove +[0-9]+ Package"` 로 바꾼다.

## 참고

- 535:11 — `fuser` ACCESS `F` 는 "파일을 열고 있음"(읽기·쓰기 구분 없음)이다. 보기 A 와 explanation 이 `rsync` 를 "파일을 쓰고 있어서"라 쓴다. 의미에 지장은 없다. 문구를 "파일을 열고 있어서"로 바꾸면 더 정확하다.
- 534:8 — 두 이미지 중 하나를 고르는 문제라 `blkid` 를 한 번도 실행하지 않고 찍어도 50% 로 통과한다. 무행동은 실패하지만 추측은 통과한다. 이미지 세 개로 늘려 GPT 인 것을 찾게 하면 추측 확률이 줄어든다.
- 정답 선택지가 가장 긴 객관식이 많다: 534:1, 535:11, 536:2, 536:5, 538:2, 538:8, 539:10, 540:2, 541:7, 541:12. 선택지 길이를 맞추거나 정답 위치를 섞으면 길이만으로 고르는 것을 막는다.
- 534·535 중복: 534:4·5·6 이 535:2·4·5·6 과 거의 같은 실습(truncate, mkfs, blkid UUID)이다. 535 명세가 "534 와 독립이며 사전지식으로 가정하지 않는다"고 못 박아 둔 의도된 중복으로 보인다. 같은 단원에서 연달아 풀면 반복이다. 534 쪽 실습 4·5 를 읽기형으로 줄이거나 535 쪽 2·4 를 줄이는 것을 고려할 수 있다.
- docs 링크: 534 는 모든 문제에 `lsblk(8)`·`fdisk(8)`, 535 는 `mount(8)`·`truncate(1)` 가 문제 내용과 무관하게 똑같이 붙어 있다(536 도 `fstab(5)`·`swapon(8)` 고정). 문제별로 `mkfs.ext4`·`blkid`·`dumpe2fs`·`e2fsck`·`mkswap` 매뉴얼로 바꾸면 도움이 된다.
- 537:2 — 실제 `pvs` 는 `PSize` 가 `<100.00g`(메타데이터 때문에 약간 작게) 로 나오는 일이 많다. 샘플은 정확히 `100.00g` 다. 읽기 연습에는 지장 없고, 필요하면 `<100.00g` 로 바꾸면 더 실제답다.
- 541:11 — `/proc/cmdline` 은 호스트 커널 값(예: `BOOT_IMAGE`, `root=UUID=…`)이 그대로 보인다. 채점은 현재 값과 비교하므로 안전하다. 다만 호스트의 실제 값이 화면에 노출된다. 현장 정보 금지 관점에서 문제 설명에 "값은 이 샌드박스 호스트의 것이며 현장 서버와 같지 않을 수 있다"는 한 줄이 있으면 좋다.
- 538:1·3·4·7·9·10 — 실제 dnf·rpm 명령으로 푸는 실습이라 만족도가 높다. 단, 모든 정답이 `rockylinux:9-ubi-init` 에 설치돼 있는 패키지(curl-minimal, openssl-libs, which, vim-minimal, dejavu-sans-fonts)에 의존한다. 이미지가 바뀌면 점검(`verify:quests`)에서 가장 먼저 깨질 곳이다.
- 샌드박스 제약으로 읽기형·샘플 파일 읽기로 대체한 문제의 "실습다움" 평가
  - 540: 실습 5개가 모두 `grep`·`awk`·`tr` 로 샘플 텍스트를 가공하는 문제다. `firewall-cmd`·`getenforce`·`restorecon` 은 한 번도 실행하지 않는다. 출력을 읽는 능력은 연습되지만 "실습이라 부르기엔 억지"에 가장 가깝다. 한계를 인정한다면 문제 제목에 "(출력 읽기)"를 붙여 기대를 맞추는 것이 낫다.
  - 537:2·3·7·10: LVM 도 샘플 파일 읽기 중심이지만, 537:11(`resize2fs` 로 이미지 키우기)이 실제 명령 실습이라 균형은 맞다.
  - 534·535: 이미지 파일에 대한 `truncate`·`mkfs`·`tune2fs`·`blkid`·`dumpe2fs`·`e2fsck` 는 실제 명령이라 실습답다. `mount`·`fdisk` 는 읽기형인데 명세에 이유가 적혀 있고 읽기형도 자연스럽다.
  - 536: fstab 은 사본 편집이라 실습답고, `swapon` 만 읽기형이다.
  - 538·539·541: 실제 명령(`dnf`·`rpm`·`dpkg`·`apt-cache`·`systemctl`·`journalctl`)이 샌드박스에서 동작하는 실습이라 "억지" 소지가 적다.
