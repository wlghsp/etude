# 세트 502·503·504 점검 결과 (읽기 전용, 파일 미수정)

정답 정확성·복수 정답·순서 고정·설명 사실 오류·현장 정보 항목에서는 결함을 찾지 못했다. 실습 문제는 모두 아무것도 안 하면 실패한다. 지적은 힌트 누설이 대부분이다.

## 차단 (고치지 않으면 문제가 성립하지 않음)

- 502:12 — hint 가 정답 순서 전체("시작 → 변경 → 표시 → 변경 → 되돌리기 → 확정")를 그대로 알려 줌.
  수정안(hint): `트랜잭션을 연 뒤 변경하고, 되돌릴 지점을 표시합니다. 그 이후 변경만 취소하고 마지막에 확정하는 흐름을 떠올려 보세요.`
- 503:9 — hint 가 정답 순서 전체("막힌 것을 확인 → 관리자로 들어가 상황 보기 → 정리 → 재확인")를 알려 줌.
  수정안(hint): `문제를 알아챈 뒤, 접속 수 한도와 상관없이 들어갈 수 있는 계정으로 원인을 살펴보고 정리하세요. 해결됐는지는 마지막에 확인합니다.`
- 504:9 — hint 가 정답 순서 전체("키를 만들고 → 서버에 알리고 → 접속을 확인하고 → 올리기")를 알려 줌.
  수정안(hint): `서버가 나를 알아보려면 무엇이 먼저 있어야 하는지 생각해 보세요. push 는 접속이 확인된 뒤의 마지막 단계입니다.`

## 권고

- 502:1 — hint 가 정답 값("`1` 이면 켜진 것")을 알려 줌.
  수정안(hint): `` `SELECT @@autocommit;` 를 `mariadb -N -e` 로 실행하고 `>` 로 저장합니다. 켜져 있으면 1, 꺼져 있으면 0 으로 나옵니다. ``
  (값 1 을 직접 말하지 않음. 해설 주석에는 남겨도 됨.)
- 504:2 — hint 가 정답 값("소유자만 읽기·쓰기는 `600`")을 알려 줌.
  수정안(hint): `chmod 로 권한을 숫자로 줍니다. 읽기=4, 쓰기=2, 실행=1 을 더해 소유자/그룹/기타 순서로 적습니다. 소유자만 읽기·쓰기이면 어떤 숫자일까요?`
- 502:10 — hint("세션들이 서로 반대 순서로 행을 잡아서 생긴 문제였습니다")가 정답("같은 순서로 갱신")을 사실상 알려 줌.
  수정안(hint): `데드락은 서로 상대가 쥔 것을 기다리는 고리입니다. 그 고리가 생기지 않게 하려면 락을 잡는 순서를 어떻게 해야 할지 생각해 보세요.`
- 503:8 — hint("지금 연결된 스레드 수")가 보기 이름 `Threads_connected` 를 한글로 그대로 풀어 줌. 또 이 세트는 Threads_connected 를 가르친 적이 없다(문맥 밖 사실).
  수정안(hint): `지금 이 순간의 값이 필요합니다. 서버 시작 이후의 최고치가 아닙니다.`
  (문제 자체는 정확. 문맥 확장이 꺼려지면 503:5 hint 에 `SHOW STATUS LIKE 'Threads%'` 를 한 번 소개하는 방안도 있음.)
- 503:7 — hint("락을 쥐고 안 놓는다는 뜻")가 정답을 거의 알려 주고, 정답 보기가 가장 길고 구체적이라 요령으로 맞힐 수 있음. 정답이 틀리지는 않음.
  수정안(hint): `이 오류는 내 쿼리가 아니라 다른 쪽 때문에 생기는 경우가 많습니다. 원인을 확인하기 전에 설정이나 서버를 건드리지 마세요.`
- 502:6 — 잠금 세션이 `SLEEP(8)` 인데 학습자가 두 번째 명령을 손으로 입력하면 8초 안에 못 쳐서 UPDATE 가 성공해 버릴 수 있음(오류 파일이 안 생겨 재시도해야 함).
  수정안(description 의 첫 세션 명령): `` `mariadb bank -e "START TRANSACTION; SELECT * FROM accounts WHERE id=1 FOR UPDATE; SELECT SLEEP(20); ROLLBACK;" &` `` (8 → 20)
- 502:9 — SLEEP(2) 안에 두 세션을 모두 띄워야 데드락이 나므로 손으로 따로 치면 실패하기 쉬움.
  수정안(hint 끝에 추가): `두 명령을 연달아 한 번에 붙여넣거나, 한 줄에 이어서 실행해야 2초 안에 겹칩니다.`
- 504:9 — 카드 "ssh -T 로 접속 확인"은 이 세트에서 가르친 적 없는 명령. 정답은 맞음. 해설에 `ssh -T git@호스트` 한 줄을 넣어 설명하면 보완됨(수정안 explanation: 기존 문장 뒤에 ` (`ssh -T git@호스트` 는 접속·인증만 확인하는 명령입니다.)`).

## 참고 (조치 불필요)

- 503:6 은 502:8 과 풀이(innodb_trx 로 세션 찾아 KILL)가 사실상 같음. 시나리오(1205 상황집)가 달라 유지 가능.
- 502:3, 502:4, 502:5 는 트랜잭션·SAVEPOINT 없이 같은 최종 값을 만들어도 통과함(채점 한계). 힌트·설명으로 방향이 분명해 허용 가능.
- 503:5 는 한도를 올리는 해결(`SET GLOBAL max_connections`)도 통과함. 힌트가 두 방법을 모두 안내하므로 정상.
