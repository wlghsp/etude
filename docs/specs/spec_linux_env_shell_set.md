# 명세 — 리눅스 환경 변수와 쉘 설정 세트 (export · PATH · VAR=값 명령 · unset · ${VAR:-} · 설정 파일 · alias)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-12). 세트 350. 근거: 세트 50(10번 `export` 로 자식에게 넘기기), 세트 3(7·8번 환경변수 설정·전체 저장), 세트 10(8번 PATH 등록, 3번 `/etc/profile.d`), 세트 21(9번 alias 를 `~/.bashrc` 에 등록)이 각각 **한 문제씩** 다룬다. 세트 135/263·204/280·213/283 은 환경 변수·alias·`export` 를 섞어 다루지만 대부분 퀴즈다. 이 세트는 "**쉘 설정을 한 흐름으로**" 묶는 데 집중한다: export 한 것과 안 한 것의 차이, PATH 의 **순서**와 `command -v`, 명령 한 번에만 주는 `VAR=값 명령`, `unset`, 기본값 `${VAR:-값}`, 설정 파일에 적고 `source`, alias 추가·`unalias`. 세트 50·3·10·21 과 개념이 일부(export·PATH 추가·alias 등록) 겹치므로, 이 세트는 **새 쉘에서 설정 파일을 읽어 확인**하고 `VAR=값 명령`·`unset`·`${:-}`·PATH 우선순위처럼 겹치지 않는 부분에 무게를 둔다. 겹침은 "부분 겹침"이며 전면 중복은 아니다.

## 목표

작은 실습 폴더(`/tmp/lab`: 실행 파일 `tools/hello-lab`, 같은 이름이 든 `new/`·`old/`, 스크립트 `showenv.sh`, 설정 파일 `my_bashrc`·`aliasrc`)에서 "변수 → 환경 변수 → PATH → 일회성 변수 → 지우기 → 기본값 → 설정 파일 → alias" 를 쌓는다. 문제마다 새 개념 하나.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1.
- setup 은 `/tmp/lab` 을 지우고 모든 재료를 다시 만든다. 몇 번 실행해도 같은 상태다. 학습자 쉘의 상태(alias·export)는 채점 쉘에 보이지 않으므로, 결과를 **파일로 저장**하게 하거나 채점이 **새 쉘(`env -i ... bash -c 'source 파일; ...'`)에서 설정 파일을 읽어** 값을 본다.
- 채점은 파일 내용의 md5 일치와, 설정 파일을 source 한 새 쉘의 실제 값(자식에게 전달되는지는 `printenv` 로)을 본다. 9번은 `greet.sh` 를 `NAME` 미설정·`Ann`·빈 값 세 경우로 실행해 `:-` 와 `-` 의 차이까지 가른다. 11번은 기존 `LAB_LEVEL` 줄이 남아야 해서 `>` 로 덮어쓴 풀이를 거른다. 3번은 PATH 맨 끝이 `/tmp/lab/tools` 이고 기존 `/usr/bin` 이 남아야 해서 PATH 를 덮어쓴 풀이를 거른다.
- 한계: 1·2·5·7번 같은 "결과를 파일에 저장" 문제는 값을 직접 `echo` 로 적어도 통과할 수 있다. 5번은 스크립트가 남기는 `seen.log`(첫 실행 값이 `debug`, 두 줄 이상), 3번은 `ran.log` 로 실제 실행을 확인해 일부 줄였다.
- 모든 터미널 문제는 setup 직후에는 채점이 실패한다 (결과 파일 없음, 설정 파일이 그대로).
- 이미지(`etude-linux`)의 bash, GNU coreutils(`printenv`, `env`), awk 를 쓴다. 채점은 `sh -c`, 풀이는 `bash`. 네트워크·`sleep` 없음.
- 객관식 정답은 보기 첫 번째로 적고 도우미가 섞는다. 보기 길이를 비슷하게 맞췄고 해설은 보기와 모순되지 않는다. 빈칸 칩(`:-` `:=` `:+` `:?`)은 출력이 `guest` / `[]` 두 줄이어야 해서 `:-` 만 정답이다(`:=` 는 둘째 줄이 `[guest]`).
- 순서 문제는 "전 상태 확인 → 파일에 적기 → source → 후 상태 확인" 으로 순서가 하나다.
- 가상 데이터만 쓰고 IP·도메인·회사·내부 시스템 이름은 없다. 힌트는 "어떻게 살펴보나" 만 말한다.
- 문서 링크: man7.org 의 `bash`·`env`·`printenv`·`environ(7)`·POSIX `export` (모두 200 확인). `alias` 는 쉘 내장이라 별도 man 페이지가 없어(404) `bash` 매뉴얼로 대신한다.

## 세트 구성 (12개, 세트 350)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | 변수를 만들고 자식 프로세스에 넘기기 | `export` vs 그냥 변수, `bash -c` | `plain.txt` = `[]`, `exported.txt` = `[two]` |
| 2 | 터미널 | 환경 변수 보기 | `printenv 이름`, `env \| grep` | `value.txt`, `env_line.txt` |
| 3 | 터미널 | 실습 폴더를 PATH 뒤에 붙여 이름만으로 실행하기 | `export PATH=$PATH:폴더` | 출력, PATH 맨 끝·`/usr/bin` 유지, 실행 기록 |
| 4 | 터미널 | 같은 이름이 두 곳에 있을 때: PATH 순서와 command -v | PATH 앞쪽 우선, `command -v` | `where.txt`, `ver.txt`, `path4.txt` 순서 |
| 5 | 터미널 | 명령 한 번에만 변수 주기 | `VAR=값 명령` | `once.txt` = `mode=[debug]`, `after.txt` = `mode=[]`, 실행 기록 |
| 6 | 객관식 | VAR=값 명령 과 export VAR=값 의 차이는? | 일회성 vs 이후 계속 | 정답: 한 번만 / 계속 |
| 7 | 터미널 | 변수 지우기 | `unset`, 종료 코드 | `before.txt`=`s3`, `after.txt` 빈 파일, `status.txt`=`1` |
| 8 | 빈칸 | 값이 없을 때만 기본값 쓰기 | `${NAME:-guest}` | 칸 1개 (`:-`) |
| 9 | 터미널 | 기본값이 있는 스크립트 만들기 | 스크립트에서 `:-` | `greet.sh` 3가지 입력 |
| 10 | 순서 | 설정 파일에 적고 적용하기 | 적기 → `source` → 확인 | 4조각 |
| 11 | 터미널 | 설정 파일에 환경 변수와 PATH 적기 | `>>`, `source` | 새 쉘에서 `LAB_COLOR`·PATH·기존 `LAB_LEVEL` |
| 12 | 터미널 | 별칭 추가하고 하나는 없애기 | `alias`, `unalias` | 새 쉘에서 `lt` 정의, `rm` 없음, `ll`·`cp` 유지 |

- 빈칸·순서·객관식은 터미널이 필요 없어 터미널 창이 보이지 않는다.
