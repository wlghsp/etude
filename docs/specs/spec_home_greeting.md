# 명세 — 홈 인사 문구 (마지막 학습을 기억하는 응원)

> 상태: **초안** (2026-11-12). 근거: 사용자 제안("오랜만에 오면 오랜만이에요 지호님, 매일 하고 있으면 아주 좋아요 같은 문구"). 재미·성취감 요소 전체는 아직 고민 중이라, 이번에는 **홈 맨 위 인사 문구**만 다룬다.

## 목표

홈의 "다음 세트" 카드 맨 위 한 줄(지금은 "오늘은 이거 해 볼까요? 🙂" 고정)을 **마지막 학습 시점과 연속 학습일에 맞춰 바꿔** 돌아온 사람을 반기고 꾸준히 하는 사람을 응원한다.

## 원칙

- **응원만 한다.** 쉬었다고 죄책감·압박을 주는 문구("며칠째 안 하고 계세요")는 쓰지 않는다.
- **새 데이터를 만들지 않는다.** 마지막 학습 시점은 홈이 이미 가진 완료 기록(`completedAt`)에서, 연속 학습일은 서버 값(`streak`)에서 쓴다. 서버·DB 변경 없음. 규칙(연속 계산, XP)은 바꾸지 않는다.
- **문구 선택은 순수 함수**로 분리한다(`frontend/src/greeting.ts`). 입력은 값만 받고 화면·시계를 직접 읽지 않는다(현재 시각은 인자로 받는다). 화면은 결과 문자열만 그린다.
- 하루의 경계는 사용자 브라우저의 **로컬 날짜**다. 완료 시각과 현재 시각을 로컬 날짜로 바꿔 달력 날짜 차이로 센다(24시간 단위로 세지 않는다).
- 다음 세트 카드의 다른 요소(세트 이름, 설명, 시작 버튼, 첫 완료 XP)는 그대로다. 문구 한 줄만 바뀐다.

## 입력과 문구

입력: `lastAt`(마지막 세트 완료 시각, 없을 수 있음), `streak`, `completed`(완료한 세트 수), `lastSetTitle`(마지막 완료 세트 이름, 없을 수 있음), `now`.

`daysAway` = 로컬 달력 날짜 기준으로 `now` 와 `lastAt` 사이의 일수.

위에서부터 처음 맞는 규칙을 쓴다.

| # | 조건 | 문구 |
|---|---|---|
| 1 | `completed === 0` 또는 `lastAt` 없음 | 첫 세트를 시작해 볼까요? 🙂 |
| 2 | `daysAway === 0` 그리고 `streak` 가 7의 배수이고 7 이상 | 🎉 {streak}일째 매일 하고 있어요, 대단해요! |
| 3 | `daysAway === 0` 그리고 `streak ≥ 2` | 오늘도 해냈네요! 연속 {streak}일째예요 🔥 |
| 4 | `daysAway === 0` | 오늘 한 세트를 끝냈어요. 하나 더 해 볼까요? 🙂 |
| 5 | `daysAway === 1` 그리고 `streak ≥ 2` | 어제에 이어 오늘도 해 볼까요? 연속 {streak}일을 이어 가요 🔥 |
| 6 | `daysAway === 1` | 어제 이어서 오늘도 해 볼까요? 🙂 |
| 7 | `2 ≤ daysAway ≤ 13` | 오랜만이에요! 지난번엔 "{lastSetTitle}" 를 했어요. 오늘은 이거 해 볼까요? 🙂 (`lastSetTitle` 없으면 앞 문장 생략) |
| 8 | `daysAway ≥ 14` | 다시 와 주셔서 반가워요. 가볍게 한 세트부터 시작해요 🙂 |

- 호칭: 사용자 이름은 맨 위 띠("안녕하세요, {이름}님 👋")에 이미 있다. 문구에는 이름을 다시 넣지 않는다.
- `lastSetTitle` 은 길 수 있어 화면에서 한 줄로 줄여 보인다(말줄임).
- `daysAway < 0`(시계 오차)은 0으로 본다.
- 규칙 2·3·4 는 "오늘 이미 끝냈다"는 뜻이라 다음 세트를 권하는 문장이 이어진다. 시작 버튼 문구("이어서 하기")는 지금과 같다.

## 구현 범위

1. `frontend/src/greeting.ts`: 위 표를 구현한 순수 함수 `homeGreeting(input): string`.
2. `SetSelect.tsx`: 완료 기록에서 구한 `latest.at` 을 `stats` 에 `lastAt` 으로 담고, `lastSetId` 로 `sets` 에서 이름을 찾아 함수에 넘겨 기존 고정 문구 자리에 쓴다. 다른 줄은 건드리지 않는다.
3. 테스트: 표의 각 줄과 경계(자정 전후, `daysAway` 1·2·13·14, `streak` 7·14, `lastSetTitle` 없음, 시계 오차)를 순수 함수 단위로 확인한다.

## 하지 않는 것

- 서버·DB 변경, 알림·이메일, 푸시.
- 레벨업·배지·축하 효과 같은 다른 재미 요소(별도 고민 중).
- 문구를 사용자별로 설정하는 기능, 다국어.
- 쉼 기간에 따른 경고·연속 기록 끊김 안내.

## 수용 조건

- [ ] 표의 8개 규칙마다 입력에 대응하는 문구가 나온다(테스트).
- [ ] 자정 직전·직후 완료도 달력 날짜 기준으로 `daysAway` 가 맞다(테스트).
- [ ] 완료 기록이 없는 신규 사용자는 지금과 같은 "첫 세트를 시작해 볼까요? 🙂" 가 나온다.
- [ ] 홈에서 세트 이름이 길어도 한 줄로 줄어 레이아웃이 깨지지 않는다 (화면 수동 확인).
- [ ] 다음 세트 카드의 나머지 요소와 동작이 이전과 같다 (화면 수동 확인).
- [ ] `npm run build`(프론트) 통과.

## 구현 순서

1. 이 명세 확인.
2. `homeGreeting` 테스트 작성 → 실패(RED) 확인 → 구현 → 통과(GREEN).
3. `SetSelect.tsx` 연결, 프론트 빌드 확인.
4. 화면 확인은 사용자가 한다.

## 열린 결정

| 결정 | 기본안 |
|---|---|
| 프론트에 테스트 도구 추가 | `frontend/node_modules/.bin/vitest` 가 이미 있다. `package.json` 에 `test` 스크립트만 추가하는 안을 기본으로 하되, 의존성 목록이 바뀌면 사용자에게 먼저 알린다 |
| 7일 단위 칭찬 | 7의 배수(7·14·21…)마다 규칙 2. 30일·100일 같은 별도 마일스톤은 이후 재미 요소 논의에서 정한다 |
