# 명세 — 리눅스 프로세스 찾고 멈추기 세트 (ps · pgrep · ss -ltnp · kill · pkill)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 세트 229. 근거: "무엇이 돌고 있나 → 누구를 멈출까 → 어떻게 멈출까"는 장애 때마다 반복되는 일이다. 기존에는 세트 3·16·85·173 에 `ps`·`kill`·`nohup` 문제가 하나씩 흩어져 있고, 세트 129·144·162·199·204·210·215 는 `kill` 신호·`ps` 옵션·`pgrep` 개념을 객관식·빈칸으로 묻는다. 이 흐름을 **살아 있는 프로세스를 직접 찾고 멈추는 실습 한 줄기**로 이어 주는 세트는 없다.

## 목표

서버에서 프로세스를 다루는 일을 순서대로 반복해 손버릇으로 만든다. `ps` 로 목록을 보고, `pgrep` 으로 PID 를 찾고, `ss -ltnp` 로 포트를 쥔 프로세스를 확인하고, `&` 와 `$!` 로 백그라운드 작업의 PID 를 기록한 뒤, `kill` → `kill -9` → `pkill` 로 종료한다. 쉬운 것부터 차례로 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1 (형식을 섞는 규칙). 터미널이 필요 없는 문제에서는 터미널 창이 보이지 않는다.
- setup 이 `/tmp/lab` 에 작은 셸 스크립트(`worker.sh`, `batch.sh` ×3, `stubborn.sh`, `hog.sh`)를 만들어 `setsid nohup` 으로 띄우고, `sleep 601` 과 `nc -l -p 8080` 도 띄운다. `setsid nohup` 이라 setup 의 `sh -c` 가 끝나도 살아남는다. 같은 컨테이너에서 setup·채점이 각각 별도 `exec` 로 실행돼도 프로세스가 유지된다.
- **PID 는 실행마다 달라진다.** 채점은 고정 숫자를 쓰지 않고 실제 상태와 비교한다 (`pgrep -x worker.sh` 의 현재 값과 파일 내용이 같은가, `ss` 출력에 `pid=$(pgrep -x nc)` 가 있는가).
- 이름 기준은 `pgrep -x` (정확한 이름). 채점 명령 자신이 `pgrep -f` 에 잡히지 않도록 `-f` 패턴은 `[s]leep 604` 꼴로 쓴다.
- "죽었는가" 판정은 좀비(`Z`)를 제외하고 `ps -eo stat=,comm=` 로 한다.
- 파괴적 동작은 setup 이 만든 `/tmp/lab` 스크립트와 `sleep` 에만 향한다. 다른 프로세스를 건드렸는지(과잉 종료)도 채점한다.
- 새 개념은 한 문제에 하나만. 객관식은 `$!` (기존 세트의 kill 신호·nohup 질문과 겹치지 않는 주제), `kill`·`kill -9` 는 실습으로 먼저 겪게 하고 빈칸·순서로 정리한다.
- 샌드박스는 `linux` (이미지 `etude-linux`, systemd 없음, root). 이미지에 `ps pgrep pidof pkill ss nc setsid nohup` 는 있고 `killall`·`lsof`·`python3` 는 없으므로 쓰지 않는다.

## 세트 구성 (12개, 세트 229)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | 실행 중인 프로세스 전체 목록 저장하기 | `ps -ef` | 제목에 UID·PPID, worker.sh·sleep 601 줄 |
| 2 | 터미널 | 이름으로 PID 찾기 (pgrep) | `pgrep -x 이름` | 파일 == 현재 worker.sh PID |
| 3 | 터미널 | PID 하나 자세히 보기 (ps -o) | `ps -o pid,ppid,etime,args -p` | 2줄, 열 순서, 첫 칸 == PID |
| 4 | 터미널 | 메모리를 가장 많이 쓰는 프로세스 | `ps aux --sort=-%mem \| head` | 2줄, 1등 hog.sh |
| 5 | 터미널 | 8080 포트를 쥔 프로세스 찾기 (ss -ltnp) | `ss -ltnp \| grep` | LISTEN :8080 줄에 nc 의 PID |
| 6 | 객관식 | 방금 띄운 백그라운드 작업의 PID | `$!` (`$$`·`$?` 와 구분) | 정답: 방금 띄운 프로세스의 PID |
| 7 | 터미널 | 백그라운드로 띄우고 PID 기록하기 | `&`, `$!`, `jobs` | 파일 == 살아 있는 sleep 604 의 PID |
| 8 | 터미널 | 프로세스 정상 종료하기 (kill) | `kill $(pgrep ...)` (SIGTERM) | worker.sh 종료, 나머지 생존 |
| 9 | 터미널 | kill 해도 안 죽는 프로세스 (kill -9) | `kill -9`, SIGTERM 무시 | stubborn.sh 종료, 나머지 생존 |
| 10 | 빈칸 | 강제 종료 신호 번호 | SIGKILL = 9 (칩 9·15·0·18) | 칸 1개 |
| 11 | 터미널 | 이름이 같은 프로세스 한꺼번에 종료 (pkill) | `pkill -x`, `pgrep -a` | batch.sh 3개 모두 종료, 나머지 생존 |
| 12 | 순서 | 프로세스를 안전하게 종료하는 순서 | 확인 → TERM → 확인 → KILL → 확인 | 5조각 |

- 객관식 정답은 보기 목록의 첫 번째로 적고, 도우미가 섞는다. 해설은 보기와 모순되지 않게 쓴다.
- 터미널 문제 setup 은 모두 같다 (재실행해도 안전: 먼저 같은 이름의 프로세스를 정리한다). 5번 `nc` 는 연결이 들어오면 끝나므로, 포트 점유는 한 번만 확인한다.
- 4번은 `hog.sh` 가 셸 변수에 약 40MB 를 쥐고 있어 RSS 1등이 되도록 만든다 (CPU 는 쓰지 않는다).
