# 명세 — 문제 풀이 타이머와 기록 (A 단계)

> 상태: **A 단계 구현 완료(로컬), 화면 확인 대기** (2026-10-29). B(내 기록), C(관리자 문제별 통계)는 후속.

## 배경

채점할 때마다 `quest_attempt`에 걸린 시간(`elapsed_sec`), 힌트·풀이 사용, 통과 여부가 쌓이지만 화면에는 보이지 않았다. 또 시간은 문제 화면을 연 순간부터 재서, 다른 문제로 갔다 오거나 새로고침하면 0부터 다시 셌다.

## A 단계 동작

- 문제 헤더(`n / 전체` 옆)에 경과 시간을 `mm:ss`(1시간 이상은 `h:mm:ss`)로 보여 준다.
- **탭이 보일 때만 센다** (딴 일을 하는 동안 시간이 부풀지 않게).
- (세션, 문제)별로 `localStorage`(`etude.questTimer.<sessionId>.<questId>`)에 저장해 **같은 세트 안에서 다른 문제로 갔다 오면 이어서 센다.** 세트에 들어올 때마다 새 `sessionId`와 새 터미널 환경이 만들어지므로, **나갔다 다시 들어오면 0부터** 센다 (이전에 한 작업이 사라진 환경에서 시간만 이어지는 것을 막는다). 이전 세션의 저장값은 자동으로 지운다. 저장이 막힌 환경에서는 그 화면 안에서만 센다.
- 채점 요청의 `elapsedSec`는 이 누적 시간을 보낸다 (기존 API 계약 그대로, 서버 변경 없음).
- 통과하면 멈추고 저장값을 지운다 (다시 풀 때는 0부터). 완료 박스에 "걸린 시간 1분 23초 · 힌트 사용 · 풀이 사용"을 보여 준다.
- 환경 초기화는 시간을 되돌리지 않는다.

## 알려진 한계

- 시간은 브라우저에서 재는 값이라 정확한 감사 기록이 아니다 (학습 통계 용도). 서버에서 기록하는 값은 채점 시점에 클라이언트가 보낸 누적 시간이다.
- 사용자가 브라우저 저장소를 지우면 누적이 초기화된다.
- 새로고침은 터미널을 다시 연결하므로 새 세션이 되어 시간이 0부터 다시 센다.

## 수용 조건

- [x] 시간 표시 함수가 경계값에서 맞다 (`00:05`, `01:05`, `59:59`, `1:02:05` 등 9개 값 확인) — `검증됨`
- [x] 타입 검사와 프론트 빌드 통과 — `검증됨`
- [ ] 화면에서 시간이 흐르고, 탭을 숨기면 멈추고, 다른 문제를 갔다 와도 이어지는지 확인 (`미검증`, 프론트에 자동 테스트 환경이 없어 브라우저 확인)
- [ ] 통과 시 걸린 시간과 힌트·풀이 사용이 보인다 (`미검증`)

## 후속

- **B:** 내 진행 현황에 문제별 걸린 시간·시도 횟수·힌트/풀이 사용 (API 하나 + 화면 하나).
- **C:** 관리자 화면에 문제별 통과율·평균 시간·힌트/풀이 사용률 (어려운 문제를 찾아 문구를 개선하기 위함).
- 리더보드에는 시간을 넣지 않는다 (힌트를 안 보려는 부담을 막기 위해).

## 세트 완료 화면 (2026-10-29 추가)

마지막 문제를 통과하면(또는 모든 문제를 완료하면) "결과 보기"가 나오고, 왼쪽 패널에 요약 화면이 열린다.

- **제목:** 모두 완료하면 "축하합니다!", 건너뛴 문제가 있으면 "수고하셨어요"(일부 완료 기준).
- **요약 카드:** 총 걸린 시간(문제당 평균), 힌트 없이 푼 개수, 풀이 안 보고 푼 개수.
- **문제별 기록:** 걸린 시간 막대와 "힌트 / 풀이 / n번 시도" 표시. 문제를 누르면 그 문제로 돌아간다.
- **복습하면 좋은 문제:** 풀이를 봤거나 3번 이상 시도한 문제.
- **버튼:** 홈으로. 모든 퀘스트를 완료한 뒤 다른 문제를 다시 보는 중에도 "모든 퀘스트 완료 · 결과 보기"로 돌아올 수 있다.
- 완료 화면의 문제별 기록은 이번 세션의 값(클라이언트 상태)이고, 세트 완료 기록은 서버가 확인해 저장한다 ([spec_progress_dashboard.md](spec_progress_dashboard.md)). 시도 횟수는 이번 화면에서 관찰한 채점 횟수다.
- 리더보드나 다른 사람과의 비교는 넣지 않는다.
