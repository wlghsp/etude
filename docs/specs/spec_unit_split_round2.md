# 명세 — 기초 단원 나누기 2차 (Git·리눅스·k8s)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-18). 근거: 사용자 지시 "git 기초도 너무 길다 분리가 필요", "각 분야의 기초들이 다 그렇네". 1차는 [spec_docker_unit_split.md](spec_docker_unit_split.md)(도커)다. 규칙은 같다: **단원은 10세트 안팎, 넘으면 나눈다.**

## 원칙

- 세트 내용·번호·완료 기록·XP 는 그대로다. 바뀌는 것은 `unit_id`, `display_order`(단원이 이어지도록 다시 매김), 새 `unit` 행뿐이다.
- 프론트는 같은 단원의 세트가 `display_order` 로 이어져 있다고 가정한다([units.ts](../../frontend/src/units.ts)). 그래서 분야의 기존 `display_order` 값 묶음을 그대로 쓰고, (단원 순서, 단원 안 기존 순서)로 다시 배정한다. 다른 분야·단원 밖 세트의 값은 변하지 않는다.
- 새 단원 id 는 49 부터. 단원 `display_order` 는 정수로, 기존 단원 사이에 끼운다.
- 이번 범위는 **공개 대상(리눅스·k8s)과 Git**. 도커 32·33, 네트워크 47, 가상화 48, 스토리지 21 도 10세트를 넘으므로 해당 분야를 열기 전에 같은 방식으로 나눈다 (미완).
