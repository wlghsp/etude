# 명세 — 리눅스 디스크 사용량 점검 세트 (df · du · sort -h · find -size)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 세트 226. 근거: 디스크 알람 때 "어디가 찼고, 무엇이 큰가"를 찾는 일은 현장에서 가장 자주 반복된다. 기존에는 세트 2·3·16·27·30·44·45·142·144 등에 `du`·`df`·`find -size` 문제가 하나씩 흩어져 있고(세트 129·32·219 는 df/du 차이 개념), 이 흐름을 한 번에 연속으로 손에 익히는 세트는 없다.

## 목표

디스크가 찼다는 알람을 받았을 때 하는 일을 순서대로 반복해 손버릇으로 만든다. `df` 로 어느 디스크인지 보고, `du` 로 큰 폴더를 좁히고, `sort -h`·`ls -lhS`·`find -size` 로 큰 파일을 찾고, 지우기 전후 크기를 비교한다. 쉬운 것부터 차례로 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1 (형식을 섞는 규칙). 터미널이 필요 없는 문제에서는 터미널 창이 보이지 않는다.
- 채점은 결과 파일(`/tmp/*.txt`)의 **내용**으로 한다. 크기 값이 결정적이도록 setup 이 `/tmp/lab` 아래에 크기가 정해진 파일을 `head -c` 로 만든다 (로그 15.5M, 데이터 25.5M, 미디어 33.5M, 작은 파일 300개). 디렉터리 항목이 4K 를 더해 `du -h` 가 올림하므로 일부러 `.5M` 로 맞춘다 (16M / 26M / 34M).
- 새 개념은 한 문제에 하나만. 앞 문제의 표현을 다음 문제가 한 칸씩 확장한다.
- 샌드박스는 `linux` (이미지 `etude-linux`, systemd 없음). 파괴적 명령은 `/tmp/lab` 안으로만 한정한다.
- 호스트 환경에 따라 달라지는 값(루트의 실제 사용량 등)은 형식(제목 줄, `%`, 마운트 지점)만 채점하고 수치는 채점하지 않는다.
- 기존 세트와 겹치는 단일 개념(df -h, du -sh, find -size)은 "한 줄 확인"이 아니라 **디스크가 찼을 때의 흐름 속 한 단계**로 다룬다.

## 세트 구성 (12개, 세트 226)

| # | 형식 | 제목 | 새로 익히는 것 |
|---|------|------|----------------|
| 1 | 터미널 | 디스크 전체 사용률 보기 | `df -h /` |
| 2 | 터미널 | inode 사용률 보기 | `df -i /` |
| 3 | 터미널 | 디렉터리 하나의 크기 | `du -sh 폴더` |
| 4 | 터미널 | 한 단계 아래만 펼쳐 보기 | `du -h --max-depth=1` |
| 5 | 터미널 | 폴더 안 파일을 큰 순서로 | `ls -lhS` |
| 6 | 빈칸 | 큰 순서로 정렬하기 | `--max-depth=1`, `sort -rh` (`-nr` 과의 차이) |
| 7 | 터미널 | 가장 큰 폴더 두 개 | `du -sh * \| sort -rh \| head` |
| 8 | 터미널 | 10MB 넘는 파일 찾기 | `find -type f -size +10M` |
| 9 | 터미널 | 가장 큰 파일 세 개 | `find -printf '%s %p\n' \| sort -rn \| head` |
| 10 | 객관식 | 지웠는데 용량이 안 줄 때 | df 와 du 의 차이 (열린 채 지워진 파일) |
| 11 | 터미널 | 지우기 전후 크기 비교 | 삭제 전후 `du -sh` 기록 |
| 12 | 순서 | 디스크가 찼을 때 찾는 순서 | df → du → find/ls → 정리 후 df |

- 객관식 정답은 보기 목록의 첫 번째로 적고, 도우미가 섞는다. 해설은 보기와 모순되지 않게 쓴다.
- 터미널 문제 setup 은 모두 같다 (`/tmp/lab/{logs,data,media,many}` 생성). 11번만 파일을 지운다.
