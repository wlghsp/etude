# 명세 — 리눅스 아카이브와 간단한 백업 직접 해 보기 세트 (tar · --exclude · gzip -k · cp -a · sha256sum · 날짜 이름 · 오래된 백업 정리)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 세트 338. 근거: 기존 세트 7(tar·zip·gzip 기본 사용), 10(압축 백업 1문제), 133·262·181·274(퀴즈 세트, 1/2·2/2 로 분리됨)는 명령을 **하나씩 따라 하거나 고르는** 수준이다. "묶기 → 목록 → 원하는 곳에 풀기 → 제외 → 보존 복사 → 체크섬 검증 → 날짜 이름 → 오래된 백업 정리" 를 **한 줄기로 잇고, 채점이 아카이브의 내용을 직접 열어 보는** 세트는 없다.

## 목표

작은 폴더로 백업의 한 사이클을 직접 해 본다. 문제마다 새 개념을 하나씩 붙인다: `tar czf` 와 `-C`, `tar tzf` 목록 보기, `tar xzf -C 폴더`, `--exclude`, 절대 경로의 `Removing leading /`, `gzip -k`, `zcat`, `cp -a`(권한·시각 보존)와 `cp -r` 의 차이, `sha256sum` 과 `-c`, 백업 순서(만들기 → 체크섬 → 복사 → 확인), `$(date +%F)` 날짜 이름, `ls -t | tail -n +4 | xargs rm` 으로 새 것 N개만 남기기. 쉬운 것부터 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1 (형식을 섞는 규칙).
- 채점은 **상태**를 본다: `tar tzf` 목록, `tar xzOf` 로 꺼낸 파일 내용, 풀린 파일, 체크섬, 권한·수정 시각, 남은 파일 이름. 명령 문자열이 아니라 결과를 본다. 날짜 이름은 **모양**(`data-YYYY-MM-DD.tar.gz`)만 보고 오늘 날짜인지는 보지 않는다.
- 겹침 점검: 세트 7(tar·zip 기본 10문제), 10(백업 1문제)과 가장 가깝다. 차별점은 `--exclude`, `-C` 로 경로 제어, `cp -a`, 체크섬 검증, 날짜 이름, 오래된 백업 정리다. 퀴즈 세트 133·181·262·274 는 고르기 위주라 겹치지 않는다. 데이터베이스·Redis 백업(109·118)은 대상이 다르다. 이미지 save·load(8·337)와도 다르다.
- 이미지(`etude-linux`)에 `tar`(GNU 1.34), `gzip`, `zcat`, `sha256sum`, `xargs`, `cp -a` 가 있다. `zip`·`unzip` 도 있지만 세트 7 이 다루므로 이 세트는 쓰지 않는다. `root` 로 실행되며 systemd 가 없다.
- setup 은 `/tmp/lab`, `/tmp/restore`, `/tmp/*.txt`, `/tmp/*.gz`, `/tmp/*.tgz` 를 지우고 작은 데이터(`project/`, `data/`, `site.tar.gz`, `big.txt`, `server.log.gz`, `src/conf.sh`, `daily/` 5개)를 다시 만든다. 오래된 시각(`touch -d`)은 `src/conf.sh` 와 `daily/` 에만 쓴다. 몇 번 실행해도 같은 상태다.
- 채점 명령은 `sh -c` 로 돌므로 bash 전용 문법을 쓰지 않는다. 풀이는 `bash` 로 실행한다. 입력은 작고 결정적이다. 네트워크, `sleep`, 무한 반복이 없다.
- 객관식 정답은 보기 목록의 첫 번째로 적고, 도우미가 섞는다. 해설은 보기와 모순되지 않게 쓴다. 빈칸의 칩에는 정답이 둘 이상 되는 값이 없다 (`zcat` 만 정답).
- IP·도메인·회사·내부 시스템 이름을 쓰지 않는다. 힌트는 "어떻게 살펴보나" 만 말하고 답을 주지 않는다.

## 세트 구성 (12개, 세트 338)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | 디렉토리를 tar.gz 로 묶고 압축하기 (czf, -C) | `tar czf`, `-C` 로 앞 경로 떼기 | gzip 유효, `project/app.conf` 있음, `tmp/` 로 시작하는 경로 없음, 내용 일치 |
| 2 | 터미널 | 아카이브 안을 풀지 않고 목록만 보기 (tzf) | `tar tzf`, 출력 저장 | `/tmp/list.txt` 가 `tar tzf` 와 같음, 아무것도 풀리지 않음 |
| 3 | 터미널 | 원하는 폴더에 풀기 (xzf -C) | `tar xzf -C`, 풀 폴더는 미리 만든다 | `/tmp/restore/site/` 의 두 파일 내용, 현재 위치에 안 풀림 |
| 4 | 터미널 | 특정 폴더는 빼고 묶기 (--exclude) | `--exclude=logs`, 대상보다 앞에 | 3개 파일 포함, `logs` 없음 |
| 5 | 객관식 | tar 가 "Removing leading /" 라고 알릴 때 | 절대 경로를 상대 경로로 저장하는 이유 | 정답: 맨 앞 `/` 를 떼어 저장한다는 안내 |
| 6 | 터미널 | 원본을 남기고 gzip 으로 압축하기 (gzip -k) | `gzip -k` | `.gz` 유효, 원본 200줄 남음, 풀면 원본과 같음 |
| 7 | 빈칸 | 풀지 않고 압축된 로그 바로 읽기 | `zcat … \| grep -c` (칩 `zcat gunzip cat gzip`) | 칸 1개 |
| 8 | 터미널 | 권한과 수정 시각까지 그대로 복사하기 (cp -a) | `cp -a` 와 `cp -r` 의 차이 | `copy/conf.sh` 내용·권한 750·수정 시각이 원본과 같음 |
| 9 | 터미널 | 복사본이 같은지 체크섬으로 확인하기 (sha256sum) | `sha256sum 두 파일 > 기록`, `-c` | `report.bak` 일치, 두 줄, 해시 동일·실제 값, `sha256sum -c` 통과 |
| 10 | 순서 | 백업 파일을 안전하게 보관하는 순서 | 만들기 → 체크섬 기록 → 복사 → `-c` 확인 | 4조각 |
| 11 | 터미널 | 날짜가 들어간 백업 이름 만들기 ($(date +%F)) | `$(date +%F)` 로 이름 만들기 | `data-YYYY-MM-DD.tar.gz` 1개(날짜 값은 안 봄), 안에 `data/a.txt`·`data/report.csv`, `tmp/` 없음 |
| 12 | 터미널 | 가장 새 백업 3개만 남기고 지우기 (ls -t \| tail \| xargs rm) | `ls -t \| tail -n +4 \| xargs rm` | `daily/` 에 정확히 3개, 01-03·01-04·01-05 |

- 빈칸·순서·객관식은 터미널이 필요 없어 터미널 창이 보이지 않는다.
- 이름순 `ls | tail -n +4` 로 지우면 가장 새 파일이 지워져 12번 채점이 실패한다.
