# 명세 — 세트 완료 기록과 내 진행현황

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-29). 방향 결정: **기록의 단위는 "세트 완료"** 이고, 문제 단위의 체크·진행률·이어서 풀기·문제로 바로 입장은 두지 않는다 (사용자 결정).

## 원칙

- 학습의 단위는 세트다. 세트에 들어오면 처음부터 풀고, 이미 푼 문제를 다시 푸는 것도 반복 학습이다.
- **사용자에게 보이는 기록은 세트 완료뿐**이다. 문제별 채점 기록(`quest_attempt`)은 계속 수집하지만(관리자용 문제별 통계의 원천) 사용자 화면의 기능으로 내보내지 않는다. 완료 기록 안에 문제별 내역을 읽기 전용으로 두는 것은 허용한다.
- 리더보드나 다른 사람과의 시간 비교는 두지 않는다.

## 세트 완료의 정의

**한 번 입장한 세션에서 그 세트의 모든 퀘스트를 통과**하면 1건. 여러 날에 나눠 푼 누적은 완료로 인정하지 않는다.

## 서버

- 테이블 `set_completion`: `user_id, quest_set_id, session_id, completed_at, quest_count, total_seconds, hint_free_count, solution_free_count, detail(JSON)`. `(user_id, quest_set_id, session_id)` 고유. 외래 키는 두지 않는다 (기존 테이블 `id` 타입이 INT/BIGINT로 환경마다 달라 맞추기 어렵고, 이 값은 서버가 검증한 뒤에만 쓴다).
- `POST /quest-sets/:id/complete` `{ sessionId }`: 접근 권한을 확인하고, **서버가 `quest_attempt`에서 그 세션의 모든 퀘스트가 통과인지 직접 확인**한 뒤에만 저장한다. 부족하면 409, 잘못된 요청은 400, 같은 세션의 중복은 한 번만 저장된다 (`INSERT IGNORE`).
- 문제별 `detail`: 통과한 시도 중 가장 짧은 시간과 그 시도의 힌트·풀이 사용, 그 세션의 시도 횟수.
- `GET /progress`: 볼 수 있는 세트(공개 / 관리자 / 접근 권한)별 완료 기록 목록(최근 순)을 돌려준다.
- `GET /leaderboard`: **완료한 세트 수**로 순위를 매긴다 (같은 세트를 여러 번 완료해도 1번).
- 이전: `quest_attempt`에서 세트의 모든 퀘스트를 한 번이라도 통과한 (사용자, 세트)는 1번 완료한 것으로 옮긴다 (`session_id='backfill'`, 문제별 내역 없음, 시간·힌트·풀이는 문제별 최단 통과 기록 기준).

## 화면

- **홈 세트 카드:** 진행 막대 대신 "✓ 완료 · n회" / "미완료".
- **세트 완료 화면(`SetComplete`):** 마지막 문제 통과 시 열리고, 완료 기록 저장 상태("저장 중 / 저장됨 / 실패 → 다시 저장")를 보여 준다. 저장은 모든 퀘스트를 통과하는 순간 한 번 요청한다.
- **내 진행현황:** 완료한 세트 수(/전체), 총 완료 횟수, 총 학습 시간, 이번 주 완료 + 분야 필터(전체/분야별/미완료) + 세트 목록("완료 n회 · 최근 날짜 · 최단 시간"). 세트를 펼치면 완료 기록 목록(날짜, 총 시간, 힌트·풀이 없이 푼 개수)이 나오고, 기록을 펼치면 문제별 내역(시간·힌트·풀이·시도 횟수)이 읽기 전용으로 보인다.
- **리더보드:** 팀원별 "완료한 세트 n/전체", 펼치면 세트별 완료/미완료.

## 알려진 한계

- 타이머 배포 이전의 걸린 시간은 부정확하다 ("문제를 연 순간부터"). 이전된 기록의 시간은 참고용이다.
- 완료 기록 저장이 실패하면(네트워크 등) 완료 화면에서 다시 저장할 수 있다. 화면을 닫으면 그 세션의 기록은 남지 않는다.
- 같은 세션 안에서 일부 문제를 건너뛰고 끝내면 완료가 아니다 (기록 저장 안 됨, 완료 화면은 "수고하셨어요").

## 다시 풀기 추천 (세트 단위, 2026-10-30)

- `GET /progress` 의 각 세트에 `retry: { assistedPct } | null` 을 더한다 (`retryHint`). **가장 최근 완료**에서 힌트나 풀이를 쓴 문제가 40% 이상이면 값이 있고(많이 쓴 쪽 기준, 힌트·풀이가 겹칠 수 있어 최소치), 아니면 null. 다시 풀어 도움이 줄면 더 추천하지 않는다.
- 홈 상단 패널 아래에 "💪 퍼펙트에 도전해 볼까요?" 카드: 도움을 가장 많이 쓴 세트 최대 3개, 누르면 그 세트로 들어간다. **본인에게만** 보이고 다른 사람에게 드러나지 않으며, 말투는 칭찬·도전 중심이다.
- 문제 단위 오답 노트는 만들지 않는다 (세트 단위 기록 원칙). 검증: `progress.test.ts` 의 `retryHint` 3개 포함 백엔드 271개 통과, 프론트 타입 검사·빌드. 화면은 미확인.

## 오늘의 목표와 이달의 도전 (2026-10-30)

듀오링고의 일일·월간 퀘스트를 참고한다. ("퀘스트"는 이 앱에서 문제를 뜻해서 이름은 **목표**와 **도전**으로 쓴다.) 작은 목표를 끝낼 때마다 성취감을 주고 매일 들어오는 습관을 만든다. 새 테이블은 없고 `set_completion` 에서 계산한다.

### 목표
| 구분 | 목표 | 달성 기준 |
|---|---|---|
| 오늘 | 세트 1개 끝내기 | 오늘 완료한 세트 1개 이상 |
| 오늘 | 문제 10개 풀기 | 오늘 완료한 세트의 문제 수 합계 10개 이상 |
| 오늘 | 복습 1개 | 이미 끝낸 적이 있는 세트를 오늘 다시 끝냄 (완료한 세트가 하나라도 있는 사람에게만 보인다) |
| 이달 | 세트 10개 끝내기 | 이번 달 완료 횟수(복습 포함) 10회 이상 |

- 날짜와 달은 DB 기준(`CURDATE()`)이다. 오늘은 자정에, 이달은 말일 자정에 새로 시작한다.
- 못 채워도 어떤 나쁜 표시도 하지 않는다. 남은 시간은 "오늘 N시간 남았어요"처럼 부드럽게만 알린다. 본인에게만 보인다.
- 목표 달성 보상은 시각 연출(진행 막대가 채워지고 보상 상자가 열림)이다. XP 를 더 주지는 않는다 (XP 규칙을 한 곳에 두기 위해).
- 이달의 도전을 이루면 소식에 "이달의 도전을 완료했어요!" 축하가 오른다 (`feed-cheers`).

### API
- `GET /goals` → `{ today: { goals: [{ key, title, current, target, done }], hoursLeft }, month: { label, current, target, done, daysLeft } }`.
- 서버 `services/goals.ts`: `buildGoals`(순수 계산) + `getGoals`(DB 조회).

### 화면
- 홈 상단 패널 아래 "오늘의 목표" 카드: 목표마다 진행 막대(숫자 `3 / 10` 이 막대 안 가운데), 달성하면 막대가 초록·상자가 🎁 로 열림. 위에 "이달의 도전" 막대와 남은 일수.

## 복습 허브 (2026-10-30)

듀오링고의 "오늘의 복습"을 참고한 사이드바 메뉴 **복습**(`pages/Review.tsx`). 복습할 곳이 한 군데에 모이고, 시작 버튼에 얻을 수 있는 XP 를 보인다. 세트 단위이며 본인에게만 보인다.

- `GET /review` → `{ pick, retry, reviewSets, stale }` (`services/review.ts` 의 `buildReview`).
  - `retry`: 다시 풀기 추천 세트 (`retryHint` 있는 세트, 도움을 많이 쓴 순). 
  - `reviewSets`: 아직 안 푼 복습 세트(`is_review`).
  - `stale`: 마지막으로 끝낸 지 14일 이상 지난 세트 (오래된 순, 5개까지, `retry` 와 겹치지 않게).
  - `pick`: 오늘의 추천 1개 = `retry[0]` → `reviewSets[0]` → `stale[0]` 순서로 첫 번째. 없으면 null.
- 항목: `{ questSetId, title, category, reason, gainXp }`. `gainXp` 는 이 세트를 퍼펙트로 다시 끝낼 때 늘어나는 XP (복습 보너스 5 XP, 한 번도 퍼펙트가 없었다면 퍼펙트 보너스 문제 수×5). 안 푼 복습 세트는 문제 수를 몰라 null.
- 화면: 위에 오늘의 추천 카드("시작 +N XP"), 아래에 "다시 풀기", "복습 세트", "오랜만에" 목록. 홈의 "퍼펙트에 도전" 카드에는 "모두 보기 →" 로 이 화면으로 이어진다.

## XP·레벨·배지의 기준 (2026-10-30)

- 규칙은 서버 한 곳(`services/xp.ts`, `services/gamification.ts`)이다. `GET /gamification` → `{ xp, level, streak, badges }`. 홈 상단 패널(레벨·연속 학습일)과 내 진행현황(배지)은 이 값을 그대로 보여 주고, 프론트에는 계산 코드가 없다 (이전의 `frontend/src/gamification.ts` 삭제).
- 단원·분야 정복은 **공개 세트** 기준이다 (예전에는 화면에 보이는 세트 기준이라 관리자 계정에서 다를 수 있었다). 연속 학습일은 DB 날짜 기준이다.
- 소식 축하(`feed-cheers`)와 주간 XP 순위가 같은 규칙을 쓴다.
