# 명세 — 세트 표시 순서

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-29)

## 배경과 목적

세트 목록이 만든 순서(id)로 보여서 배움의 순서와 맞지 않았다 (예: 리눅스 "성능·NFS" 가 "압축"·"Vim" 앞에 옴). 분야 안에서 **쉬운 것에서 어려운 것으로** 보이게 한다.

## 원칙

- 세트 id 는 완료 기록(`set_completion`) 등이 참조하므로 **바꾸지 않는다.** 표시 순서는 별도 열로 둔다.
- 순서의 기준은 DB 한 곳(`quest_set.display_order`)이다. 프론트에 순서 표를 두지 않는다.
- **원리·개념 세트는 관련 실습 세트 뒤에** 둔다. 실습만 하면 놓치기 쉬운 것을 짚는 목적이라, 실습 전에 읽으면 외우기가 되기 쉽다.
- 앞 세트가 뒤 세트의 전제가 되게 한다 (입문 → 중급 → 고급).

## 데이터

- `quest_set.display_order INT NOT NULL DEFAULT 0` 을 추가한다. 작을수록 먼저 보인다. 같으면 id 순이다.
- 값은 10 단위로 준다 (사이에 세트를 끼워 넣을 수 있게).
- 목록 조회(홈, 관리자, 진행현황)는 모두 `ORDER BY display_order, id` 이다. 홈의 분야 묶음 순서는 첫 번째로 나온 세트가 정하므로 리눅스 → 도커 → k8s 순이다.
- 초기화는 `05_display_order.sql`, 이미 있는 DB 는 `migrations/2026-10-29_set_display_order.sql` (`ADD COLUMN IF NOT EXISTS` 와 같은 UPDATE).

## 현재 순서 (세트 id)

- **리눅스:** 1, 2, 3, 21, 9, 7 (입문) → 15, 30, 17, 4, 18, 24, 10 (중급) → 16, 27, 32, 28 (고급, 28 은 종합 점검)
- **도커:** 5, 11, 8
- **k8s:** 6, 20, 33, 19, 12, 22, 13, 25, 26, 14, 23, 31, 29

새 세트를 추가할 때는 `05_display_order.sql` 과 새 마이그레이션에 순서를 함께 넣는다.

## 검증

- `검증됨`: 새 초기화 경로(`00`~`03`, `05`)와 `check-migrations.sh`(이전 배포 상태에서 마이그레이션 적용)가 통과, 로컬 DB 에서 분야별 순서 확인, 백엔드 전체 테스트 191개 통과, 타입 검사 통과.
- `미검증`: 홈·진행현황 화면에서 순서가 보이는지.
- 후속 후보: 난이도 배지(입문·중급·고급). 순서만으로 흐름이 보이는지 확인한 뒤 결정한다.
