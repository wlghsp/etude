# 명세 — 문제 종류별 화면, 마지막 분야 기억, 푼 세트 표시

> 상태: **결정 완료(기본안 확정, 사용자 위임), 구현 완료(로컬), 화면 확인 대기** (2026-11-11). 근거: 배포 서버 피드백 #2(터미널 필요 없는 문제에 터미널이 보임), #10(풀던 분야가 먼저 안 보임), #11(푼 세트 표시가 마음에 들지 않음).

## 1. 터미널이 필요 없는 문제에서는 터미널 창을 숨긴다 (#2)

### 현재
화면은 **세트**의 `sandbox_type` 이 `quiz` 인지로 레이아웃을 정한다 (`App.tsx` 의 `isQuiz`). 그래서 터미널 문제와 객관식·순서·빈칸 문제가 섞인 세트에서는 객관식을 풀 때도 터미널 창이 열려 있고, 컨테이너도 만들어진다. 해당 세트가 52개, 해당 문제가 296개다.

### 바꿀 것
레이아웃의 기준을 **지금 보고 있는 문제의 `kind`** 로 바꾼다.

- `kind` 가 `terminal` 이면 지금처럼 문제 + 터미널 2분할.
- `choice`·`order`·`fill` 이면 터미널 창을 그리지 않고 문제 패널을 한 칸으로 쓴다 (퀴즈 세트와 같은 모양). 컨테이너도 만들지 않는다.
- 세트 상단의 "개념 퀴즈 · 터미널 없이 푸는 문제예요" 배지는 지금처럼 세트가 `quiz` 일 때만 보인다 (문제 종류 기준이 아님).
- **`docker-persistent` 세트는 지금 방식을 유지한다.** 앞 문제에서 바꾼 컨테이너 상태가 이어지므로, 터미널 창을 닫으면 상태가 사라진다.
- 로딩 화면("실습 환경을 준비하고 있어요")은 터미널 문제로 넘어갈 때만 띄운다. 첫 문제가 객관식이면 띄우지 않는다.
- 터미널 문제로 돌아오면 그 문제용 새 컨테이너를 만든다 (지금도 문제마다 새 컨테이너다).

### 수용 조건 (화면 수동 확인)
- [ ] 터미널·객관식이 섞인 세트에서 객관식 문제에는 터미널 창이 없고 컨테이너가 만들어지지 않는다.
- [ ] 같은 세트에서 터미널 문제로 넘어가면 2분할과 새 컨테이너가 나온다.
- [ ] 퀴즈 세트·`docker-persistent` 세트는 지금과 같다.
- [ ] 터미널 문제에서 다음 터미널 문제로 넘어가면 준비 화면이 다시 나오고, 이전 컨테이너로 채점되지 않는다 (연결된 터미널이 지금 문제의 것일 때만 컨테이너 ID 를 쓴다).
- [ ] 이어 풀기로 들어와 첫 미완 문제가 객관식이어도 로딩 화면에서 멈추지 않는다.

## 2. 마지막에 풀던 분야를 먼저 보여준다 (#10)

### 현재
홈은 분야 탭을 `localStorage('etude.category')` 에 저장된 선택으로 고르고, 없으면 **마지막으로 "완료한"** 세트의 분야를 쓴다. 세트를 시작만 하고 완료하지 못했거나, 다른 분야 탭을 눌러 구경한 뒤에는 풀던 분야가 아니라 마지막으로 누른 탭이 열린다.

### 바꿀 것
**세트에 들어갈 때** 그 세트의 분야를 `etude.category` 로 저장한다. 홈은 지금 규칙(저장값 → 마지막 완료 분야 → 첫 분야) 그대로 쓰되, 저장값이 "마지막으로 푼 분야"가 되게 하는 것이다. 서버·DB 변경은 없다 (화면 한 곳).

### 수용 조건
- [ ] 분야 A 의 세트에 들어갔다가 홈으로 돌아오면 분야 A 탭이 열려 있다.
- [ ] 홈에서 다른 분야 탭을 눌러 보기만 한 뒤 새로고침해도, 마지막으로 푼 분야가 아니라 마지막으로 누른 탭이 유지된다 (구경은 푼 것이 아니므로 규칙 충돌 없음 — 확인 필요).

> 위 둘째 항목은 "구경 탭이 풀던 분야를 덮어쓰는가"에 대한 결정이다. 아래 결정 표 참고.

## 3. 푼 세트 표시 (#11)

피드백: "풀이한 세트를 표시하는게 생각보다 마음에 들지는 않음. 어떻게 나타내면 좋을지 고민해보자." 구체적으로 무엇이 별로인지는 적혀 있지 않다. 현재 표시(`SetPath`)를 바탕으로 방향만 정하고, 시안은 결정 뒤에 만든다.

| 안 | 내용 | 장단점 |
|----|------|--------|
| A | 단원 안에서 완료 세트를 접고, 다음 세트와 앞으로 할 세트만 보인다 (**채택**: 한 단원에서 3개 이상 끝내면 접고 "끝낸 N개 펼치기"로 펼친다. 단원 상자 진행도는 접힌 세트도 센다) | 목록이 짧아지고 "다음 할 것"이 눈에 띔. 완료한 것을 다시 찾으려면 펼쳐야 함 |
| B | 지금 경로 모양은 유지하고, 완료 표시를 색 변화가 아니라 체크 배지 + 별(만점)로만 단순하게 한다 | 변경이 작음. 불만의 원인이 모양이 아니라 위치·크기라면 해결 안 됨 |
| C | 단원 헤더에 진행 막대(예: 3/12)를 두고, 세트 카드는 완료·미완료 두 가지 상태만 구분한다 | 단원 단위 성취가 보임. 단원이 길면 여전히 길다 |

## 결정이 필요한 것

| 결정 | 기본안 |
|------|--------|
| 터미널 숨김의 기준 | 문제 `kind` (세트 종류 아님), `docker-persistent` 제외 |
| 분야 탭: 구경 탭이 풀던 분야를 덮어쓰는가 | 세트에 들어갈 때만 저장한다. 탭을 눌러 구경하는 것은 저장하지 않는다 (지금은 탭 클릭도 저장하므로 이 부분이 동작 변경) |
| 푼 세트 표시 | A (완료 세트 접기). 불편한 점을 알려 주시면 이후 조정한다 |

## 구현 순서

1. (결정 후) §1 화면: 문제 `kind` 기준 레이아웃, 로딩 조건.
2. §2 화면: 세트 진입 시 분야 저장, 탭 클릭 저장 제거.
3. §3: 안이 정해지면 `SetPath` 시안과 구현.
