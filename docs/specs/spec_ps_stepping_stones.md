# 명세 — ps 징검다리 (프로세스 문제의 선수 지식 채우기)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30)

## 배경과 목적

세트 16의 CPU 문제와 세트 27의 메모리 문제가 `ps -eo`(열 고르기), `--sort`(정렬), `sed`, `awk` 를 한꺼번에 요구했다. 그런데 `ps` 는 세트 3 에서 `ps aux` 두 문제로만 가르쳤고 `-eo`·`--sort` 는 한 번도 가르치지 않았다. "찾는 것이 목적인데 뽑는 도구가 장벽"이 되었다는 피드백이 있었다.

## 원칙

- 새로운 옵션은 **쓰기 전에 먼저 가르친다** (선수 지식 사슬을 확인한다).
- 목적이 "값을 뽑기"가 아닌 문제는 학습자가 **정렬한 출력을 저장**하고, 값 추출은 채점이 한다.
- `sed`/`awk` 는 세트 15 에서 배우는 도구다. 그 앞의 세트는 이 도구를 필수로 요구하지 않는다.

## 변경

- **세트 3** 끝에 문제 3개 추가 (기존 번호는 그대로, 완료 기록 영향 없음):
  - 9. `ps -eo pid,rss,args` 로 필요한 열만 골라 저장 (채점: 제목 줄이 `PID RSS COMMAND`)
  - 10. `--sort=-rss` 로 메모리 큰 순서 정렬해 저장 (채점: 2번째 줄이 실제 1등 PID)
  - 11. `pkill` 로 이름이 같은 프로세스 한꺼번에 종료 (채점: 해당 이름의 프로세스 없음). `killall` 은 이미지에 없고 `pkill` 이 같은 역할이다.
- **세트 16 #4**: PID 뽑기 → `--sort=-pcpu` 정렬 결과 저장 (채점이 2번째 줄 PID 를 확인).
- **세트 27 #1**: PID 뽑기 → 정렬 후 `head -n 4` 로 상위 3개만 저장 (`head` 는 앞 세트에서 이미 배운다).
- `top` 은 세트 27 #5 에 이미 있어 추가하지 않았다.

## 검증

- `검증됨`: `npm run verify:quests -- --set 3,16,27` 36문제 모두 통과 (정답은 통과, setup 만으로는 통과하지 않음). `check-migrations.sh`(이전 배포 상태에서 적용)와 새 초기화 경로(임시 DB) 통과.
- `미검증`: 화면에서 문제를 푸는 흐름, 운영 컨테이너에서의 동작.
- 세트 16·27 은 이미 운영에 있어 `UPDATE` 마이그레이션(`2026-10-30_ps_stepping_stones.sql`)으로 반영한다. 정답 문구가 바뀌어 이미 푼 학습자의 완료 기록(`set_completion`)에는 영향이 없다.
