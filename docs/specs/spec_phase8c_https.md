# Phase 8c 명세 — 도메인 + HTTPS 전환 + 보안 점검

## 목표

지금까지 `http://{공인IP}`로 서비스 중인 Etude를 도메인 기반 HTTPS로 전환한다. 로그인 시 비밀번호가 평문으로 오가는 문제를 해결하고, 팀원이 접속할 주소를 IP가 아닌 도메인으로 안정화한다. 동시에 인터넷에 공개된 서버 전반의 보안 상태를 점검한다.

배경: Phase 8 실제 배포 중 `docs/ops/guide_user_management.md`에 관리자 비밀번호가 실수로 커밋된 사고가 있었음(비밀번호는 즉시 재발급, git 히스토리는 무효화된 값이라 정리하지 않기로 결정 — [session-log](../session-log/2026-07-02.md) 참고). 이 사고를 계기로 "서버가 털릴 수 있는가"에 대한 점검 필요성이 제기됨.

---

## 범위 A — 도메인 + HTTPS

### 구성

- 신규 도메인 구매 (사용자가 직접 진행, 등록기관 임의)
- Cloudflare에 도메인 연결 (네임서버 변경)
- Cloudflare DNS에서 A 레코드로 서버 공인 IP(`161.33.45.200`) 연결
- 서버에 Let's Encrypt(certbot)로 무료 SSL 인증서 발급
- `nginx.conf`에 443 포트 HTTPS 설정 추가, 80 포트는 443으로 리다이렉트
- Terraform 보안 그룹에 443 포트 인바운드 규칙 추가

### 프론트/백엔드 코드 영향

`frontend/.env.production`의 `VITE_API_BASE`/`VITE_WS_BASE`가 이미 빈 값(same-origin 기준)이라 프로토콜이 하드코딩되어 있지 않다. 도메인+HTTPS 전환은 인프라(nginx, DNS, 인증서) 변경만으로 충분하며, 프론트/백엔드 코드 변경은 불필요.

### 인증서 갱신

Let's Encrypt 인증서는 90일마다 만료된다. certbot의 자동 갱신(cron 또는 systemd timer)을 설정해 사람이 개입하지 않아도 되게 한다.

## 범위 B — 서버 보안 점검

Phase 8c 배경에 있는 사고(비밀번호 실수 커밋)를 계기로, 인터넷에 공개된 서버가 실제로 공격받을 수 있는 경로를 점검한다.

### 점검 항목

| 항목 | 확인할 것 |
|------|-----------|
| SSH | 비밀번호 로그인 비활성화 여부(키 인증만 허용), 기본 22번 포트 노출 범위, `fail2ban` 등 무차별 대입 방어 |
| 방화벽 | Terraform 보안 그룹이 실제로 필요한 포트(22, 80, 443)만 여는지, 3306(DB)이 외부에 안 열려있는지 재확인 |
| 자동 업데이트 | 서버 OS/패키지 보안 업데이트 자동 적용 여부 |
| 자격증명 노출 | `.env.prod`, `terraform.tfvars` 등 비밀 파일이 실제로 git에서 제외되고 있는지 재확인, 서버 로그에 비밀번호가 평문으로 남는지 점검 |
| Docker 소켓 | `/var/run/docker.sock`을 backend 컨테이너에 마운트하고 있는데(샌드박스 제어용), 이 컨테이너가 뚫리면 호스트 전체 권한을 갖게 되는 구조적 위험 — 완화 방안 검토 |
| 애플리케이션 레벨 | JWT_SECRET 강도, bcrypt 라운드 수, 로그인 rate limit 여부 |

### 범위 밖

- 침투 테스트(모의 해킹) 등 능동적 보안 감사 — 이 Phase는 설정 점검 수준에 한정
- WAF(웹 방화벽) 도입 — 향후 필요시 별도 검토

## 검증 기준

- [ ] `https://{도메인}`으로 접속 시 인증서 경고 없이 정상 로드
- [ ] `http://{도메인}` 접속 시 자동으로 `https://`로 리다이렉트
- [ ] `http://{공인IP}` 직접 접속도 계속 동작하는지, 혹은 도메인으로만 제한할지 결정 후 반영
- [ ] Let's Encrypt 인증서 자동 갱신 설정 확인 (`certbot renew --dry-run`)
- [ ] 보안 점검 항목 표의 각 행을 점검하고 결과를 문서화
- [ ] SSH 비밀번호 로그인이 비활성화되어 있는지 확인
- [ ] 3306(DB) 포트가 `127.0.0.1`에만 바인딩되어 외부에 노출되지 않는지 재확인
