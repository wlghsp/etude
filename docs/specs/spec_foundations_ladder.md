# 명세 — 촘촘한 기본기 사다리 (선수 지식 먼저, 하나씩 쌓기)

> 상태: **진행 중** (2026-10-30). 계기: "`2>&1`, `|`, `&&` 같은 기본을 모르고 리눅스를 하는 경우가 많다. `find` 는 아직 어렵다. 문제를 풀려면 사전에 먼저 배워야 하는 것이 채워지는 세트와 퀘스트 구조로 가자."

## 분석 결과 (2026-10-30, 리눅스 터미널 문제 184개)

- **가르치는 문제가 문법마다 딱 1개**이고 이후 6~32번 다시 쓰인다. 파이프(`|`)는 세트 34 #1 에서 가르치고 32개 문제가 쓴다. `2>&1` 은 세트 34 #6 에서 가르치지만 **세트 3 #12 가 먼저 쓴다.** `&&` 도 세트 1 #2·#11 이 먼저 쓴다.
- **`find` 를 쓰는 문제는 5개뿐**이다. `-name` 3개, `-type`·`-exec`(세트 16 #1)·`-mtime`·`-delete`(세트 16 #3)는 1개씩이고, `-size`, `-maxdepth`, `-perm`, `-o`, `!`, `xargs` 와의 조합은 연습이 없다.
- `grep` 은 21개 문제가 쓰지만 `-r`, `-w`, `-A/-B/-C` 는 연습이 없다.
- 결론: 문제는 "순서"보다 **깊이와 반복**이다. 한 번 맛보고 끝나서 쓸 때마다 낯설다.

## 원칙

1. **선수 지식 먼저**: 어떤 문법·명령을 처음 쓰는 문제 앞에, 그것을 가르치는 문제(또는 개념 세트)가 있어야 한다. 처음 쓰이는 문제의 힌트에서 최소 한 줄 설명은 유지한다 (기존 규칙).
2. **개념 → 하나씩 쌓기 → 조합 종합**: 한 세트는 (가) 가벼운 개념 문제(구조 이해, 순서 맞추기, 빈칸) → (나) 옵션 하나씩 실습(작게 쪼갬) → (다) 여러 개를 합친 조건형 종합 문제로 끝난다.
3. **반복**: 가르친 문법은 이후 단원에서 다시 만나게 하고, 주요 문법마다 "다시 보기" 문제를 둔다 (복습 세트의 재료).
4. **형식 다양화**: 개념은 가벼운 형식(`spec_question_types.md`)으로, 실습은 터미널로, 종합은 조건형(`spec_grade_checks.md`)으로.
5. 문제를 하나 쓸 때는 `spec_quest_writing_guide.md`(옵션 설명 필수)를 따르고, 실습은 컨테이너로 검증한다 (`verify:quests`, 조건 포함).

## 방향 (사용자 확정, 2026-10-30)

1. **이해 없이 복사·붙여넣기 하는 습관을 깬다.** 대부분 리눅스 명령을 "그냥 치고", 무슨 뜻인지 모른 채 복사해서 붙인다. 그래서 명령을 **읽고 해부하는** 세트(명령·옵션·인자, 이 조각은 왜 들어갔나, 실행하면 무엇이 나오나)와 **복사 전에 확인하는 습관**(`--help`, `ls` 로 대상 확인, 위험 명령 알아보기)을 기본기로 둔다.
2. **모든 길은 k8s 로 이어진다.** 리눅스(경로·권한·프로세스·포트·이름 풀이·로그·쉘 문법) → 도커(이미지·컨테이너·포트·볼륨·Dockerfile/compose) → k8s(`kubectl` 구조, YAML, 라벨·셀렉터, 서비스, 설정·저장소). 각 단계가 다음 단계의 선수 지식이 되게 순서를 짠다.
3. **인프라 한계 안에서 최대한 제공한다.** 지금은 컨테이너·클러스터를 띄우는 실습을 마음껏 늘릴 수 없다. 그래서 k8s 쪽은 **클러스터 없이 가능한 것**을 먼저 풍성하게 한다: `kubectl` 명령 해부, YAML 읽기·빈칸·순서, `--dry-run=client -o yaml` 로 뼈대 만들기, 장애 상태 읽기. 공유 클러스터의 격리 네임스페이스에서 되는 실습은 기존대로 둔다.
4. **향후 개발 서버**를 제공하면, 사람마다 오래 쓰는 환경(영구 저장, 여러 컨테이너, 더 큰 권한)에서 더 깊은 실습(compose 로 서비스 띄우기, 직접 클러스터 다루기, 장애 재현)을 하는 구조로 확장한다. 그때를 위해 세트 설명에 "개발 서버에서 더 해 볼 것"을 적어 둘 수 있게 하고, 지금은 만들지 않는다. **개발 서버는 자원을 계속 차지하므로 중지/재시작(Stop/Start), 자동 유휴 종료, 남은 시간 표시가 필수**다 (KodeKloud 의 Stop Lab 에 해당). 지금의 일회성 샌드박스는 화면을 나가거나 탭을 닫으면 자동으로 정리되므로(소켓 종료 → 컨테이너 정리, 끊긴 연결은 하트비트가 정리) 별도 Stop Lab 버튼은 두지 않고, 나갈 때 안내 문구만 보강한다.

## 포지셔닝 (사용자 확정, 2026-10-30)

- Etude 는 **CKA 취득까지 책임지지 않는다** (지금 자원으로는 불가능). 대신 거기까지 가는 길에서 **익숙함과 경험**을 준다.
- KodeKloud 같은 곳은 기본기를 가르치며 진행하지 않는다. **기본기를 촘촘히 채우는 것이 Etude 의 차별점**이다.
- **공식 문서를 읽는 능력**도 가르친다 (KodeKloud 는 문제 위에 문서 링크를 둔다): 문제마다 참고 문서 링크(`quest.docs`), 그리고 `--help`/`man`/`kubectl explain` 으로 **명령을 스스로 완성**하는 문제(힌트는 정답이 아니라 "도움말에서 찾는 법"을 알려 준다).

## 이해 중심 세트 (이번 묶음)

- **세트 45 (리눅스) 명령어 해부하기 — 복사하기 전에 읽는 법**: 명령/옵션/인자 구분, `tar`·`ls`·`df` 옵션 읽기, 낯선 명령을 쓸 때의 안전한 순서(도움말 → 대상 확인 → 실행 → 결과 확인), 위험한 명령(`rm -rf ~/*`, `>` 덮어쓰기, `curl ... | sh`) 알아보기, 실행 결과 예측하기.
- **세트 46 (k8s) kubectl 명령과 YAML 해부하기**: `kubectl 동사 자원 -n 네임스페이스 -o 형식` 구조, Deployment YAML 의 `apiVersion`/`kind`/`metadata`/`spec`, 들여쓰기, 라벨과 셀렉터, `apply` 와 `create`, `--dry-run=client -o yaml`, `delete --all` 의 위험.

- **세트 47 (리눅스) 도움말로 명령 완성하기**: `cut`·`sort`·`head`·`date`·`ls`·`grep` 의 옵션을 정답으로 알려 주지 않고 `--help` 에서 찾아 쓰게 한다. 도움말 읽는 법(사용법 줄의 `[ ]` 와 `...`, `man` 에서 `/` 검색)은 개념 2문제로 먼저.

## 사다리 (리눅스, 이번 묶음)

```
[단원 1 기초]  42 개념 → 1 탐색 → 2 삭제·검색·권한 → 43 명령 연결 개념(NEW) → 3 프로세스 → 34 파이프·리다이렉션 실습 → 21 쉘 기본기
[단원 2 도구]  44 find 천천히(NEW) → 9 Vim → 7 압축 → 15 로그·텍스트 처리 → 30 → 17 쉘 스크립트 → 35 반복
```

- **세트 43 (개념, 터미널 없음)**: 표준 입력·출력·오류, `>`·`>>`·`2>`·`2>&1`(순서 포함), 파이프, `&&`·`||`·`;`. 세트 3 이 `2>&1` 을 쓰기 **앞**에서 이해시키고, 세트 34 가 손으로 익히게 한다. `display_order` 25 (세트 2 와 3 사이).
- **세트 44 (`find` 천천히)**: 구조(`find 어디 조건`) 개념 3문제 + 실습 11문제 (`-name`, `-type`, `-size`, `-mtime`, `-maxdepth`, `-o`, `!`, `-exec`, `-delete`, `xargs`, 4조건 종합). 단원 2 맨 앞 (`display_order` 45).
