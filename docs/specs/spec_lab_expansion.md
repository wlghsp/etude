# 명세 (초안) — 실습 세트 확대

> 상태: **초안 — 사용자 확인 대기** (2026-11-18). 계기: 사용자 지적 "실습이 많이 없다. 특히 리눅스·k8s·도커·Git 은 실습을 제공할 수 있었을 텐데."
> 현황 (`검증됨`, DB 집계, 세트 기준): 리눅스 42/112 (38%), k8s 26/100 (26%), 도커 16/61 (26%), Git 10/38 (26%). 전체 125/475 (26%).
> 원인: 최근 라운드가 `man`·공식 문서를 읽고 고르는 퀴즈(근거 링크·정확성에 강함)로 쏠렸다. 이 네 분야는 샌드박스로 직접 실행할 수 있다.

## 목표

- 네 분야(리눅스·k8s·도커·Git)의 실습 세트 비중을 **40% 이상**으로 올린다. 필요한 신규 실습 세트는 약 52개다.

| 분야 | 현재 실습/전체 | 40% 에 필요한 신규 실습 세트 |
|---|---|---|
| k8s | 26/100 | 약 24 |
| 도커 | 16/61 | 약 14 |
| Git | 10/38 | 약 9 |
| 리눅스 | 42/112 | 약 5 (공백 주제 위주) |

- 계산: (현재 실습 + x) / (전체 + x) ≥ 0.4. 이후 새 퀴즈를 만들 때마다 같은 비율을 유지한다 (퀴즈 라운드 사이에 실습 라운드를 끼운다).
- 샌드박스가 불가능한 분야(스토리지·가상화·OpenStack·네트워크 대부분)는 퀴즈 중심을 유지한다. 대상이 아니다.

## 원칙

- **이미 퀴즈로 읽은 주제를 손으로 해 보는 짝 세트**를 우선한다. 퀴즈가 "옵션·형식을 읽는" 것이라면 실습은 "직접 치고 결과로 채점"한다.
- 형식은 기존 실습 세트 규칙을 따른다: 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1, 결과 파일 **내용**으로 채점, 파괴적 명령은 `/tmp/lab` 안으로 한정, 환경 의존 값은 형식만 채점.
- 모든 터미널 문제는 `solution` 실행 시 통과, setup 만 한 상태에서는 실패해야 한다 (`verify:quests` 로컬 검증, 거짓 통과 금지).
- 라운드당 2~3세트 (실습은 세트마다 채점 스크립트·환경 검증이 필요해 퀴즈보다 느리다).

## 우선순위와 후보 (퀴즈로만 있는 주제 → 실습으로)

1. **Git (약 9)**: 가장 값싸다. 로컬 저장소만으로 완결, 외부 의존 없음. 후보: rebase -i·fixup·--onto, merge 전략·충돌 해결(rerere), worktree, bisect 실전, reflog 복구, 부분 스테이징(-p), config·별칭·includeIf, format-patch·am, 훅(pre-commit), 서브모듈, sparse-checkout.
2. **도커 (약 14)**: `docker` 샌드박스 사용. 후보: 멀티스테이지 빌드, 레이어·캐시 확인, ENTRYPOINT/CMD 조합, 볼륨·bind mount, 사용자 정의 네트워크, compose 의존·헬스체크, 로그 드라이버·자원 제한, 이미지 저장·반입, 종료 코드·시그널, exec·cp·디버깅.
3. **k8s (약 24)**: `k8s`(k3d) 샌드박스. 기동 시간이 길어 세트당 문제를 같은 클러스터에서 이어 푼다. 후보: Deployment 롤아웃·롤백, Probe, 리소스·QoS, Taint·Affinity·분산 제약, NetworkPolicy, PV/PVC, StatefulSet, CronJob, RBAC(권한 허용 시), Ingress, kubectl debug, Kustomize, Helm 업그레이드·롤백, 장애 주입 후 복구.
4. **리눅스 (약 5)**: 컨테이너에서 가능한 공백: sudoers 규칙 작성·검증(visudo -c), POSIX ACL(setfacl·getfacl), strace 로 실패 원인 찾기, sysctl·modprobe 조회·설정 범위, systemd 유닛·타이머 작성(`linux-systemd` 샌드박스), tcpdump 필터(루프백).

## 진행 방식

- 분야별로 위 순서. 세트마다 별도 명세(`spec_{분야}_{주제}_set.md`)와 수용 조건, `verify:quests` 결과를 남긴다.
- 기존 퀴즈 세트와 같은 주제는 "짝"으로 표시해 단원 안 인접하게 둔다 (실습 → 퀴즈 복습 순 또는 그 반대, 단원 규칙 [spec_units.md](spec_units.md)).
- 각 라운드 후 분야별 비율을 다시 집계해 보고한다.
