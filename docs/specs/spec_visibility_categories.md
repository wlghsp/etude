# 명세 (초안) — 대분류·퀘스트 단위 공개 제어와 코스 선택

> 상태: **초안 — 결정 대기** (2026-10-31). 코드 변경 없음.
> 계기: "자신에게 허용된 대분류 중 필요한 대분류만 선택해서 보여준다", "지금은 세트별로 공개 여부를 선택하는데 대분류, 세트, 퀘스트 별로 공개 여부를 선택할 필요도 있음."
> 이 문서는 [spec_phase7_quest_access.md](spec_phase7_quest_access.md)의 "범위 밖"(퀘스트 단위 제어, 그룹 단위 할당)을 새로 다룬다. 인증·인가를 바꾸므로 구현 전 사용자 승인과 리뷰 대상이다.

## 활용: 내부용과 외부용 구분

대분류를 공개/비공개로 나누면 같은 서비스 안에서 **내부 전용 분야**(예: 사내 운영 사례)와 **외부에도 보여 줄 분야**(일반 리눅스·k8s)를 구분할 수 있다. 한계도 분명하다.

- 이것은 **로그인한 사용자 사이의 노출 제어**이지 네트워크·서버 분리가 아니다. 외부 사용자가 같은 서버에 접속하는 구조라면, 내부 전용 콘텐츠가 서버에는 존재한다. 정말 격리가 필요하면 별도 배포가 필요하다.
- 강제는 반드시 **서버에서** 한다. 목록뿐 아니라 세트·문제 직접 조회, 터미널 세션 시작, 채점, 진행현황·소식 탭(feed)·리더보드의 이름과 활동까지 같은 가시성 조건을 거쳐야 한다. 화면에서 숨기는 것만으로는 직접 URL·API 호출로 새어 나간다.
- 외부 사용자를 받으려면 계정 발급 방식(가입·초대)과 역할(`member` 외 `guest` 등)도 함께 정해야 한다. 이 문서는 노출 제어까지만 다룬다.
- 콘텐츠 자체는 이미 현장 정보(IP·도메인·기관명)를 넣지 않는 규칙으로 일반화되어 있어, 외부 공개에 대한 위험이 낮다.

## 현재 (Phase 7)

- 공개 여부는 `quest_set.is_public` 하나. 비공개 세트는 `quest_set_access`의 사용자 또는 admin 만 본다.
- 대분류(`quest_set.category`)는 문자열 컬럼이라 공개 여부나 접근 목록이 없다.
- 퀘스트 단위 제어는 없다.

## 목표

1. **대분류 단위** 공개·접근 제어: 분야(예: 미들웨어, 인프라) 전체를 한 번에 공개/비공개로 하고 특정 사용자에게만 열 수 있다.
2. **퀘스트 단위** 숨김: 작성 중이거나 문제가 있는 퀘스트를 세트 안에서 잠시 숨긴다.
3. **학습자의 코스 선택**: 내게 허용된 대분류 중 보고 싶은 것만 골라 홈에 표시한다 (개인 설정, 접근 권한과는 별개).

## 가시성 규칙

세트가 사용자에게 보이는 조건은 **대분류 가시 AND 세트 가시** 이다.

| 단계 | 가시 조건 |
|---|---|
| 대분류 | 공개이거나, 접근 목록에 있거나, admin |
| 세트 | 기존 규칙 (공개이거나 세트 접근 목록에 있거나 admin) |
| 퀘스트 | `is_public = TRUE` 이거나 admin |

- 대분류가 보이지 않으면 그 안의 세트는 세트 접근 목록에 있어도 보이지 않는다 (더 넓은 쪽이 더 좁은 쪽을 막는다).
- 코스 선택은 **보이는 대분류 안에서만** 고를 수 있다. 선택은 화면 필터일 뿐 권한이 아니다.

## 데이터 모델 (제안)

```sql
CREATE TABLE category_setting (
  category  VARCHAR(50) PRIMARY KEY,
  is_public BOOLEAN NOT NULL DEFAULT TRUE
);
CREATE TABLE category_access (
  category   VARCHAR(50) NOT NULL,
  user_id    INT NOT NULL,
  granted_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (category, user_id),
  FOREIGN KEY (user_id) REFERENCES user(id)
);
ALTER TABLE quest ADD COLUMN is_public BOOLEAN NOT NULL DEFAULT TRUE;
-- 코스 선택은 사용자 설정: user_course(user_id, category) 또는 localStorage (결정 1)
```

대분류에 행이 없으면 공개로 본다 (기존 데이터 호환, 마이그레이션 불필요).

## 퀘스트 숨김의 의미 (결정 필요한 부분)

숨겨진 퀘스트는 세트의 문제 목록, 문제 수(`quest_count`), 첫 완료 XP, 세트 완료 판정에서 모두 빠진다. 이미 푼 기록(`quest_attempt`)은 지우지 않는다.

위험: 이미 세트를 끝낸 사용자는 완료 기록이 있는데 문제 수가 줄어든다. 완료는 "그 시점의 기록"이므로 유지하고, 새로 숨김 처리해도 진행률 집계(`progress`)가 어긋나지 않는지 테스트로 고정해야 한다.

## 영향 범위 (코드 확인 기준)

`quest_set.is_public` 을 읽는 곳은 `quest.ts`(목록·단건), `progress.ts`, `gamification.ts`, `feed.ts` 이다. 가시성 판단을 **한 함수(SQL 조각)로 모은 뒤** 이곳들이 같이 쓰게 해야 새 규칙이 곳곳에서 어긋나지 않는다.

## 결정 필요

1. **코스 선택 저장 위치:** 서버(`user_course`, 기기를 바꿔도 유지) vs 브라우저(`localStorage`, 단순). 추천: 처음엔 `localStorage`(현재 `etude.category` 와 같은 방식), 필요해지면 서버로.
2. **대분류 접근 단위:** 사용자 개별(세트와 동일) vs 그룹/역할. 추천: 개별로 시작(현재 규모에 충분).
3. **퀘스트 숨김의 용도:** 작성 중 초안 숨김 용도로 한정(추천) vs 학습자별 맞춤 노출. 후자는 범위가 크므로 제외.
4. **관리 화면:** 대분류 목록과 공개 토글, 접근 사용자 지정을 기존 세트 관리 화면 위에 추가.

## 구현 순서 (결정 후)

1. 가시성 SQL 조각을 한 곳으로 모으는 리팩터링 + 기존 테스트 통과 (동작 유지).
2. 대분류 테이블·API·관리 화면, 가시성 테스트(대분류 비공개, 접근 허용, admin).
3. 퀘스트 `is_public` 과 집계 테스트.
4. 홈 코스 선택기(상단 칩) — [project 메모의 코스 선택 UI 제안](spec_content_reinforcement.md)과 함께.

## 비목표

- 이미 쌓인 학습 기록·리더보드는 접근 변경과 무관하게 유지한다 (Phase 7 과 동일).
- 팀·그룹 관리 체계는 만들지 않는다.
