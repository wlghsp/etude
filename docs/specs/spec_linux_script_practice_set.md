# 명세 — 리눅스 쉘 스크립트 직접 써 보기 세트 (heredoc · shebang · 인자 · if · for · while read · exit · set -e · 함수 · $( ))

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 세트 335. 근거: 기존 세트 17·35·207·213 은 스크립트를 **읽고 고르거나**(퀴즈 세트 152·197·207·213·267·278) 짧은 스크립트 한두 개를 만드는 정도다. "heredoc 으로 파일을 만들고 → 실행 권한 → 인자 → 조건 → 반복 → 종료 코드 → `set -e` → 함수 → 명령 치환" 을 **한 줄기로 이어서, 채점이 학습자의 스크립트를 직접 실행해 보는** 세트는 없다.

## 목표

작은 쉘 스크립트를 편집기 없이 heredoc 으로 만들고, 실행 권한을 주고, 직접 돌려 본다. 문제마다 새 개념을 하나씩 붙인다: shebang·`chmod +x`·`./` 실행, `$1`, `$#`, `if [ -f ]`, `for f in *.txt`, `while read`, `exit 3` 과 `echo $?`, `set -e`, 함수, `$( )` 명령 치환, 출력을 파일에 저장. 쉬운 것부터 차례로 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1 (형식을 섞는 규칙).
- 학습자가 **쓰는** 세트다. 채점은 (1) 스크립트 파일이 있고 실행 가능한지, (2) 내용(shebang, `set -e`, `$(`, `while`/`read`, 함수 정의), (3) **실제로 실행해 본 출력과 종료 코드** 를 본다. 출력은 인자를 바꿔 보거나(`greet.sh Etude`/`Bash`), 데이터 파일을 하나 더 만들어 보는 식으로 확인해 값을 글자로 박아 넣은 풀이를 거른다.
- 채점이 학습자 스크립트를 실행하므로 입력은 작고 결정적이다. 네트워크, `sleep`, 무한 반복이 없다.
- setup 은 `/tmp/lab`, `/tmp/*.txt` 를 지우고 `data/{a,b,c}.txt`(2·1·3 줄)와 `names.txt`(alice·bob·carol)를 다시 만든다. 몇 번 실행해도 같은 상태다. 채점이 임시로 만든 파일(`z.txt`, `other.txt`)은 채점이 직접 지운다.
- 채점 명령은 `sh -c` 로 돌므로 bash 전용 문법을 쓰지 않는다. 풀이는 `bash` 로 실행한다.
- 이미지(`etude-linux`)는 `root` 로 실행되며 systemd 가 없다. 외부 도구는 쓰지 않는다.
- 객관식 정답은 보기 목록의 첫 번째로 적고, 도우미가 섞는다. 해설은 보기와 모순되지 않게 쓴다. 빈칸의 칩에는 정답이 둘 이상 되는 값이 없다 (`$#` 만 개수).
- 겹침 점검: 세트 17(첫 스크립트·인자·파일 확인·반복·종료 코드), 35(for·while read), 207·213(스크립트 기본기), 152·197·267·278(퀴즈·빈칸)과 주제가 겹친다. 차별점은 **heredoc 으로 직접 쓰고 채점이 스크립트를 실행**한다는 점, `set -e`·함수·`$( )` 를 파일 저장까지 이어 만드는 점이다. 17번과 가장 가깝다.

## 세트 구성 (12개, 세트 335)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | heredoc 으로 첫 스크립트 만들고 실행하기 | heredoc, shebang, `chmod +x`, `./` 실행, `>` 저장 | 실행 가능, 첫 줄 `#!`, 출력 `hello script`, 저장 파일 |
| 2 | 터미널 | 첫 번째 인자로 인사하기 ($1) | `$1` | `greet.sh Etude`, `greet.sh Bash` 출력 |
| 3 | 빈칸 | 받은 인자의 개수 | `$#` (칩 `$# $1 $@ $?`) | 칸 1개 |
| 4 | 순서 | 스크립트를 만들고 실행하는 순서 | 만들기 → 권한 → 실행 → `$?` | 4조각 |
| 5 | 터미널 | 파일이 있는지 확인하는 스크립트 (if [ -f ]) | `if [ -f ]`, else | 있으면 `found`, 없으면 `missing` |
| 6 | 터미널 | *.txt 파일을 하나씩 돌며 줄 수 세기 (for) | `for f in 경로/*.txt`, `basename`, `wc -l <` | 3줄 출력, 파일을 하나 더 만들어도 맞음 |
| 7 | 터미널 | 파일을 한 줄씩 읽어 처리하는 스크립트 (while read) | `while read line; do …; done < 파일` | names.txt 3줄, 다른 파일도 처리 |
| 8 | 터미널 | 종료 코드로 결과 알리기 (exit 3, echo $?) | `exit 숫자`, `$?` | 있으면 0, 없으면 3, `/tmp/rc.txt` == 3 |
| 9 | 객관식 | $? 를 두 번 읽으면 | `$?` 는 직전 명령의 종료 코드 | 정답: 1 그리고 0 |
| 10 | 터미널 | 명령이 실패하면 바로 멈추는 스크립트 (set -e) | `set -e` | 출력 `start` 만, 실패 코드, `set -e`·`echo end` 포함 |
| 11 | 터미널 | 함수로 묶어 재사용하기 (function) | 함수 정의·호출, `$(( ))` | `square.sh 4`=16, `7`=49, 함수 정의 포함 |
| 12 | 터미널 | 명령 결과를 변수에 담아 파일로 저장하기 ($( )) | `변수=$(명령)`, 스크립트 안의 `>` | `$(` 포함, `txt files: 3`, 파일을 더하면 `4` |

- 빈칸·순서·객관식은 터미널이 필요 없어 터미널 창이 보이지 않는다.
