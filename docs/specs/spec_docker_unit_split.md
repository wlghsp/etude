# 명세 — 도커 단원 나누기와 문제 단계 표시

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 근거: 피드백 #14("도커 기초 단원 단계가 너무 많음, 분리 필요"), #13("문제 31개는 너무 많다, 단계별로 나눠 머리 안 아픈 구조로"). 구체안은 사용자 위임으로 확정.

## 1. 도커 단원 나누기 (#14)

도커 "Docker 기초" 단원이 26세트까지 늘었다. 세트 자체는 그대로 두고 **단원만 주제별로 나눈다** (세트 번호·완료 기록·XP 불변, 데이터는 `unit_id`·`display_order` 만 바뀐다).

| 단원 (표시 순서) | 세트 id (단원 안 순서) |
|---|---|
| Docker 기초 | 40, 77, 5, 137 |
| 컨테이너 다루기 (신규 32) | 171, 191, 195, 199, 203, 212, 215, 160 |
| 이미지와 Dockerfile (신규 33) | 11, 167, 218, 183, 221, 154, 187, 8 |
| 네트워크와 볼륨 (신규 34) | 142, 179, 209 |
| Compose와 운영 (신규 35) | 148, 175, 206 |
| (기존) Dockerfile·compose 읽기, 문제 해결 | 38, 39 / 97 |

- 단원 `display_order`: 기초 10, 컨테이너 다루기 12, 이미지와 Dockerfile 14, 네트워크와 볼륨 16, Compose와 운영 18, 읽기 20, 문제 해결 30.
- 세트 `display_order` 는 175~200 으로 단원 안에서 이어진다 ([spec_units.md](spec_units.md) 규칙).
- 반영: `05_display_order.sql`·`06_units.sql` 끝에 덮어쓰는 블록, 이미 있는 DB 는 `migrations/2026-11-11_docker_unit_split.sql` (여러 번 실행해도 안전).
- 새 도커 세트는 주제에 맞는 단원에 넣고, 단원이 10세트를 넘으면 나눈다.

## 2. 문제 단계 표시 (#13)

최근 세트는 29~31문제다. 세트를 쪼개면 세트 번호·완료 기록·XP 가 바뀌므로 **쪼개지 않고, 화면에서 10문제씩 단계로 보여 준다** (이어 풀기가 있어 중간에 나가도 된다, [spec_resume_set.md](spec_resume_set.md)).

- 문제가 10개를 넘는 세트에서만: 진행 막대를 10칸마다 간격으로 나누고, 문제 배지 옆에 "N단계 / M단계"를 보인다.
- 완료 규칙·기록·XP 는 그대로다 (세트 단위).
