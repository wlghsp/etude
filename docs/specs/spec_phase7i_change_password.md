# Phase 7i 명세 — 본인 비밀번호 변경

## 목표

로그인한 유저가 스스로 비밀번호를 바꿀 수 있게 한다. 지금은 관리자가 계정 생성 시 임시 비밀번호를 정해주는 방식뿐이라([guide_user_management.md](../ops/guide_user_management.md)), 여러 팀원이 같은/유사한 임시 비밀번호를 공유하게 되는 문제가 있다.

배경: 팀원 계정을 실제로 오픈하기 직전, "비밀번호가 같다는 문제를 어떻게 해결할까" 논의에서 결정.

---

## 범위

**포함**: 로그인 상태에서 본인이 현재 비밀번호를 확인하고 새 비밀번호로 바꾸는 기능.

**제외 (범위 밖)**:
- 이메일 기반 "비밀번호를 잊으셨나요" 셀프 재설정 — SMTP 연동이 전무하고, 사내 소수 인원 규모에서는 과한 기능으로 판단.
- 비밀번호를 완전히 잊은 경우는 기존에 이미 있는 관리자 강제 리셋(`PATCH /admin/users/:id/password`)으로 충분하다고 판단 — 사내 도구에서 "관리자에게 요청 → 리셋"은 자연스러운 흐름.
- 비밀번호 정책(최소 길이, 특수문자 요구 등) 강제 — 현재 계정 생성 시에도 정책이 없으므로 이 Phase에서 새로 도입하지 않는다.
- 이전 비밀번호 재사용 금지 — 지금 규모에서는 과한 제약으로 판단, 도입하지 않는다.

---

## API

`PATCH /me/password`

| 항목 | 내용 |
|------|------|
| 인증 | 필수 (JWT) — `authMiddleware` |
| body | `{ currentPassword: string, newPassword: string }` |
| 동작 | `currentPassword`를 DB의 해시와 bcrypt 비교 → 일치하면 `newPassword`를 해시해 업데이트 |
| 실패 조건 | `currentPassword` 불일치 시 401 |

관리자용 강제 리셋(`PATCH /admin/users/:id/password`, `resetPassword()`)과는 별개의 엔드포인트다 — 관리자용은 현재 비밀번호 확인 없이 admin 권한만으로 바꾸는 것이고, 이번 것은 본인이 현재 비밀번호를 알아야 바꿀 수 있다는 점이 다르다.

## 프론트엔드

기존 `SideNav.tsx`에 유저 이름/이메일이 이미 표시되는 영역이 있다 ([SideNav.tsx:45-46](../../frontend/src/components/SideNav.tsx#L45-L46)). 그 근처에 "비밀번호 변경" 진입점(버튼 또는 링크)을 추가하고, 클릭 시 모달 또는 별도 화면에서 현재 비밀번호/새 비밀번호/새 비밀번호 확인 3개 입력 필드를 받는다.

새 비밀번호와 확인 입력이 일치하지 않으면 제출 전에 프론트에서 막는다.

---

## 검증 기준

- [ ] 로그인 후 비밀번호 변경 화면 진입 가능
- [ ] 현재 비밀번호를 틀리면 실패, 에러 메시지 표시
- [ ] 현재 비밀번호가 맞고 새 비밀번호를 입력하면 변경 성공
- [ ] 변경 후 기존 비밀번호로는 로그인 안 되고, 새 비밀번호로는 로그인 됨
- [ ] 관리자 강제 리셋(`PATCH /admin/users/:id/password`) 기능이 이 변경으로 영향받지 않는지 회귀 확인
