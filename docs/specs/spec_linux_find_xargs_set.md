# 명세 — 리눅스 파일 찾고 한꺼번에 처리하기 세트 (find · -exec · xargs · grep -rl)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-12). 세트 347. 근거: 세트 44(find 천천히 익히기)가 `-name`·`-type`·`-size`·`-mtime`·`-maxdepth`·`-o`·`!`·`-exec`·`-delete`·`xargs` 줄 수 합계를 터미널 11문제로 다루고, 세트 169/271(찾아서 처리하기)·216/284(find 조건 모음, `-print0`·`-prune`)·201/279(xargs `-n`/`-I`/`-P`)는 대부분 **고르는 퀴즈**다. 세트 21 은 `find | xargs` 한 문제, 세트 338 은 `ls -t | tail | xargs rm` 한 문제다. 이 세트는 "찾은 결과를 **실제로 옮기고·복사하고·지우고·고치는**" 일괄 처리에 집중하고, 조건 조합(`-o`·`!`·`-prune`)은 기존 세트에 맡긴다. 공백이 든 이름(`-print0`/`xargs -0`)과 `grep -rl | xargs sed -i` 를 **상태 채점**하는 터미널 세트는 없다.

## 목표

작은 작업 폴더(`/tmp/lab/src`, 파일 18개, 폴더 3단계, 공백이 든 이름 4개, 오래된 파일 3개)에서 "찾기 → 세기 → 옮기기·복사하기 → 안전하게 지우기 → 내용으로 찾아 고치기" 를 쌓는다. 문제마다 새 개념 하나: `-name`+`-type f`, `-maxdepth`+`wc -l`, `-size +1k`, `-mtime +30`, `-exec mv {} 목적지 \;`, `\;` 와 `+` 의 차이, `-exec cp -t ... +`, `-print0 | xargs -0`, 공백 이름 삭제, `xargs -n1`, 지우기 전 확인 순서, `grep -rl --include | xargs sed -i`. 쉬운 것부터 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1.
- setup 은 `/tmp/lab` 을 지우고 `src` 트리(`touch -d '2020-01-01'` 로 오래된 파일 3개를 고정), `trash/`, `backup/` 을 다시 쓴다. 몇 번 실행해도 같은 상태이고 `-mtime` 채점은 실행 시각과 무관하다(오래된 파일은 2020년, 나머지는 방금 만든 것).
- 채점은 **파일시스템 상태**를 본다: 결과 목록은 정렬해 md5 비교(find 출력 순서에 의존하지 않음), 옮기기·복사·삭제 문제는 대상 폴더의 파일 이름 목록과 `src` 의 남은 파일 수를 함께 본다(15·14·7개). 결과를 `echo` 로 지어내도 되는 목록 문제(1~4, 10번)는 어쩔 수 없이 내용 일치로 채점하고, 이름이 `.log` 인 폴더(`rotated.log`)·`notes.txt` 속 `debug=true` 같은 함정으로 조건을 빠뜨린 풀이를 거른다.
- 모든 터미널 문제는 setup 직후에는 채점이 실패한다.
- 이미지(`etude-linux`)는 GNU findutils 4.8(`find`, `xargs`), GNU coreutils(`cp -t`, `mv`, `basename`), GNU grep/sed 를 쓴다. 채점은 `sh -c`, 풀이는 `bash`. 네트워크·`sleep` 없음.
- 객관식 정답은 보기 첫 번째로 적고 도우미가 섞는다. 보기 길이를 비슷하게 맞췄고 해설은 보기와 모순되지 않는다. 빈칸 칩(`-0` `-n1` `-t` `-r`)은 이름이 공백에서 쪼개지지 않게 하는 옵션이 `-0` 뿐이므로 정답이 하나다.
- 순서 문제는 순서가 하나로 정해지는 작업(목록 저장 → 확인 → 삭제 → 재확인)으로 골랐다.
- 가상 데이터만 쓰고 IP·도메인·회사·내부 시스템 이름은 없다. 힌트는 "어떻게 살펴보나" 만 말한다.
- 문서 링크: man7.org 의 `find`·`xargs`·`grep`·`mv`·`cp` (모두 200 확인).
- 겹침 점검: 세트 44 는 `-name`(4번)·`-size`(6)·`-mtime`(7)·`-maxdepth`(8)·`-exec`(11)·xargs 합계(13)를 이미 다룬다. 이 세트는 같은 조건을 쓰되 (1) 결과를 **파일에 저장·개수 세기**, (2) `-exec mv`/`cp -t +` 로 **옮기고 복사한 상태 채점**, (3) `-print0`/`xargs -0` 로 **공백 이름 안전 삭제**, (4) `grep -rl --include | xargs sed -i` 로 **내용 기반 일괄 수정**이 차별점이다. 세트 216/284 의 `-print0`·`-exec ; 와 +` 는 퀴즈이고 이 세트는 터미널 상태 채점이다. 세트 201/279 의 `xargs -n/-I/-P` 는 퀴즈다. 세트 21·338 과 `xargs rm` 이 한 번 겹치지만 공백 이름과 상태 채점이 다르다.

## 세트 구성 (12개, 세트 347)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | 이름 패턴으로 파일만 찾아 저장하기 | `-name '*.log'` + `-type f` | `logs.txt` 에 .log 파일 7개(폴더 `rotated.log` 제외) |
| 2 | 터미널 | 바로 아래만 찾고 개수 세기 | `-maxdepth 1`, `wc -l` | `top_count.txt` 가 3 |
| 3 | 터미널 | 크기로 찾기 | `-size +1k` | `big.txt` 에 큰 파일 2개 |
| 4 | 터미널 | 오래된 파일 찾기 | `-mtime +30` | `old.txt` 에 오래된 파일 3개 |
| 5 | 터미널 | 찾은 파일을 한 곳으로 옮기기 | `-exec mv {} 목적지 \;` | `trash/` 에 .tmp 3개, `src` 에 .tmp 없음, 나머지 15개 유지 |
| 6 | 객관식 | -exec 의 `\;` 와 `+` 는 무엇이 다를까? | 파일마다 실행 vs 모아서 한 번 | 정답: 파일마다 / 모아서 |
| 7 | 터미널 | 여러 파일을 한 번에 복사하기 | `-exec cp -t 목적지 {} +` | `backup/` 에 .log 7개, 원본 7개 유지 |
| 8 | 빈칸 | 공백이 있는 이름을 안전하게 넘기기 | `-print0 \| xargs -0` | 칸 1개 (`-0`) |
| 9 | 터미널 | 이름에 공백이 있는 파일 지우기 | 공백 이름 패턴 `'* *'` + `xargs -0 rm` | 공백 이름 파일 없음, 나머지 14개 유지 |
| 10 | 터미널 | 인자를 하나씩 넘기기 | `xargs -n1 basename` | `confnames.txt` 에 이름 3개 |
| 11 | 순서 | 지우기 전에 확인하는 순서 | 목록 저장 → 확인 → 삭제 → 재확인 | 4조각 |
| 12 | 터미널 | 내용으로 찾아 한꺼번에 고치기 | `grep -rl --include \| xargs sed -i` | app·db 는 `debug=false`, net·notes 는 그대로 |

- 빈칸·순서·객관식은 터미널이 필요 없어 터미널 창이 보이지 않는다.
