# 명세 — 리눅스 접속 로그 한 줄기로 분석하기 세트 (wc · grep -c · awk · sort | uniq -c · sort -rn | head · sort -u · 합계 · cut)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 세트 341. 근거: 세트 15(로그와 텍스트 처리 12문제)와 49(텍스트 도구 입문), 185·189·177 등 퀴즈 세트는 도구를 **따로따로** 다루거나 고르는 수준이다. "한 개의 고정 로그 → 줄 수 → 상태 코드 세기 → 칸 뽑기 → IP 별 횟수 → 상위 3개 → 상태 코드로 걸러내기 → 오류 경로 → 바이트 합계 → 한 줄 파이프라인 파일 저장" 을 **한 이야기로 잇고, 파일에 저장된 값을 로그에서 따로 계산한 정확한 값과 비교하는** 세트는 없다.

## 목표

웹 접속 로그(common log format) 36줄 하나를 단계별로 분석한다. 문제마다 새 개념을 하나씩 붙인다: `wc -l`, `grep -c ' 500 '`, `awk '{print $1}'`, `cut -d' ' -f`(awk 칸 번호와의 대응), `uniq -c` 앞에 `sort` 가 필요한 이유, `sort | uniq -c`, `sort -rn | head -3`, 파이프라인 단계의 순서, `awk '$9==404'` 조건 걸러내기, 조건 + 칸 뽑기 + `sort -u`, `awk '{s+=$10} END {print s}'`, 세 단계 파이프라인을 파일로 저장. 쉬운 것부터 12문제.

## 원칙

- 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1.
- 로그는 setup 이 `/tmp/lab/access.log` 로 쓴다. 36줄, 날짜·난수 없음, IP 는 `192.0.2.10~14`, 경로 7개, 상태 200·404·500, 시각 고정(2026-11-10 09:00:00 부터 37초 간격). 칸 번호: 1 IP, 4 `[날짜`, 6 `"GET`, 7 경로, 9 상태, 10 바이트. 생성기가 한 번 정한 값을 본문에 박으므로 몇 번 실행해도 같다.
- 로그의 정확한 값: 전체 36줄, 500 응답 6건, IP 별 `.10`=13·`.11`=9·`.12`=7·`.14`=4·`.13`=3 (동률 없음), 404 줄 6개(`/old-page` 4·`/missing.png` 2), 500 경로 `/api/login`·`/api/orders`, 바이트 합계 362086.
- 채점은 **파일 내용**을 본다: 숫자, md5(줄 순서까지 정확한 기대값), `awk '{print $2" "$1}' | sort` 로 정규화한 `횟수 IP`. 값은 생성기가 로그에서 따로 계산해 채점 명령에 넣는다. 명령 문자열은 보지 않되, 12번은 스크립트를 **실제로 실행**해 결과를 본다.
- 겹침 점검: 세트 15 는 `tail`·`grep ERROR`·IP 추출 등 별개 로그로 12문제, 49 는 sort·uniq·cut 단독 입문이다. 이 세트는 **하나의 데이터로 쌓는 분석 이야기**, 정확한 값 검증, 한 줄 파이프라인 파일 저장이 차별점이다. 퀴즈 세트(185·189·177 등)는 고르기 위주다. 세트 15 의 8번(IP 만 뽑기)과 3번이 비슷하나 여기서는 이후 단계의 재료다.
- 이미지(`etude-linux`)의 awk 는 **mawk 1.3.4** 다. POSIX awk 기능(`$9==404`, `END`)만 쓴다. `sort`, `uniq`, `cut`, `wc`, `md5sum` 있음. `root` 로 실행되며 systemd 가 없다.
- setup 은 `/tmp/lab` 을 지우고 로그를 다시 쓴다. 터미널 문제는 모두 같은 setup 이고 몇 번 실행해도 같은 상태다.
- 채점 명령은 `sh -c`, 풀이는 `bash`. 네트워크·`sleep` 없음.
- 객관식 정답은 보기 첫 번째로 적고 도우미가 섞는다. 보기 길이를 비슷하게 맞췄고 해설은 보기와 모순되지 않는다. 빈칸 칩(`sort head tac cat`)에는 정답이 둘 이상 되는 값이 없다.
- IP 는 문서용 대역 `192.0.2.x` 만, 도메인·회사·내부 시스템 이름을 쓰지 않는다. 힌트는 "어떻게 살펴보나" 만 말한다.
- 문서 링크: GNU coreutils(sort·uniq·cut)와 gawk 안내서. 작성 시점에 gnu.org 에 접속되지 않아 200 확인을 못 했다. 통합 전에 확인한다.

## 세트 구성 (12개, 세트 341)

| # | 형식 | 제목 | 새로 익히는 것 | 채점 |
|---|------|------|----------------|------|
| 1 | 터미널 | 로그가 모두 몇 줄인지 세기 (wc -l) | `wc -l < 파일` | `total.txt` = 36, 한 줄 |
| 2 | 터미널 | 특정 상태 코드만 세기 (grep -c) | `grep -c ' 500 '` | `count500.txt` = 6, 한 줄 |
| 3 | 터미널 | 한 칸만 뽑아내기 (awk '{print $1}') | awk 칸 번호 | `ips.txt` 36줄, md5 일치 |
| 4 | 객관식 | cut 으로 상태 코드 칸 뽑기 | `cut -d' ' -f9` = awk `$9` | 정답: `$9` |
| 5 | 빈칸 | 같은 IP 를 이웃하게 모으기 (uniq 앞의 한 단계) | `uniq -c` 는 이웃한 줄만 센다 | 칸 1개 (`sort`) |
| 6 | 터미널 | IP 별 요청 횟수 세기 (sort \| uniq -c) | `sort \| uniq -c` | `per_ip.txt` 5줄, `횟수 IP` 일치 |
| 7 | 터미널 | 가장 많이 요청한 IP 3개 (sort -rn \| head -3) | `sort -rn`, `head -3` | `top3.txt` 3줄, 많은 순 정확 |
| 8 | 순서 | 가장 많이 요청된 경로 3개를 구하는 순서 | 파이프라인 단계의 순서 | 5조각 |
| 9 | 터미널 | 상태 코드로 줄 걸러내기 (awk '$9==404') | awk 조건(동작 생략) | `notfound.log` md5(줄 전체), 6줄 |
| 10 | 터미널 | 서버 오류가 난 경로 목록 (조건 + 칸 뽑기 + sort -u) | 조건 + 동작, `sort -u` | `err_paths.txt` md5, 2줄 |
| 11 | 터미널 | 전송한 바이트 합계 구하기 (awk 의 END) | `END`, 누적 변수 | `bytes_total.txt` = 362086, 한 줄 |
| 12 | 터미널 | 404 경로별 횟수를 구하는 한 줄을 스크립트 파일로 저장하기 | 세 단계 파이프라인을 파일로 | `notfound.sh` 존재, 파이프 2개 이상, **실행 결과** 일치 |

- 빈칸·순서·객관식은 터미널이 필요 없어 터미널 창이 보이지 않는다.
- 상태 코드는 요청대로 200·404·500 만 쓴다. 5xx 전체를 묻는 문제는 만들지 않았다.
