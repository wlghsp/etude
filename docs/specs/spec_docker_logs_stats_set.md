# 명세 — 도커 컨테이너 들여다보기 실습 세트 (로그·자원·파일 복사)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 근거: 기존 도커 세트는 `inspect -f`·`ps --format`(225), 장애 진단(97), 볼륨·네트워크(228)를 다룬다. 실행 중인 컨테이너를 **밖에서 읽는 도구**(`logs`, `top`, `stats`, `cp`, `diff`)는 세트 5 의 `logs`·`exec` 각 한 문제 외에는 연습할 곳이 없다.

## 목표

`docker logs` 를 `--tail`·`-t` 로 골라 보고, `docker exec` 로 안에서 명령을 한 번 실행한다. `docker top`·`docker stats --no-stream --format` 으로 프로세스·자원을 밖에서 확인하고, `docker cp` 로 파일을 꺼내고 넣는다. `docker diff` 로 바뀐 파일을 고르고, `inspect -f` 로 상태와 재시작 횟수를 읽는다.

## 원칙

- 터미널 실습은 결과 파일·상태의 **내용**으로 채점한다. setup 만 한 상태에서는 반드시 실패한다.
- 새 개념은 한 문제에 하나. 쉬운 것에서 어려운 것으로.
- 이미지는 `alpine` 하나만 쓴다. 로그는 `line1`~`line5` 를 출력하는 결정적인 컨테이너로 만든다.
- `docker stats` 숫자는 매번 달라지므로 **값이 아니라 모양**(이름, `사용량 / 한도` 형식)만 채점한다. `-f`(계속 따라가기)는 끝나지 않아 채점할 수 없으므로 객관식 개념 문제로만 다룬다. `docker events` 는 결정성이 낮아 뺐다.
- 225(`inspect -f`·`ps --format` 추출), 97(장애 진단), 228(볼륨·네트워크)과 겹치지 않게, 11번의 `inspect -f` 는 상태+재시작 횟수 읽기에만 쓴다.

## 세트 구성 (12개: 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1)

| # | 형식 | 제목 | 새로 익히는 것 |
|---|------|------|----------------|
| 1 | 터미널 | 컨테이너 로그 전부 저장하기 | `docker logs 이름` |
| 2 | 터미널 | 끝의 몇 줄만 보기 | `--tail N` |
| 3 | 터미널 | 줄마다 시각 붙이기 | `-t` 타임스탬프 |
| 4 | 객관식 | 로그를 계속 따라가며 보기 | `docker logs -f` (개념) |
| 5 | 터미널 | 컨테이너 안에서 명령 한 번 실행 | `docker exec 이름 명령` |
| 6 | 터미널 | 컨테이너 안에서 도는 프로세스 | `docker top` |
| 7 | 빈칸 | 호스트 파일을 컨테이너로 복사 | `docker cp 원본 대상` (넣기) |
| 8 | 터미널 | 컨테이너 자원 사용량 한 번만 보기 | `docker stats --no-stream --format` |
| 9 | 터미널 | 컨테이너 안의 파일 꺼내기 | `docker cp 이름:경로 호스트경로` |
| 10 | 터미널 | 컨테이너가 바꾼 파일만 골라 보기 | `docker diff` + `grep '^A'` |
| 11 | 터미널 | 재시작 횟수와 상태 읽기 | `inspect -f '{{.State.Status}} {{.RestartCount}}'` |
| 12 | 순서 | 이상한 컨테이너 들여다보는 흐름 | ps → logs → top → exec → cp |
