# 명세 — `SQL 기초` 단원을 주제별 단원 넷으로 나누기

> 상태: **구현 중(로컬)** (2026-11-13). 근거: 사용자 지적("SQL 기초도 너무 길다, 분할이 필요하다").

## 현황

- 단원 `SQL 기초`(id 30)에 세트가 18개다. 개념 퀴즈 12개(분할된 1/2·2/2 포함)와 손연습 6개(366·367·369·371·372·374)가 한 단원에 섞여 있다.

## 결정

주제별로 네 단원으로 나누고 단원 이름에 번호를 붙인다(사용자: "넘버링으로 분할해도 좋다"). 단원 안에서 단원 안에서 개념 퀴즈 → 손연습 순으로 둔다. 세트 번호는 바꾸지 않는다.

| 단원(display_order) | 세트 (순서대로) |
|---|---|
| `SQL 1 · 조회` (id 30, 이름 변경, 10) | 125, 126, 139, 329, 140, 330, 366 |
| `SQL 2 · JOIN·서브쿼리·윈도` (새 id 44, 11) | 141, 331, 372, 374 |
| `SQL 3 · 데이터 바꾸기` (새 id 45, 12) | 159, 333, 367 |
| `SQL 4 · 테이블과 인덱스` (새 id 46, 13) | 164, 334, 371, 369 |

- 세트 `display_order` 는 기존 538~555 범위를 그대로 쓰되 위 순서대로 다시 매긴다(분야의 다른 세트는 이동하지 않는다).
- 단원 `display_order` 는 `MariaDB 운영`(20) 앞에 오도록 10~13 으로 둔다.

## 반영 방식

- 새 DB: `06_units.sql` 에 단원 이름 변경·새 단원·세트 이동을 덧붙이고, `11_new_set_order.sql` 에 절대값 `display_order` 를 덧붙인다(뒤 파일이 이긴다).
- 기존 DB: `backend/db/migrations/2026-11-13_split_sql_basics_unit.sql` (여러 번 실행해도 안전).
