# 명세 — 활동 피드 (소식, 좋아요, 댓글)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30). 참고: 듀오링고 친구 소식.

## 목적

서로의 학습을 보고 응원하는 화면이다. 누가 어떤 세트를 끝냈는지 소식으로 보이고, 좋아요와 짧은 댓글로 서로 기분 좋게 한다. 혼자 하는 학습의 외로움을 줄이고 반복 학습의 동기가 되게 한다.

## 소식

- **세트 완료 한 건이 소식 한 건이다.** "OO님이 [분야] #번호 세트 제목 을(를) 완료했어요".
- 표시: `퍼펙트`(힌트·풀이 없이 모두), `첫 완료`(그 세트를 처음 끝냄), `복습`(이미 끝낸 세트를 다시 끝냄).
- 대상은 회원(`role = 'member'`)의 완료이고 공개 세트만이다. 최신순이며 20개씩 "더 보기".
- 문제별 채점 기록은 쓰지 않는다 (기록 단위는 세트 완료).

## 좋아요

- 소식마다 사람당 하나. 누르면 켜지고 다시 누르면 취소된다.
- **내 소식에는 누를 수 없다** (수를 부풀리지 못하게).

## 댓글

- 1~300자, 앞뒤 공백은 제거한다. 화면에는 **글자 그대로**(HTML 로 해석하지 않음) 보인다.
- 한 사람이 **1분에 10개**까지 쓸 수 있다.
- 지우기는 **쓴 사람 또는 관리자**. 지운 댓글은 숨기기만 한다(`deleted_at`).
- 소식당 최대 50개까지 보인다.

## 새 반응 알림

- 내 소식에 **다른 사람이** 남긴 좋아요·댓글 중 내가 "소식" 탭을 마지막으로 열고 난 뒤의 것을 센다. "소식" 탭에 숫자 배지로 보이고, 탭을 열면 읽음 처리(`feed_seen`)한다.

## 데이터

외래 키는 두지 않는다 (`set_completion` 과 같은 이유). 소식의 id 는 `set_completion.id` 이다.

- `feed_like(completion_id, user_id, created_at)` — 기본 키 (completion_id, user_id)
- `feed_comment(id, completion_id, user_id, body, created_at, deleted_at)`
- `feed_seen(user_id, seen_at)`

## API (모두 로그인 필요)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/feed?before=<id>&limit=<n>` | 소식 목록(좋아요 수, 내가 눌렀는지, 댓글, 내가 지울 수 있는지 포함) |
| POST | `/feed/:id/like` | 좋아요 켜기/끄기 → `{ liked, likes }` |
| POST | `/feed/:id/comments` | 댓글 쓰기 `{ body }` → 만든 댓글 |
| DELETE | `/feed/comments/:id` | 댓글 지우기 (작성자·관리자) |
| GET | `/feed/summary` | `{ newForMe }` 안 본 새 반응 수 |
| POST | `/feed/seen` | 읽음 처리 |

오류: 400(빈 댓글·300자 초과·내 소식 좋아요), 404(없는 소식·댓글), 403(남의 댓글 삭제), 429(1분 10개 초과).

## 화면

랭킹 화면의 세 번째 탭 **소식**. 카드(아바타, "OO님이 … 완료했어요", 몇 분 전, 표시 칩), 좋아요 버튼과 수, 댓글 펼치기와 입력, 내 댓글 삭제, "더 보기". 소식이 없으면 "첫 소식의 주인공이 되어 보세요!".

## 검증

- 서비스 테스트(댓글 검증·속도 제한·삭제 권한·좋아요 토글·내 소식 좋아요 거부·목록 구성·알림 수)와 라우트 테스트, 새 초기화 경로·마이그레이션, 프론트 타입 검사와 빌드. 화면은 사용자가 확인한다.
