# 명세 — 활동 피드 (소식, 좋아요, 댓글)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30). 참고: 듀오링고 친구 소식.

## 목적

서로의 학습을 보고 응원하는 화면이다. 누가 어떤 세트를 끝냈는지 소식으로 보이고, 좋아요와 짧은 댓글로 서로 기분 좋게 한다. 혼자 하는 학습의 외로움을 줄이고 반복 학습의 동기가 되게 한다.

## 소식 분류 (한눈에 보기)

소식 화면에 올라오는 것은 아래 네 갈래뿐이고, **모두 좋은 소식**이다.

| 분류 | 모양 | 좋아요·댓글 | 근거 |
|---|---|---|---|
| **세트 완료** | 카드 한 장 ("OO님이 [분야] #번호 세트를 완료했어요") | 가능 | 세트 완료 기록 한 건 = 소식 한 건 |
| **표시 칩** (완료 카드에 붙음) | 💯 퍼펙트 · 🌱 첫 완료 · 🔁 복습 | — | 그 완료의 성격 |
| **축하** (완료 카드에 붙음) | 금색 띠 하나 + 나머지는 칩 | — | 그 완료로 **처음 이룬 일** (아래 표) |
| **주간 MVP 배너** | 소식 맨 위 한 줄 (소식 한 건 아님) | 불가 | 명예의 전당과 같은 계산 |

### 축하 종류와 우선순위 (높은 것이 큰 띠, 나머지는 칩)

1. 🌟 분야 정복 — 그 분야의 공개 세트를 모두 끝냄
2. 🎖️ 단원 정복 — 한 단원의 세트를 모두 끝냄
3. 🎁 이달의 도전 — 이번 달 열 번째 완료
4. ⭐ 레벨 업 — XP 레벨이 올라감
5. 🔥 연속 학습 — 14·30일에 처음 닿음 (3·7일은 배지로 축하)
6. 🏅 배지 — 새로 얻은 배지 (첫 걸음, 다섯·열·스무 세트, 3·7일 연속, 퍼펙트, 복습왕)

### 색과 아바타 (2026-10-30)

- 축하는 **종류 안에서도 서로 다른 색**이다. 서버가 축하마다 고유 키(`cheer.key`: `category`, `unit`, `challenge`, `level`, `streak14`, `badge:first`, `badge:perfect` …)를 내려 주고, 화면(`FeedTab.tsx` 의 `TONE_BY_KEY`)이 키별 색을 고른다 (없으면 종류별 색). 🎉 같은 장식 이모지는 겹쳐 넣지 않고 띠 왼쪽의 큰 아이콘이 축하를 맡는다.
- 사용자 아바타는 **이름으로 정해지는 8가지 색**(`avatar.ts`)이라 사람마다 다르고 소식과 사이드바에서 같다.

### 소식에 올리지 않는 것

틀린 횟수, 힌트·풀이를 많이 쓴 것, 순위 하락, 시간 초과, 오랜만의 복귀, 다른 사람과의 비교. (칭찬·응원 중심이다.)

### 후보 (아직 안 만듦)

- ⏱ 시험 통과: 시간 제한 세트(복습 세트)를 제한 시간 안에 끝냄 — 복습 세트가 생긴 뒤.

## 소식

- **세트 완료 한 건이 소식 한 건이다.** "OO님이 [분야] #번호 세트 제목 을(를) 완료했어요".
- 표시: `퍼펙트`(힌트·풀이 없이 모두), `첫 완료`(그 세트를 처음 끝냄), `복습`(이미 끝낸 세트를 다시 끝냄).
- 대상은 회원(`role = 'member'`)의 완료이고 공개 세트만이다. 최신순이며 20개씩 "더 보기".
- 문제별 채점 기록은 쓰지 않는다 (기록 단위는 세트 완료).

## 반응 (좋아요·박수·힘내요·대단해요)

- 반응 종류는 ❤️ `like`, 👏 `clap`, 💪 `strong`, 🔥 `fire` 네 가지다 (빠른 응원 버튼, 글을 쓰지 않아도 응원할 수 있다).
- **한 사람이 소식 한 건에 여러 반응**을 남길 수 있다 (카톡·Slack 처럼). 같은 반응을 다시 누르면 그 반응만 취소되고, 다른 반응을 누르면 추가된다 (2026-10-30 "한 사람 한 반응" 에서 변경). 기본 키는 `(completion_id, user_id, kind)` 이다.
- **내 소식에는 남길 수 없다** (수를 부풀리지 못하게). 내 소식에는 받은 반응 수만 보인다.
- 대댓글은 만들지 않는다 (응원까지만, 소통이 길어지는 것을 막는다). 2026-10-30 결정.

## 댓글

- 1~300자, 앞뒤 공백은 제거한다. 화면에는 **글자 그대로**(HTML 로 해석하지 않음) 보인다.
- 한 사람이 **1분에 10개**까지 쓸 수 있다.
- 지우기는 **쓴 사람 또는 관리자**. 지운 댓글은 숨기기만 한다(`deleted_at`).
- 소식당 최대 50개까지 보인다.

## 새 반응 알림

- 내 소식에 **다른 사람이** 남긴 좋아요·댓글 중 내가 "소식" 화면을 마지막으로 열고 난 뒤의 것을 센다. "소식" 탭에 숫자 배지로 보이고, 탭을 열면 읽음 처리(`feed_seen`)한다.

## 데이터

외래 키는 두지 않는다 (`set_completion` 과 같은 이유). 소식의 id 는 `set_completion.id` 이다.

- `feed_like(completion_id, user_id, kind, created_at)` — 기본 키 (completion_id, user_id, kind), `kind` 는 반응 종류
- `feed_comment(id, completion_id, user_id, body, created_at, deleted_at)`
- `feed_seen(user_id, seen_at)`

## API (모두 로그인 필요)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/feed?before=<id>&limit=<n>` | 소식 목록(좋아요 수, 내가 눌렀는지, 댓글, 내가 지울 수 있는지 포함) |
| POST | `/feed/:id/like` | 본문 `{ kind }` (생략하면 like). 그 반응을 켜거나 끈다 → `{ mine, counts }` (`mine`: 내가 단 반응 종류 목록, `counts`: 종류별 수). 소식 항목의 `myReaction` 은 `myReactions`(목록)로 바뀐다 |
| POST | `/feed/:id/comments` | 댓글 쓰기 `{ body }` → 만든 댓글 |
| DELETE | `/feed/comments/:id` | 댓글 지우기 (작성자·관리자) |
| GET | `/feed/summary` | `{ newForMe }` 안 본 새 반응 수 |
| POST | `/feed/seen` | 읽음 처리 |

오류: 400(빈 댓글·300자 초과·내 소식 좋아요), 404(없는 소식·댓글), 403(남의 댓글 삭제), 429(1분 10개 초과).

## 화면

사이드바의 독립 메뉴 **소식**(랭킹 아래, `pages/Feed.tsx`). 새 반응이 있으면 메뉴에 빨간 숫자 배지가 붙고, 화면을 열면 본 것으로 기록된다. (2026-10-30 랭킹 탭에서 이동) 카드(아바타, "OO님이 … 완료했어요", 몇 분 전, 표시 칩), 좋아요 버튼과 수, 댓글 펼치기와 입력, 내 댓글 삭제, "더 보기". 소식이 없으면 "첫 소식의 주인공이 되어 보세요!".

## 축하 소식 (좋은 소식만, 2026-10-30)

세트 완료 소식 한 건에 **그 완료로 처음 이룬 일**을 축하로 붙인다. 새 테이블은 없고, 소식을 조회할 때 그 사람의 완료 기록을 그 완료 시점까지 되돌려 계산한다. 좋아요·댓글은 지금처럼 완료 한 건(`completion_id`)에 붙는다.

### 축하 종류

종류와 우선순위는 위 **소식 분류**의 표가 기준이다 (같은 내용을 두 곳에 쓰지 않는다).

- 한 완료에 여러 개가 겹치면 위 표의 **우선순위**로 정렬한다. 화면은 첫 번째를 큰 축하 문구로, 나머지는 칩으로 보인다.
- 규칙(XP·레벨·배지)은 서버 `services/gamification.ts`·`xp.ts` 한 곳이 기준이고, 진행현황 화면도 `GET /gamification` 값을 쓴다 (프론트 계산 코드는 없앴다).
- **주간 MVP**: 소식 맨 위의 배너로 보인다 ("이번 주 MVP는 OO 님이에요 🎉", 최근 7일 완료 수·연속 학습일). 상대적이고 계속 바뀌는 값이라 소식 한 건(좋아요·댓글 대상)이 아니라 명예의 전당과 같은 계산(`GET /report` 의 `mvp`)을 그대로 쓴다.

## 검증

- 서비스 테스트(댓글 검증·속도 제한·삭제 권한·좋아요 토글·내 소식 좋아요 거부·목록 구성·알림 수)와 라우트 테스트, 새 초기화 경로·마이그레이션, 프론트 타입 검사와 빌드. 화면은 사용자가 확인한다.
