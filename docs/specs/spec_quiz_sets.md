# 명세 — 객관식 퀴즈 세트

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-29). 시범: 세트 28 리눅스 명령어 확인 14문제(NFS 2문제 포함), 세트 29 k8s CKA 개념·명령 12문제.

## 배경과 목적

지금은 모든 문제가 터미널에서 직접 하는 실습형이다. **명령어를 알아보고, 출력을 읽고, 개념을 이해하는지** 확인하는 문제가 없다 (CKA 연습, KodeKloud 퀴즈처럼). 객관식은 실습으로 다루기 어려운 영역(대화형 명령, 컨테이너에서 못 도는 것, 개념, 장애 해석)을 채우고, 컨테이너 없이 풀어 서버 자원을 거의 쓰지 않는다.

## 원칙

- **퀴즈 세트**를 따로 둔다 (실습 세트에 섞지 않는다). 터미널과 컨테이너가 없다.
- 기록의 단위는 여전히 **세트 완료**다 ([spec_progress_dashboard.md](spec_progress_dashboard.md)). 한 번 입장한 세션에서 모든 문제를 맞히면 완료이고, 완료 기록·완료 화면·진행현황·리더보드를 그대로 쓴다.
- **정답과 해설은 서버만 안다.** 화면에는 선택지만 보내고, 정답을 맞힌 뒤에 해설을 돌려준다.
- 4지선다, 정답 하나로 시작한다. 단답형과 복수 선택은 후속.
- 해설이 핵심이다: 정답뿐 아니라 **오답이 왜 틀렸는지**를 쓴다 (찍어서 맞히는 것을 학습으로 바꾸기 위해). 문구 기준은 [spec_quest_writing_guide.md](spec_quest_writing_guide.md)를 따른다.

## 데이터

- `quest` 에 열 추가: `kind`('terminal' | 'choice', 기본 'terminal'), `choices`(JSON 배열), `answer_index`(0부터), `explanation`(해설). 객관식은 `grade_cmd`를 쓰지 않으므로 `[]`로 채운다 (기존 NOT NULL 제약 유지).
- `sandbox` 에 타입 `quiz`(이미지 없음)를 추가하고, 퀴즈 세트는 `sandbox_type='quiz'` 로 둔다.
- `GET /quest-sets/:id/quests` 는 객관식에 `kind`, `choices` 만 내보내고 `answer_index`, `explanation` 은 내보내지 않는다.

## 서버

`POST /quest-sets/:id/answer` `{ questId, sessionId, choiceIndex, elapsedSec, hintUsed }`:
- 접근 권한을 확인하고, 그 퀘스트가 그 세트의 객관식인지 DB로 확정한다.
- 정답 여부를 서버가 판정하고 `quest_attempt` 에 기록한다 (세트 완료 판정이 그대로 동작).
- 응답: `{ passed }`, 정답일 때만 `explanation` 포함.
- 선택지 번호가 범위를 벗어나면 400.

## 화면

- 퀴즈 세트는 터미널 없이 문제 화면이 넓게 보인다 (환경 준비 단계 없음).
- 설명(문제) → 선택지(A~D 버튼) → "정답 확인". 선택 후 정답이면 효과와 함께 해설이 열리고, 오답이면 흔들림 효과와 함께 그 선택지가 비활성화된다 (정답은 알려주지 않고 다시 고르게 한다). 힌트는 접고 펼 수 있다.
- 타이머, 정답·오답 효과, 세트 완료 화면은 실습 세트와 같다.

## 검증

- 서버: 정답 판정, 정답 노출 금지(문제 조회에 정답·해설 없음), 범위 밖 선택, 접근 권한, 객관식이 아닌 퀘스트 거부를 단위 테스트로 확인.
- 문제 내용: 명령 출력을 묻는 문제는 실제 컨테이너에서 실행해 정답을 검증한다 (`backend/verify/quiz*.json`의 증명 명령).

## 문제 추가 방법

1. `backend/db/03_quest_setNN.sql` 에 `kind='choice'` 문제를 쓰고(선택지 4개 JSON, `answer_index`, 해설은 `정답은 **B ...**` 로 시작해 오답이 왜 틀렸는지 설명), `02_quest_set.sql` 에 `sandbox_type='quiz'` 세트를 추가한다.
2. 같은 내용의 마이그레이션(`NOT EXISTS` 가드)을 `backend/db/migrations/` 에 추가한다.
3. 명령 출력을 묻는 문제는 `backend/verify/quiz-proofs.json` 에 증명 명령을 추가하고 `npm run verify:quiz` 로 확인한다 (`image: "host"` 는 이 컴퓨터에서 실행, 클러스터가 필요한 kubectl 용).
