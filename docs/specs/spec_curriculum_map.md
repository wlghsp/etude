# 명세 — 개념 지도와 선수 지식 점검

> 상태: **1차 점검과 보강 완료(로컬)** (2026-10-30)

## 목적

문제가 앞에서 배우지 않은 도구나 문법을 요구하지 않도록 점검한다. 방법: 학습 순서(`display_order`)대로 모든 문제의 풀이에서 **각 명령어·문법이 처음 쓰인 곳**과 **처음 가르친 곳**을 비교한다. (제목에 이름이 있거나 힌트가 그 명령을 설명하며 시작하는 곳을 "가르친 곳"으로 본다. 휴리스틱이라 잡음이 있어 사람이 판단한다.)

## 원칙

- 새 도구·문법은 **처음 쓰이는 문제의 힌트에서 한 줄 이상 설명**하거나, 그 앞에 가르치는 문제를 둔다.
- 목적이 "값 뽑기"가 아닌 문제는 추출 도구(`sed`, `awk`)를 요구하지 않는다 (세트 16·27 낮춤).
- 학습자 권한으로 할 수 없는 것(`kubectl get pods -A`, 네임스페이스·RBAC 만들기)은 실습으로 만들지 않고 객관식으로 다룬다.

## 1차 점검 결과 (리눅스 / k8s)

**이미 처음 쓰이는 문제의 힌트에서 설명하는 것 (조치 불필요):** `&&`(세트 1 #2), `*` 와일드카드(2 #9), `sed`(9 #3), `$( )`(3 #4), `nohup`(18 #8), `getent`(35 #5).

**한 번도 가르치지 않은 기본기 → 보강:**

| 빈틈 | 보강 |
|---|---|
| 절대·상대 경로, `.` `..` | 세트 1 #11 (실습), #12 (객관식) |
| 종료 코드 `$?` | 세트 1 #13 |
| 명령 도움말 `--help` | 세트 1 #14 |
| `nohup` (끊김 신호) | 세트 3 #12 |
| `kubectl edit` | 세트 19 #11 |

**이미 앞선 작업에서 채운 것:** 파이프·리다이렉션·`&&`·`||`(세트 34), 반복문(35), 이름으로 통신(36), k8s 통신(37), `ps` 정렬과 `pkill`(세트 3 #9~11), `gzip`·`gunzip`·`userdel`(7, 21).

**제외(이유):**
- `history`: 대화형 쉘에서만 동작해서 자동 채점 검증이 안 된다.
- `kubectl config set-context --namespace`: 학습자 kubeconfig 에 기본 네임스페이스가 이미 들어 있다.
- `kubectl get -A`, 네임스페이스·RBAC·ResourceQuota 만들기: 학습자 권한 밖이다 (격리 vcluster 세트가 생기면 다시 검토).
- `kubectl top`: 샌드박스 클러스터에 metrics-server 가 없다. `sudo`: 학습자가 root 라 의미가 없다.
- `less`, `htop`: 샌드박스에 없고 중요도가 낮다.
