# 명세 — Git 기록 살펴보기 세트 (log · show · diff · blame)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-12). 세트 365, 새 단원 `기록 살펴보기`(id 42, Git 분야, `display_order` 45), 세트 `display_order` 440, 아이콘 🔎. 근거: Git 실습 세트 52·53·54·56·94·95·96 은 만들기·브랜치·원격·되돌리기·.gitignore 를 다루지만 **기록을 읽는 법**(`log` 옵션, `show`, `diff` 두 종류, `blame`)을 한 흐름으로 묶은 실습은 없다. 겹침은 거의 없다(52·56 에서 `log`·`diff` 가 한두 문제 스치는 정도).

## 목표

고정된 작은 저장소(`/tmp/lab/proj`, 커밋 6개, 작성자 Ann·Bob, 이름이 바뀐 파일 1개, 스테이징 전·후 변경 1개씩)에서 "훑기 → 줄이기 → 거르기 → 한 커밋 보기 → 차이 보기 → 줄 단위 책임 찾기" 를 쌓는다.

## 원칙

- 터미널 9 + 객관식 1 + 빈칸 1 + 순서 1.
- setup 은 `/tmp/lab` 을 지우고 저장소를 다시 만든다. 커밋 작성자·날짜는 환경 변수로 고정해 해시가 매번 같다. 학습자 git 설정(user.name 등)에 기대지 않는다.
- 채점은 학습자가 저장한 파일을 **같은 git 명령의 실제 출력**(`git -C /tmp/lab/proj ...`)과 비교한다. 해시를 하드코딩하지 않는다. 줄 수도 함께 확인해 빈 파일을 거른다.
- 한계: 결과를 파일에 저장하는 문제라 다른 명령으로 같은 출력을 만들어도 통과한다(예: 같은 결과를 내는 다른 옵션 조합). 의도한 명령을 힌트와 해설로 안내한다.
- 가상 데이터만 쓴다(`example.com` 이메일). 네트워크 없음. 이미지 `etude-linux` 의 git 2.34 를 쓴다.
- 문서 링크: git-scm.com/docs 의 `git-log`·`git-diff`·`git-show`·`git-blame` (모두 200 확인).
