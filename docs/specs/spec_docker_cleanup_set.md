# 명세 — 도커 정리와 디스크 사용량 세트 (system df·container/image/volume/network prune·필터로 골라 지우기)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-12, 세트 352 · sandbox `docker` · 카테고리 `도커`). 근거: 정리 주제는 183·203·212·247·252·255 등이 객관식·빈칸으로만 다루고, 터미널 실습은 337(dangling 한 문제)·228(볼륨 prune 막힘)·97(종료 컨테이너 정리)에 한 문제씩뿐이다. 이 세트는 prune 계열을 **직접 실행해 무엇이 지워지고 무엇이 남는지**를 결과 상태로 확인하는 실습이다.

## 목표

`alpine` 만 써서 정리 명령을 하나씩 익힌다. `docker system df`(`--format`), `ps -a --filter status=`, `container prune`(`--filter label=`), 종료 코드 필터 + `docker rm $(...)`, 같은 태그로 다시 만들 때 생기는 이름 없는(dangling) 이미지, `image prune` 과 `-a`, `volume prune`(`-a`), `network prune`, `system prune --volumes`. prune 이 **지우지 않는 것**(실행 중 컨테이너, 사용 중 볼륨·네트워크·이미지)을 함께 확인한다.

## 원칙

- 터미널 실습은 **결과 상태**(남은 컨테이너·이미지·볼륨·네트워크, 저장한 파일)로 채점한다. `system df` 의 크기(바이트)는 환경마다 달라 채점하지 않고 **개수**만 쓴다(2번).
- setup 만 한 상태에서는 반드시 실패한다(대상이 아직 남아 있거나 결과 파일이 없다). setup 은 컨테이너·볼륨·네트워크·이미지·`/tmp/work` 를 비우고 `alpine` 을 다시 받아 여러 번 실행해도 안전하다. 이미지는 `alpine` 만 쓴다.
- 이름 없는 이미지는 `docker commit` 을 같은 태그로 반복해서 만든다(빌드 불필요). 채점은 `dangling=true` 이미지가 없는지로 한다.
- 9번은 도커 버전에 따라 `volume prune` 기본값(익명 볼륨만)이 다르므로, `-a` 를 쓰면 어느 쪽에서도 같은 결과가 되게 짰다. 검증 환경 docker:dind 29.9.3 에서 기본 `volume prune -f` 는 `data1` 을 남겨 실패함을 확인했다.
- 학습자의 dind 안에서만 지워진다. 호스트 도커에는 영향이 없다.
- 새 개념은 한 문제에 하나, 쉬운 것에서 어려운 것으로. 객관식은 정답을 첫 보기로 쓰고 헬퍼가 위치를 섞는다. 빈칸 11번 칩에는 두 번째 정답이 없다(`--volumes` 만 유효).

## 세트 구성 (12개: 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1)

| # | 형식 | 제목 | 새로 익히는 것 |
|---|------|------|----------------|
| 1 | 터미널 | 멈춘 컨테이너만 골라 이름 저장하기 | `ps -a --filter status=exited --format`, created 와 exited 구분 |
| 2 | 터미널 | 용량 요약을 내 형식으로 저장하기 (system df --format) | `system df --format '{{.Type}}: {{.TotalCount}}'`, 크기 대신 개수 |
| 3 | 터미널 | 멈춘 컨테이너 한꺼번에 정리하기 (container prune) | `container prune -f`, 실행 중은 남음 |
| 4 | 터미널 | 종료 코드로 골라서 지우기 (rm + filter) | `ps -aq --filter exited=1` + `docker rm $(...)` |
| 5 | 터미널 | 라벨로 범위를 좁혀 prune 하기 (--filter) | `container prune --filter label=` |
| 6 | 객관식 | 같은 태그로 다시 만들면 옛 이미지는 | 태그 이동, `<none>` 이미지, rmi 의 두 가지 |
| 7 | 터미널 | 이름 없는 이미지만 정리하기 (image prune) | dangling 만 지움, 태그 이미지 유지 |
| 8 | 터미널 | 쓰지 않는 이미지 모두 정리하기 (image prune -a) | `-a`, 컨테이너가 쓰는 이미지는 남음 |
| 9 | 터미널 | 쓰지 않는 볼륨 정리하기 (volume prune) | 사용 중(멈춘 컨테이너 포함) 볼륨 유지, 이름 있는 볼륨은 `-a` |
| 10 | 터미널 | 쓰지 않는 네트워크 정리하기 (network prune) | 연결된·기본 네트워크 유지 |
| 11 | 빈칸 | 볼륨까지 한 번에 정리 | `docker system prune --volumes` |
| 12 | 순서 | 디스크가 찼을 때 정리하는 순서 | df → 대상 확인 → 컨테이너 → 이미지 → 볼륨 → df |

## 겹침 점검

- **세트 337(이미지 관리, 터미널)**: 6번 "이름 잃은 이미지 정리"와 이 세트 7번이 **부분 겹침**이다. 7번은 같은 태그를 반복해 dangling 이 두 개 생기게 하고 "태그 이미지·alpine 이 남는다"까지 확인한다. 8번(`-a`, 사용 중 이미지 보존)과 6번 객관식(태그 이동)은 337 에 없다.
- **세트 228(볼륨·네트워크)**: 10번 "쓰는 중인 볼륨은 못 지운다", 11번 prune 미리보기와 주제가 인접하다. 이 세트 9번은 prune 의 **결과 상태**(멈춘 컨테이너가 쓰는 볼륨 유지, 익명·이름 있는 볼륨 `-a`)를, 10번은 `network prune` 을 직접 실행한다(228 은 network prune 없음).
- **세트 225·215(출력 뽑기)**: `ps --format·--filter` 는 공통이나 225 는 읽기 중심이다. 이 세트 1·4번은 필터 결과로 **지우는** 것이 목적이다(`exited=코드` 필터는 새로움).
- **세트 97 11번(종료된 컨테이너만 정리)**: 이 세트 3번과 겹친다(종료 컨테이너 일괄 정리). 3번은 `container prune` 전용 명령과 "실행 중은 남음"에 초점을 둔다.
- 객관식·빈칸이던 prune·system df·rmi 개념(142·183·203·212·247·252·255 등)은 이 세트가 터미널로 직접 해 보는 후속이다. 개념 문제와는 중복이지만 형식이 달라 허용한다.
