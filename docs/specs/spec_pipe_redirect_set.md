# 명세 — 리눅스 명령 연결하기: 파이프와 리다이렉션 (세트 34)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30)

## 배경과 목적

파이프(`|`), 리다이렉션(`>`, `>>`, `<`, `2>`, `2>&1`), `;` `&&` `||` 는 거의 모든 문제에서 쓰이지만 **따로 가르치는 문제가 없었다** (세트 3 #2 의 힌트 한 줄, 세트 28 #6 객관식 하나뿐). 학습자가 "알고 지나가는 줄 알았는데 사실 몰랐다"는 빈틈이다. `grep`·`awk`·`sort`·`for` 같은 도구는 이 연결 문법을 알아야 조합할 수 있다.

## 구성 (11문제, 실습 8 + 객관식 3)

| # | 내용 | 종류 |
|---|---|---|
| 1 | `ls \| wc -l` 로 파일 개수 세기 (파이프 = 앞 출력이 뒤 입력) | 실습 |
| 2 | 파이프 여러 번, `grep -v` 로 자기 자신 제외 | 실습 |
| 3 | `>` 덮어쓰기와 `>>` 이어쓰기 | 실습 |
| 4 | `wc -l < 파일` 로 파일 이름 없이 숫자만 | 실습 |
| 5 | `2>` 로 오류만 파일에 저장 | 실습 |
| 6 | 0·1·2 통로와 `> 파일 2>&1` 로 합쳐 저장 | 실습 |
| 7 | `&&` 앞 명령이 성공하면 이어서 | 실습 |
| 8 | `\|\|` 앞 명령이 실패하면 실행 | 실습 |
| 9 | `2>1` 의 함정(`1` 파일이 생김)으로 통로 번호와 `&1` 이해 | 객관식 |
| 10 | 파이프와 `;`·`&&` 의 차이를 직접 비교 | 객관식 |
| 11 | `yes \| head -n 3` 이 끝나는 이유(동시 실행, SIGPIPE) | 객관식 |

세트 3 과 세트 21 사이에 둔다 (`display_order` 35). 객관식은 터미널에서 직접 해 보고 고르며, 해설에 원리를 쓴다.

## 검증

- `검증됨`: `npm run verify:quests -- --set 34` 실습 8문제 통과(정답은 통과, 무행동은 실패), `npm run verify:quiz` 객관식 증명 56개 통과, `check-migrations.sh` 와 새 초기화 경로 통과, 백엔드 테스트 192개와 타입 검사 통과.
- 검증 도구 수정: `verify:quests` 는 객관식(`kind='choice'`)을 건너뛴다. 객관식은 채점 명령이 없고 `verify:quiz` 가 따로 검증하기 때문이다. 실습·객관식이 섞인 세트를 위해 필요했다.
- `미검증`: 실습과 객관식이 섞인 세트의 화면 흐름(문제마다 터미널이 새로 열리는지, 객관식에서 터미널이 함께 보이는지), 운영 컨테이너에서의 동작.
