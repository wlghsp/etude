# 명세 — 빈틈 보강 파일럿 세트 3개 (세트 502·503·504)

> 상태: **작성 중** (2026-11-19). 근거: `docs/research/content_gap_2026-11-19.md`, `gap_db.md`(M1·M2 필수), `gap_git.md`(인증·접근 필수).
> 목적: 새 실습 세트를 만드는 파이프라인(생성기 → `verify:quests` → 정확성 점검)을 3개로 먼저 확인한 뒤 병렬 확대한다.

## 공통 기준

- 계단식: 한 문제에 새 개념 1개, 기초 → 핵심 → 응용. 앞 문제에서 가르치지 않은 것을 전제하지 않는다.
- 한 세트에 형식 3종 이상(터미널 + 객관식 + 빈칸 + 순서). 객관식 정답 위치는 생성기 `POS` 규칙으로 분산.
- 현장 정보(IP·도메인·내부 이름) 금지. 예시는 `example.com`, 일반 이름만.
- 터미널 문제는 정답이 **결과물(파일 내용·DB 상태)** 에 남게 하고, 아무것도 안 하면 실패해야 한다.

## 세트 502 — 트랜잭션과 락 직접 만들어 보기 (`linux-db`, 단원 20 MariaDB 운영)

두 번째 세션은 터미널 하나에서 **백그라운드(`&`) 세션**으로 만든다. 선행: 세트 87(격리·MVCC 개념), 158·332(운영 SQL).

| # | 형식 | 개념 | 확인 |
|---|---|---|---|
| 1 | 실습 | `autocommit` 값 확인 | 파일에 1 |
| 2 | 실습 | `START TRANSACTION` → 변경 → `ROLLBACK` | 트랜잭션 안 값 ≠ 롤백 후 값 |
| 3 | 실습 | `COMMIT` 으로 이체 확정 | 잔액 이체 결과 |
| 4 | 실습 | `SAVEPOINT` 부분 롤백 | 최종 잔액 |
| 5 | 실습 | 다른 세션은 커밋 전 변경을 못 본다 | 파일에 원래 값 |
| 6 | 실습 | `SELECT ... FOR UPDATE` 행 락 + 락 대기 시간 초과 | 파일에 `Lock wait timeout exceeded` |
| 7 | 실습 | `information_schema.innodb_trx` 로 열린 트랜잭션 찾기 | 파일에 트랜잭션 상태 |
| 8 | 실습 | 오래 열린 세션을 `KILL` | 열린 트랜잭션 0개 |
| 9 | 실습 | 데드락 재현 | 파일에 `Deadlock found` |
| 10 | 객관식 | 데드락 예방(접근 순서 통일) | |
| 11 | 빈칸 | `SELECT ... {0}` 로 행 잠그기 | |
| 12 | 순서 | 이체 트랜잭션 단계 | |

## 세트 503 — MariaDB 문제 해결 상황집: 오류 메시지 읽고 고치기 (`linux-db`, 단원 20)

오류 메시지 → 원인 → 해결을 직접 재현·수정한다. 선행: 502, 158·332.

| # | 형식 | 상황 | 고치면 |
|---|---|---|---|
| 1 | 실습 | `ERROR 1045 Access denied` (설정 파일의 비밀번호가 틀림) | 설정 파일로 접속 성공 |
| 2 | 실습 | `ERROR 1049 Unknown database` (이름 오타) | 올바른 DB 로 조회한 결과 저장 |
| 3 | 실습 | `ERROR 1146 Table doesn't exist` (DB 를 안 고름) | 결과 저장 |
| 4 | 실습 | `ERROR 1062 Duplicate entry` (기본 키 중복) | 새 행이 들어감 |
| 5 | 실습 | `Too many connections` (연결이 가득) | 정리 후 일반 계정 접속 성공 |
| 6 | 실습 | `Lock wait timeout exceeded` 의 원인 세션 찾아 종료 | 대기하던 변경이 성공 |
| 7 | 객관식 | 오류 번호 ↔ 원인 짝 맞추기 | |
| 8 | 빈칸 | 접속 수 확인 변수 | |
| 9 | 순서 | 접속 안 될 때 확인 순서 | |

## 세트 504 — Git 인증·접근: SSH 키와 원격 주소 (`linux`, 단원 15 원격과 협업)

실제 원격 서버 없이 **로컬 경로 원격 + 키 파일** 로 가능한 범위만 실습한다(네트워크 인증 자체는 개념 문제로).

| # | 형식 | 개념 | 확인 |
|---|---|---|---|
| 1 | 실습 | `ssh-keygen -t ed25519` 로 키 쌍 만들기 | 개인키·공개키 파일 |
| 2 | 실습 | 개인키 권한 `600` | 권한 |
| 3 | 실습 | 공개키 vs 개인키(무엇을 등록하나) 내용 구분 | 파일 |
| 4 | 실습 | 원격 주소 https → ssh 형식으로 바꾸기 (`remote set-url`) | `remote -v` 값 |
| 5 | 실습 | `git config credential.helper` 설정 | 설정 값 |
| 6 | 실습 | 인증 실패 메시지 읽고 원인 분류 | 파일 |
| 7 | 객관식 | `Permission denied (publickey)` 원인 | |
| 8 | 빈칸 | 공개키 파일 확장자 | |
| 9 | 순서 | SSH 키로 첫 push 까지 순서 | |
