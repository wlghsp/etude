# 명세 — 인프라 대분류를 가상화·스토리지·네트워크로 나누기

> 상태: **구현 중(로컬)** (2026-11-13). 근거: 사용자 지적("인프라가 많이 비어있는데? 제목이 너무 방대하다, 나누는 게 좋지 않나?")과 선택("가상화 / 스토리지 / 네트워크 3개로 분할").

## 현황

- 대분류 `인프라` 는 세트가 3개뿐이다: 55(용어 지도: RHV·RHOV·OSP·OCP), 61(스토리지·네트워크: Ceph·Cinder·Neutron 구분), 117(인프라 장애 상황집).
- 이름이 가상화·스토리지·네트워크·장애 대응을 모두 가리켜서, 어떤 주제가 비어 있는지 보이지 않는다.
- 대분류는 `quest_set.category` 문자열이고, 프론트 5곳에 아이콘·색·순서가 하드코딩돼 있다.

## 결정

`인프라` 를 없애고 세 대분류로 나눈다. 기존 세트·단원은 아래처럼 옮긴다.

| 세트 | 새 대분류 | 단원 |
|---|---|---|
| 55 용어 지도 | 가상화 | `용어 지도` (id 16, 대분류만 바꿈) |
| 61 스토리지·네트워크 구분 | 스토리지 | `스토리지 기초` (id 21, 이름을 `스토리지·네트워크·클라우드` 에서 바꿈) |
| 117 장애 상황집(이름·포트·시간·MTU) | 네트워크 | `연결이 안 될 때` (새 단원 id 43) |

- 세트 번호·`display_order`·아이콘·공개 여부·문제는 바꾸지 않는다. 학습 기록(`set_completion`, `quest_attempt`)은 세트 번호로 연결돼 있어 영향이 없다.
- 세트 제목의 "인프라" 접두어는 이번에 바꾸지 않는다.

## 프론트

- `characters.ts`(분야 정복 캐릭터), `Admin.tsx`(`CATEGORY_ORDER`), `SetSelect.tsx`(`CATEGORY_META` 아이콘·색), `Review.tsx`(아이콘), `FeedTab.tsx`(글자 색)에서 `인프라` 를 세 분야로 바꾼다.
- 색은 아직 쓰지 않은 토큰을 쓴다: 가상화 `coral`(기존 인프라 색 유지), 스토리지 `gold`, 네트워크 `success`.
- 아이콘: 가상화 🖥️, 스토리지 💾, 네트워크 🌐. 캐릭터: 가상화 🔮 수정구, 스토리지 📦 보관 상자, 네트워크 🧭 나침반.

## 반영 방식

- 새 DB: `02_quest_set.sql` 의 세트 55·61·117 대분류를 직접 바꾸고, `06_units.sql` 에 단원 변경을 덧붙인다.
- 기존 DB: `backend/db/migrations/2026-11-13_split_infra_category.sql` (여러 번 실행해도 안전: 조건 `WHERE` 와 `NOT EXISTS`).

## 하지 않는 것

- 새 퀘스트 세트 추가(이 변경 뒤에 분야별로 채운다). 대분류 공개 제어(`spec_visibility_categories.md`, 별도 결정 대기).
