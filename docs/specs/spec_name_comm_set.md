# 명세 — 리눅스 이름으로 통신하기 (세트 36)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30)

## 배경과 목적

서버끼리 통신하게 만들 때 `/etc/hosts` 에 이름을 적는 일이 매우 잦다. 지금까지는 등록 한 줄을 하는 문제가 두 개(세트 18 #7, 세트 10 #5)와 원리 객관식(세트 32 #6)뿐이었다. 여러 서버 등록, 별칭, IP 변경, 백업과 복구, 이름으로 포트 확인, 오류 메시지로 문제 단계 구분까지 **통신을 되게 만드는 흐름**을 연습한다.

## 원칙

- **방법은 자유, 채점은 결과만 본다.** `vi` 로 직접 고쳐도, `echo >>` 로 추가해도, 임시 파일로 덮어써도 된다.
- 힌트는 **쉬운 방법**을 앞에 둔다. 이 세트는 `sed` 를 선수 지식으로 요구하지 않는다 (`sed` 는 세트 15 에서 배운다).
- `getent hosts 이름` 은 이 세트의 첫 문제에서 소개한다 (시스템이 실제로 이름을 해석하는 방식 그대로 IP 를 보여 준다).
- 컨테이너 환경의 사실: `/etc/hosts` 는 Docker 가 연결한 특수 파일이라 `sed -i` 는 "Device or resource busy" 로 실패한다 (`vi` 저장, `cat > /etc/hosts`, `cp` 는 된다). 힌트에는 쓰지 않고 풀이의 주석에만 짧게 남긴다.

## 구성 (8문제, 실습 5 + 객관식 3)

| # | 내용 | 종류 |
|---|---|---|
| 1 | 서버 3대를 한 번에 등록 (`>>` 이어쓰기, `>` 의 위험), `getent` 소개 | 실습 |
| 2 | 한 IP 에 이름 여러 개 (별칭) | 실습 |
| 3 | 서버를 옮긴 뒤 옛 IP 줄을 새 IP 로 고치기 (한 이름 = 한 IP) | 실습 |
| 4 | 같은 이름이 두 줄이면 IP 두 개로 해석되는 문제 읽기 | 객관식 |
| 5 | 이름 등록 후 `nc -zv 이름 포트` 로 접속 확인, 결과를 `2>&1` 로 저장 | 실습 |
| 6 | 고치기 전 백업, 수정, 복구 | 실습 |
| 7 | `Could not resolve host` 와 `Connection refused` 가 가리키는 단계 구분 | 객관식 |
| 8 | 접속 장애를 좁히는 순서 (이름 → 경로 → 포트 → 서비스) | 객관식 |

세트 18(네트워크 진단) 바로 뒤에 둔다 (`display_order` 115). `ping`·`traceroute`·`nslookup` 은 샌드박스 이미지에 없어 쓰지 않았다.

## 검증

- `검증됨`: `verify:quests --set 36` 실습 5문제 통과, `verify:quiz` 객관식 증명 통과(전체 63개), `check-migrations.sh` 통과. 방법이 자유임을 확인: 같은 컨테이너에서 `vim` 저장, 임시 파일 덮어쓰기, `cp` 복구가 동작.
- `미검증`: 화면 흐름, 운영 컨테이너에서의 동작, `vi` 로 직접 편집해 저장하는 실제 대화형 흐름(ex 모드로만 확인).
