# 명세 — 세트 이어 풀기

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-10). 열린 결정 3가지는 기본안으로 확정(사용자 위임). 근거: 피드백 #8 ("중간까지 풀어도 기록이 남고, 다시 돌아오면 거기서부터 풀 수 있어야 한다").

## 배경과 목적

지금은 세트에 들어올 때마다 화면이 새 세션 ID 를 만들고, 완료 판정은 **같은 세션 안에서 모든 문제를 통과**해야 한다 ([spec_progress_dashboard.md](spec_progress_dashboard.md)). 그래서 일부만 풀고 나갔다가 다시 들어오면 처음부터 다시 풀어야 하고, 나가기 전에 "지금까지 푼 N개가 기록되지 않아요"라는 경고가 뜬다. 문제가 30개 안팎인 세트에서는 이것이 가장 큰 불편이다.

목표는 한 가지다: **세트에 다시 들어오면 푼 문제는 건너뛰고, 아직 못 푼 첫 문제부터 이어서 푼다.** 세트를 모두 통과했을 때 완료 기록이 남는 규칙, XP·랭킹·피드의 기준은 바꾸지 않는다.

## 원칙

- 기록의 단위는 계속 **세트 완료**다. 이 명세는 "완료하지 못한 세션을 다음 방문에서 이어 쓸 수 있게" 하는 것뿐이다. 되돌리기(`d32933f` 이전의 문제 단위 진행률)가 아니다.
- **새 테이블·열을 만들지 않는다.** 이미 있는 `quest_attempt`(문제별 통과 기록, `session_id` 포함)와 `set_completion`(세션별 완료)에서 이어 풀 세션을 구한다. 정보를 두 곳에 두지 않는다.
- 이어 풀 세션은 **서버가 정한다.** 화면이 임의의 세션 ID 를 주장하지 못한다 (본인 기록만, 아래 조건을 만족하는 것만).
- 건너뛴 문제는 통과가 아니다. 이어 풀 때 "못 푼 문제"로 남아 있고, 세트 완료에는 모든 문제의 통과가 필요하다.

## 이어 풀 세션의 조건

`GET /quest-sets/:id/resume` 가 아래를 모두 만족하는 **가장 최근 세션 하나**를 돌려준다.

1. 요청한 사람의 `quest_attempt` 에서 이 세트의 세션이고, 통과한 시도가 **1건 이상** 있다.
2. 그 세션이 `set_completion` 에 없다 (이미 완료한 세션은 닫힌 것으로 본다. 다시 들어오면 새 세션이다 — 복습 XP 규칙 그대로).
3. 마지막 시도가 **보관 기간(기본 30일)** 이내다.
4. 세트가 이어 풀기 대상이다:
   - **제외:** 시험형 세트(`time_limit_sec` 이 있음. 제한 시간이 세션에 묶여 있다), `docker-persistent` 세트(앞 문제에서 바꾼 컨테이너 상태가 다음 문제의 전제라서, 새 컨테이너로 이어 풀 수 없다).
   - 나머지(퀴즈, 문제마다 새 컨테이너를 쓰는 실습 세트)는 대상이다.

응답: `{ sessionId: string | null, passed: { questId, seconds, hintUsed, solutionUsed, attempts }[] }` (문제 순서대로). `passed` 의 값은 세트 완료 요약과 같은 규칙으로 센다: 통과한 시도 중 가장 짧은 시간의 시도가 시간·힌트·풀이 사용을 정하고, `attempts` 는 그 세션에서 그 문제의 전체 시도 수다. 조건에 맞는 세션이 없으면 `sessionId: null`, `passed: []`. 접근 권한은 세트 문제 조회(`GET /quest-sets/:id/quests`)와 같은 규칙을 쓴다. 정답·해설은 돌려주지 않는다.

## 화면

세트에 들어와 문제 목록을 받은 뒤:

1. `GET /quest-sets/:id/resume` 를 호출한다.
2. `sessionId` 가 있으면 **그 세션 ID 를 그대로 쓴다.** `POST /quest-sets/:id/start` 도 그 ID 로 호출한다. 푼 문제(`passed`)는 완료로 표시하고 문제별 기록(`records`)을 채운다. 완료 요약 화면이 `records` 로 그려지므로 이 값이 없으면 요약·완료 연출이 어긋난다. 문제 위치는 **못 푼 첫 문제**로 둔다.
3. 없으면 지금처럼 새 세션을 만든다.
4. 이어 풀기로 들어왔을 때 짧게 알린다: "지난번에 푼 N/M개를 이어서 풀어요".
5. 모든 문제가 이미 통과 상태인데 완료 기록이 없다면(완료 저장 직전에 닫은 경우), 지금의 "모두 통과하면 완료 저장" 흐름이 그대로 완료를 저장한다.
6. 나가기 경고(`leaveGuard`)는 이어 풀기 대상 세트에서는 **없앤다** (나가도 푼 문제가 저장되므로 막을 이유가 없다. 다음에 들어오면 4번 안내가 뜬다). 제외 대상 세트(시험형, `docker-persistent`)에서는 지금 문구를 유지한다. 화면은 시험형 여부를 `run`, 컨테이너 상태 의존 여부를 `sandboxType` 으로 판단한다.

이어 풀기로 불러온 문제의 문제별 타이머는 다시 돌리지 않는다 (이미 통과한 문제다).

## 하지 않는 것 (후속)

- "처음부터 다시" 버튼: 아직 완료하지 않은 세션을 버리는 기능은 이번에 넣지 않는다. 완료한 뒤에는 새 세션이 시작되므로 복습은 이미 가능하다.
- 홈 카드·진행 화면에 "진행 중 N/M" 표시.
- 문제 단위 진행률을 랭킹·XP 에 반영하는 것 (세트 완료 기준 유지).

## 열린 결정 (사용자 확인 필요)

| 결정 | 기본안 |
|------|--------|
| 이어 풀 수 있는 보관 기간 | 30일 (피드백 첨부 보관 기간과 같은 값) |

## 수용 조건

서버 (자동 테스트):
- [x] 통과 기록이 1건 이상이고 완료되지 않은 가장 최근 세션을 찾는다.
- [x] 완료한 세션(`set_completion` 있음)은 찾지 않는다. 그 뒤에 쓴 새 세션이 있으면 그것을 찾는다.
- [x] 통과 기록이 하나도 없는 세션은 찾지 않는다.
- [x] 보관 기간을 넘긴 세션은 찾지 않는다.
- [x] 다른 사람의 세션은 찾지 않는다.
- [x] 시험형 세트와 `docker-persistent` 세트는 `sessionId: null` 이다.
- [x] `passed` 는 그 세션의 통과 문제만 중복 없이, 문제 순서대로 담고, 값은 완료 요약과 같은 규칙(가장 짧은 통과 시도, 전체 시도 수)이다. 통과하지 못한 문제는 담지 않는다.
- [x] 접근 권한이 없는 세트는 거부한다.
- [x] 이어 푼 세션에서 남은 문제를 모두 통과하면 `POST /complete` 가 완료를 한 번만 저장한다 (`set-completion` 은 세션 단위로 기존 테스트가 보장하고, 이 변경은 `buildCompletion` 의 동작을 바꾸지 않는다).

화면 (수동 확인):
- [ ] 일부만 풀고 나갔다가 다시 들어오면 푼 문제가 완료로 표시되고 못 푼 첫 문제에서 시작한다.
- [ ] 나머지를 풀면 세트 완료 화면이 나오고 완료 기록이 1건 남는다.
- [ ] 이미 완료한 세트에 다시 들어가면 처음부터 시작한다.
- [ ] 시험형·`docker-persistent` 세트는 지금과 같다.
