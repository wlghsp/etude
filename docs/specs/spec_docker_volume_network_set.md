# 명세 — 도커 볼륨과 네트워크 실습 세트

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 근거: 기존 `네트워크와 볼륨` 세트(142, 179, 209)는 객관식·빈칸·순서 위주라 직접 명령을 치는 훈련이 없다. 도커 터미널 세트 5(`-v` 한 문제)·8·11 도 볼륨·네트워크를 깊게 다루지 않는다. 이 세트는 **결과로 채점하는 터미널 실습**으로 같은 주제를 몸에 익힌다.

## 목표

볼륨을 만들고 `inspect -f` 로 저장 위치를 찾고, 컨테이너를 지워도 데이터가 남는 것을 직접 확인한다. 바인드 마운트·읽기 전용(`:ro`)과 비교하고, 직접 만든 브리지 네트워크에서 컨테이너를 **이름으로** 부르는 것(ping), 기본 네트워크 컨테이너를 `network connect` 로 붙이는 것, 쓰는 중인 볼륨이 지워지지 않는 이유를 찾아 정리하는 것까지 익힌다.

## 원칙

- 터미널 실습은 결과 파일·상태의 **내용**으로 채점한다 (파일 존재만 보지 않는다). setup 만 한 상태에서는 반드시 실패한다.
- 새 개념은 한 문제에 하나. 쉬운 것에서 어려운 것으로.
- 이미지는 `alpine` 하나만 쓴다. 호스트 경로는 쓰지 않고 샌드박스(dind) 안의 `/tmp` 만 쓴다.
- IP 는 `.NetworkSettings.IPAddress` 대신 이름으로 통신을 확인한다 (새 Docker 는 최상위 IPAddress 가 없다).
- 기존 세트 142·179·209 와 겹치는 개념 문제(객관식 등)는 새로 만들지 않고, 볼륨 prune 후보 확인(`-f dangling=true`)·`--filter volume=` 처럼 실습에서만 나오는 도구를 다룬다.

## 세트 구성 (12개: 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1)

| # | 형식 | 제목 | 새로 익히는 것 |
|---|------|------|----------------|
| 1 | 터미널 | 볼륨 만들고 목록 보기 | `docker volume create`, `volume ls -q` |
| 2 | 터미널 | 볼륨이 놓인 위치 찾기 | `docker volume inspect -f '{{.Mountpoint}}'` |
| 3 | 터미널 | 컨테이너를 지워도 남는 데이터 | `-v 볼륨:경로` 로 쓰고, `--rm` 후 새 컨테이너로 읽기 |
| 4 | 터미널 | 호스트 폴더를 붙이기 (바인드 마운트) | `-v /경로:/경로`, 안에서 만든 파일이 밖에서 보임 |
| 5 | 터미널 | 읽기 전용으로 붙이면 쓰기가 막힌다 | `:ro`, `Read-only file system` 오류 |
| 6 | 빈칸 | 네트워크 만들기 | `docker network create 이름` |
| 7 | 터미널 | 같은 네트워크에 두 컨테이너 띄우기 | `--network`, `docker network inspect` |
| 8 | 터미널 | 이름으로 부르기 | `docker exec web ping -c 1 db` (이름 해석) |
| 9 | 터미널 | 기본 네트워크에 있는 컨테이너 연결하기 | `docker network connect` |
| 10 | 터미널 | 쓰는 중인 볼륨은 못 지운다 | `volume rm` 의 "in use" 오류, `ps -a --filter volume=` |
| 11 | 객관식 | prune 전에 지워질 볼륨 미리 보기 | `docker volume ls -f dangling=true` |
| 12 | 순서 | 막힌 볼륨 지우기 흐름 | 오류 확인 → 쓰는 컨테이너 찾기 → 정리 → 삭제 → 확인 |
