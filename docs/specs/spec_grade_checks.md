# 명세 — 조건별 채점 결과

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-10-30). 참고: KodeKloud 의 Check 결과(조건마다 통과 표시).

## 목적

지금은 채점 결과가 "맞았어요/틀렸어요" 하나뿐이라, 여러 조건 중 **어느 것이 남았는지** 알 수 없다. 조건마다 통과/미통과를 보여 주어 어디를 고쳐야 하는지 바로 알게 한다.

## 데이터

- `quest.checks` (JSON, 선택): `[{ "label": "조건 이름", "cmd": ["sh", "-c", "채점 명령"] }, ...]`. 없으면 지금처럼 `grade_cmd` 하나로 채점한다.
- 조건이 있는 문제는 **모든 조건이 통과해야 정답**이다. `grade_cmd` 는 같은 조건을 `&&` 로 이은 것과 같게 둔다 (`verify:quests` 와 조건 목록이 어긋나지 않게).
- 조건 목록은 한 곳(`backend/db/07_quest_checks.sql`)에서 관리하고 같은 내용의 마이그레이션(`2026-10-30_quest_checks.sql`)을 둔다. 새로 조건 목록이 필요한 문제는 이 파일에 추가한다.
- 채점 명령의 제한은 기존과 같다: 조건 하나당 15초, `$NS` 는 세션 네임스페이스로 바뀐다.

## API

- `POST /grade` 응답: 조건이 있으면 `{ passed, checks: [{ label, passed }, ...] }`, 없으면 `{ passed }`.
- `GET /quest-sets/:id/quests` 의 각 문제에 `check_labels`(조건 이름 배열 또는 null)를 더한다. **채점 명령(`cmd`)은 내보내지 않는다.**

## 화면

문제 탭의 채점 버튼 위에 **완료 조건** 목록이 보인다. 채점하기 전에는 빈 원, 채점하면 조건마다 초록 체크 또는 빨간 엑스와 `n/m 통과`가 표시되고, 실패하면 "빨간 표시가 된 조건을 확인하고 다시 시도해 보세요"라고 안내한다.

## 적용한 문제 (9개, 조건이 여럿인 것부터)

세트 3 #9·#10(`ps` 열과 정렬), 33 #5(PVC)·#7(컨테이너 2개 Pod), 36 #1·#2·#3·#6(`/etc/hosts` 4개), 37 #2(Pod IP 변화). 나머지 문제는 점차 추가한다.

## 검증

- `검증됨`: 백엔드 테스트(조건별 실행·`$NS` 치환·checks 없음·JSON 깨짐·조회 시 `cmd` 비노출·응답 형태) 포함 전체 203개 통과, `verify:quests` 세트 3·36 통과, 리눅스 조건 6문제를 컨테이너에서 개별 실행(풀이 후 모두 통과, 풀기 전 일부 실패), `check-migrations.sh` 통과, 프론트 타입 검사와 빌드.
- `미검증`: 화면에서의 모습, 운영 동작, k8s 세트(33·37)의 조건 개별 실행 (조건을 `&&` 로 이은 `grade_cmd` 는 `verify:quests` 로 확인).
