# 명세 (보류) — 학습 기록 메일 발송

> 상태: **보류** (2026-10-29, 사용자 결정). 코드는 없다. 발송 방법과 회사 정책 확인이 필요해서 나중에 다시 꺼낸다.

## 목적

어제 문제를 푼 흔적이 있는 사용자에게 다음 날 아침 학습 기록(통계)을 메일로 보내 학습 동기를 주고 다시 들어오게 유도한다. 아이디가 회사 이메일이라 별도 수집이 필요 없다. 수신 거부 기능은 필수다.

## 설계안

- **대상:** 어제(한국 시간 기준) `quest_attempt` 기록이 있고, 수신 거부를 안 했고, 오늘 아직 발송하지 않은 사용자.
- **내용:** 어제 완료한 세트와 걸린 시간, 힌트·풀이 없이 푼 개수, 지금까지 완료한 세트 수(`n/전체`), 이번 주 완료 횟수. 세트를 시작만 하고 끝내지 못했으면 "시작한 세트를 완료해 보세요" 한 줄. 세트 단위 기록 원칙([spec_progress_dashboard.md](spec_progress_dashboard.md))에 따라 문제 단위 통계나 순위, 다른 사람과의 비교는 넣지 않는다.
- **실행:** 백엔드가 정해진 시각(제안: 평일 8:30 KST)에 한 번 실행. 서버 시간대가 UTC일 수 있어 "어제"는 KST로 계산.
- **중복 방지:** 발송 기록 테이블 `(user_id, 날짜)` 고유 → 재시작·중복 실행에도 하루 1통.
- **수신 거부:** 메일 맨 아래 "수신 거부" 링크(로그인 없이 한 번 클릭, 서명된 토큰)와 앱 설정 스위치. 메일 헤더에 `List-Unsubscribe`도 넣는다.
- **안전한 시작:** 처음에는 "보내지 않고 로그와 미리보기만" 하는 모드. 관리자가 자기 메일로 시험 발송.
- 메일 라이브러리 `nodemailer` 의존성 추가 (리뷰 대상).

## 정해야 할 것 (보류 이유)

1. **발송 방법:** 회사 SMTP 중계 서버(권장, IT에 서비스용 발송 계정 확인) 또는 OCI Email Delivery 같은 외부 서비스(보내는 도메인 `etudequest.com`에 SPF·DKIM 설정 필요, 서버에서 25번 포트는 기본 차단이라 587 인증 방식). SMTP 계정과 비밀번호는 사용자가 서버 설정(`.env.prod`)에 직접 넣는다 (AI는 비밀번호를 다루지 않는다).
2. **기본값:** 기본 켬 + 쉬운 거부(추천) 또는 동의해야 켬. 직원 이메일로 자동 발송하므로 회사 정책(인사·보안팀) 확인 권장 — 광고성이 아니라는 점과 수신 거부 링크 유무.
3. **빈도:** 활동한 다음 날 1통 + 안 받음(추천), 필요하면 매일/주 1회 요약 선택지.
4. **발송 시각.**

## 진행 순서 제안

1. 외부 설정 없이 가능한 부분: 수신 거부 컬럼·링크·설정 스위치, 발송 기록 테이블, 대상 선정 쿼리, 본문 템플릿과 관리자 미리보기, 예약 실행(로그 전용 모드).
2. 발송 방법이 정해지면 SMTP 설정을 넣고 시험 발송 후 실제 발송을 켠다.
