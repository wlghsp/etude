# 명세 — 도커 이미지 관리와 옮기기 실습 세트 (pull 태그·images --format·tag·rmi·prune·commit·save/load·export/import)

> 상태: **구현 완료(로컬), 화면 확인 대기** (2026-11-11). 근거: 이미지 관리는 퀴즈형 세트 183·203·218(분할판 포함)이 다루고, 세트 8 은 영속 터미널에서 save/load 를 순서대로 따라 하는 실습이다. 이 세트는 **`alpine` 만으로 작은 상태를 만들고 결과 상태(이미지·태그·tar 목록·컨테이너 수)로 채점**하는 드릴이라는 점에서 다르다.

## 목표

특정 태그 받기, `images --format`, `tag`(이름만 늘어남), `rmi`(태그만 떼기, 컨테이너가 쓰면 막힘), dangling 이미지 `prune`, `commit`, `inspect -f`, `save`/`load`, `export`/`import` 가 이미지 상태에 어떤 결과를 남기는지 직접 확인한다.

## 원칙

- 터미널 실습은 **결과 상태**(이미지 존재와 태그, 같은 ID, tar 안 목록 `tar tf`, 컨테이너 유무, 파일 내용)로 채점한다. setup 만 한 상태에서는 반드시 실패한다.
- 새 개념은 한 문제에 하나. 쉬운 것에서 어려운 것으로.
- 이미지는 `alpine` 만 쓰고 네트워크 설치는 하지 않는다. setup 은 컨테이너·이미지·`/tmp/work` 를 비우고 `alpine` 을 다시 받아 여러 번 실행해도 안전하다.
- 진행 출력이나 정확한 바이트 크기에는 의존하지 않는다.
- 세트 8·183·203·218 과 겹치지 않도록 터미널은 상태 채점 드릴에 집중하고, 객관식·빈칸·순서는 최소한만 둔다.

## 세트 구성 (12개: 터미널 9 + 빈칸 1 + 객관식 1 + 순서 1)

| # | 형식 | 제목 | 새로 익히는 것 |
|---|------|------|----------------|
| 1 | 터미널 | 태그를 지정해서 이미지 받기 | `pull 이름:태그` |
| 2 | 터미널 | 이미지 목록을 이름:태그로 저장 | `images --format` |
| 3 | 터미널 | 이미지에 별명 붙이기 (tag) | `tag`, 같은 ID |
| 4 | 객관식 | 태그를 지우면 이미지도 지워질까 | `rmi` 는 이름표만 뗌 |
| 5 | 터미널 | 컨테이너가 쓰는 이미지 지우기 | 사용 중 이미지 `rmi` 오류, 컨테이너 먼저 삭제 |
| 6 | 터미널 | 이름 잃은 이미지 정리 (dangling) | `image prune -f` (`-a` 아님) |
| 7 | 터미널 | 컨테이너를 새 이미지로 만들기 (commit) | `commit` |
| 8 | 빈칸 | 이미지 ID 만 뽑아 보기 | `image inspect -f` |
| 9 | 터미널 | 이미지를 tar 파일로 저장 (save) | `save -o`, `tar tf` |
| 10 | 터미널 | tar 파일에서 이미지 불러오기 (load) | `load -i` |
| 11 | 터미널 | 컨테이너 파일시스템을 내보내고 이미지로 (export, import) | `export -o`, `import` |
| 12 | 순서 | 이미지를 다른 서버로 옮기는 흐름 | save → 전달 → load → images → run |
