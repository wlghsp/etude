### Step 6-1 (터미널 WebSocket) 완료

`TerminalWebSocketHandler`, `ContainerRuntime`의 attach/exec 스트림 브리징
(`AttachTerminalStream`/`ExecTerminalStream`, `PipedInputStream`/`PipedOutputStream`으로
push↔pull 불일치 해소), sandbox `default`/`docker`/`docker-persistent` 분기 구현.

- `SandboxType`을 sealed interface로 설계(`Docker(val persistent: Boolean)`가
  `docker`/`docker-persistent`를 하나의 타입으로 흡수) — enum + Map 전략 패턴 대신
  `TerminalSessionService.open()`의 exhaustive `when`으로 디스패치해 컴파일 타임에
  누락 케이스를 잡도록 함.
- 실제 WebSocket 클라이언트(Node.js `ws`)로 수동 검증하다가 두 가지 버그 발견 후 수정:
  1. `openDocker()`가 `docker:dind`(Alpine, bash 없음)에 `/bin/bash`를 exec하려다 실패 →
     `/bin/sh`로 수정
  2. WebSocket 세션에 대한 동시 `sendMessage` 호출이 겹쳐 `IllegalStateException
     (BINARY_PARTIAL_WRITING)` 발생 → `connected` 메시지를 `onOutput` 콜백 등록보다
     먼저 보내고 `synchronized(session)`으로 직렬화

### 프론트엔드 API 어댑터 계층 추가 (Step 10 조기 적용)

명세상 Step 1~9는 프론트를 안 건드리는 게 원칙이지만, `ApiResponse({meta,data})` 래퍼
때문에 브라우저 수동 검증 자체가 불가능하다는 게 드러나 조기에 어댑터를 추가하기로 결정.

- `frontend/src/api/base.ts`에 `apiFetch` 공통 헬퍼 추가 — `{meta,data}` 언래핑
- 필드명 표기법 처음엔 전역 snake_case 변환을 검토했으나, 원본 Node.js가 엔드포인트마다
  표기법이 제각각(`/progress`는 `quest_set_id`, `/leaderboard`는 `questSetId`)이라
  일괄 변환이 오히려 새 불일치를 만든다는 걸 원본 코드로 확인 → **camelCase로 통일**하는
  방향으로 결정. `types.ts`, `SetSelect.tsx`, `Progress.tsx`, `Admin.tsx`의 필드 참조를
  camelCase로 함께 갱신.
- 가이드: `docs/guides/guide_phase12_frontend_api_adapter.md` 신규 작성.
