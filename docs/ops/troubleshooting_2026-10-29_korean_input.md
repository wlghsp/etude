# 터미널에서 한글을 치면 입력이 깨지고 `(arg: 1)` 이 나타남

## 증상

퀘스트 터미널(리눅스 세트)에서 한글을 입력하면 글자가 입력되지 않고, 프롬프트 줄에 `(arg: 1)` 같은 글자가 나타나면서 커서가 제자리에서 도는 것처럼 동작한다. 영어는 정상이다.

## 원인 (쉬운 설명)

터미널 안의 프로그램(bash)은 "지금 쓰는 글자 체계(로캘)"를 환경변수 `LANG` 으로 알아낸다. 우리 샌드박스 컨테이너에는 `LANG` 이 비어 있어서 가장 오래된 영어 전용(ASCII) 설정으로 동작했다.

한글 한 글자는 컴퓨터 안에서 3바이트로 보내지는데(예: `가` = `EA B0 80`), 영어 전용 설정의 bash 는 이 바이트를 한글이 아니라 "Alt 키를 누르고 친 영문·숫자"로 잘못 읽는다. 그중 `B0`~`B9` 는 "Alt+숫자" 로 읽혀서, bash 가 "다음 명령을 몇 번 반복할지 입력 중"인 **숫자 인자 모드**(`(arg: 1)`)로 들어가 버리고, 이후 입력이 전부 이상해진다.

## 확인한 방법

호스트에서 실제 터미널(pty)을 열어 컨테이너의 bash 에 한글을 한 글자씩 타이핑했다.

| 설정 | 화면에 나온 결과 |
|---|---|
| `LANG` 없음 | `(arg: 1) 0) bash-5.1#  abc` (깨짐, 증상 재현) |
| `LANG=C.UTF-8` | `가나다 abc` (정상) |

`locale charmap` 으로도 확인: `LANG` 없음은 `ANSI_X3.4-1968`(ASCII), `LANG=C.UTF-8` 은 `UTF-8`. Ubuntu(리눅스 세트)와 Rocky(systemd 세트) 이미지 모두 `C.UTF-8` 이 들어 있다. Alpine(k8s) 이미지는 원래 UTF-8 로 동작해 영향이 없었지만 같이 설정했다.

## 해결

모든 샌드박스 컨테이너를 만들 때 환경변수 `LANG=C.UTF-8` 을 준다 (`backend/src/services/terminal.ts` 의 `SANDBOX_ENV`). 이미지를 다시 빌드할 필요가 없다. 테스트(`terminal.test.ts`)가 모든 샌드박스 종류에 `LANG` 이 들어가는지 확인한다.

## 알아 둘 점

- **새로 열리는 터미널부터** 적용된다. 이미 열려 있는 터미널은 세트에서 나갔다 다시 들어오거나 "환경 초기화"를 해야 고쳐진다.
- 한글을 직접 치는 퀘스트는 거의 없지만, 파일 이름·주석·메모에 한글을 쓰거나 한글이 든 로그를 볼 때도 같은 문제가 있었다.
