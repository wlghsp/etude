### A. 단원 목록 React 중복 key 경고 ✅ 수정함 (미커밋)

- 수정: `frontend/src/units.ts` 의 `groupByUnit` 이 같은 단원을 첫 위치에 한 묶음으로 모음. 테스트 `frontend/src/units.test.ts` 추가(RED 2개 실패 → GREEN).
- 로컬 확인: 10개 코스 모두 중복 머리글 0, 코스 순회 후 콘솔 경고 증가 없음. 진행현황(`Progress.tsx`)도 같은 함수를 써서 함께 해결됨(화면은 미확인).
- 근본 원인은 데이터: 옛 단원에 새 세트를 넣으면서 `display_order` 를 끝쪽으로 둬 단원이 갈라짐(`spec_units.md:17` 위반). 새 세트 추가 시 계속 재발할 수 있음.

(수정 전 기록)
- 콘솔: `Encountered two children with the same key` (key 값 55, 56, 57, 58, 2, 3, 4, 32, 33, 66, 67, none)
- 위치: `SetSelect.tsx:205`, `Progress.tsx:188` 의 `key={g.unitId ?? 'none'}`
- 원인(코드상 확인됨): `groupByUnit`(`units.ts`)은 **연속된 세트만** 한 단원으로 묶는다. 한 단원의 세트가 `display_order` 상으로 떨어져 있으면 같은 `unitId` 그룹이 두 번 생겨 key가 겹친다.

### D. 모바일(375px) 홈이 가로로 넘침 ✅ 수정함 (미커밋)
- 수정: `pages/pathLayout.ts`(배치 계산, 테스트 `pathLayout.test.ts` 4개) + `SetPath.tsx` 가 컨테이너 폭을 재서 480px 미만이면 좁은 배치(중심·굽이침·노드 크기 축소, 제목 2줄, 다음 추천 말풍선 생략)를 씀. 컨테이너는 `width:100%; maxWidth:520`.
- 로컬 확인: 375px 에서 `scrollWidth`=`clientWidth`=375(넘침 없음), 코스 칩 줄바꿈, 제목 2줄, 모달이 영역 안에 열림. 1200px 은 길 폭 520·노드 68·제목 폭 262/210 으로 기존과 동일.
- 한계: 약 320px 기기(콘텐츠 폭 256)는 제목 칸이 더 좁아짐. 다른 화면·문제 풀이 화면의 모바일 폭은 아직 재지 않음.

(수정 전 기록)
- 증상: 홈(트레이닝 세트)에서 문서 폭이 584px 로 늘어나 가로 스크롤이 생기고, 코스 칩(k8s·데이터베이스·네트워크)과 세트 제목이 오른쪽에서 잘린다. (`clientWidth` 375, `scrollWidth` 584 로 확인)
- 원인(코드상 확인됨): `SetPath.tsx:11` 의 `WIDTH = 520` 고정. 길 영역이 `width: 520`(`maxWidth: 100%`)이라 `main` 의 최소 폭이 520+여백=584 가 된다. 노드 좌표도 520 기준으로 계산돼 폭만 줄이면 노드가 잘린다.
- 선택지: (1) 컨테이너 폭에 맞춰 `WIDTH` 를 계산(노드 좌표 재계산), (2) 길 전체를 `scale` 로 축소. 
- 다른 화면(진행현황·랭킹·명예의 전당)과 문제 풀이 화면의 모바일 폭은 아직 같은 방식으로 재지 않음.
