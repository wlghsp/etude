## 지킬 규칙 (CLAUDE.md 요약 + 이번에 쌓은 것)

- **커밋·푸시·배포는 사용자가 명시적으로 요청할 때만.** 커밋 여부를 먼저 묻지 않는다. 파일을 하나씩 지정해 `git add` 한다.
- **민감 파일은 출력·커밋하지 않는다:** `.env*`, `backend/db/04_users.sql`, `backend/db/users/users.txt`, Terraform `terraform.tfvars`·state·plan.
- **현장 정보 금지:** 문제·해설·문서에 IP, 도메인, 회사·센터·기관·내부 시스템 이름을 쓰지 않는다. 확인: `grep -nE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+|사내|현장|센터|\.go\.kr|우리" backend/db/03_quest_setNNN.sql` 에서 문서용 예시 주소(`192.0.2.x`, `198.51.100.x`) 외에는 0건이어야 한다. 고객·기관·내부 시스템의 고유 이름은 이 문서에 적지 않으므로, 이어서 작업하는 사람은 그 목록을 사용자에게 받아 같은 방식으로 함께 검사한다.
- **형식 다양화:** 한 세트에 3종 이상, 퀴즈 전용 세트는 객관식 절반 이하.
- **객관식 검증:** `verify:quests` 는 객관식을 검사하지 않는다. DB 에 들어간 정답 보기 텍스트를 직접 출력해 확인한다.
- **쉽고 친절하게:** 한 문제 한 개념, 힌트는 "찾는 방법", 필요한 설명은 남긴다(설명을 줄이기만 하지 않는다). 어려운 문제도 정당하게 있어도 된다.
- **활용도 걸러내기:** 아주 드문 주제(Loki, Git 저장소 백업 등)만 뺀다. 너무 엄격하지 않게, 애매하면 작게 만든다.
- **codex 리뷰 스크립트(`scripts/review/codex-review.sh`)는 호출하지 않는다** (사용자 지시로 중단 중).
- **서버·DNS 는 직접 조사하지 않는다.**
- **응답은 결론·현재 상태·다음 행동 중심으로 짧게.** 근거는 요청받을 때 펼친다.

## 사용자 방향 (확정)

- 쉬운 문제를 **대량으로** 두어 매일 재미로 반복하게 한다. **리눅스·k8s 가 메인**이므로 이 두 분야의 쉬운 문제를 우선 늘린다. DB, OS, 컴퓨터 원리는 심화도 가능.
- 퀴즈형(컨테이너 없음)을 많이 두면 서버 자원 부담이 늘지 않는다. 콘텐츠 양 자체는 DB 용량·CPU 에 거의 영향이 없다 (문제 1,371개가 약 2.6MB).
- 문제가 늘면 **대분류(코스)를 선택해 그 분야의 세트만 보여 주는** 듀오링고식 홈이 필요하다 (현재는 분야 큰 카드가 화면 위를 차지함).
- CKA 는 "기출"이 아니라 **공개 커리큘럼 기준 "CKA 범위 모음"** 으로 묶는다. 시험 문제 재현은 금지(CNCF 규약). **콘텐츠를 더 채운 뒤에** 구현한다.
- 보류(향후, 먼저 제안하지 않는다): 이메일 회원 가입, 이메일 알림 서비스, AI 어시스턴트.

## 배포 전 확인 (사용자가 배포하기 전)

- **서버 디스크 여유:** `etude-linux-db` 이미지가 약 280MB 늘고 빌드가 1~2분 길어진다 (미검증).
- **`linux-db` 실습(세트 109, 126)** 을 실제 환경에서 한 번 해 본다. 컨테이너당 MariaDB 메모리는 로컬에서 약 85MB 였다(동시 학습자 10명이면 약 0.9GB, 서버 메모리 여유는 미확인). 부담이 크면 109·126 을 읽기형으로 되돌린다.
- **화면 확인(미검증):** 완료 조건 박스, 새 분야(데이터베이스) 색·아이콘, 단원 표시. 정답 효과음 안내 배너(`QuestPanel.tsx`)도 실제 브라우저에서 확인하지 않았다.
- `scripts/check-migrations.sh`, `scripts/check-content.sh`, `npx vitest run`, 프론트 `npx tsc -b -f && npm run build` 를 돌린다.
- 임시 문서 `docs/ops/manual_check_2026-10-30.md` 는 커밋하지 않은 사용자 확인용 체크리스트다 (확인 끝나면 삭제).

## 알아 둘 함정

- 마이그레이션은 **파일 이름순**으로 실행된다. 어떤 파일이 다른 파일이 만든 것을 쓰면 이름순으로 뒤에 둔다 (예: 새 분야 마이그레이션은 이름이 `zzzz` 로 시작해 맨 뒤).
- 이미 적용된 마이그레이션 파일을 고쳐도 다시 실행되지 않는다. 배포 전에는 파일을 고쳐도 되지만 배포 후에는 새 파일을 추가한다.
- 같은 단원의 세트는 `display_order` 가 이어져야 한다 (화면이 단원을 이어 묶는다). 새 세트를 끼워 넣을 때 확인한다.
- 생성기는 이전 세트의 `display_order` 값을 그대로 가져오기 쉽다. 생성 직후 05 파일과 마이그레이션의 값을 확인한다.
